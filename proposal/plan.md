## 0. 计划依据与执行规则

本计划依据 Proposal v0.3.9 与 Design v0.3.9。需求基线为 R01–R57，其中 R06、R20 已删除，R10–R13 已作废并由 R44–R47 替代，R52 已作废；设计决策为 D01–D57，待决项为 Q01–Q24。技术选型已按 `proposal/tech-evaluation.md` 确认，具体版本在 T0.2 锁定并由 M0 原型验证待验证项。设计门检视的 25 项裁定 G1–G25 记录在 `reviews/design-gate-2026-09-11.md` §6。

角色命名沿用 Proposal：**意图创建与修改 Agent** 由开发者在开发会话中以流式交互启动；**业务执行 Agent** 由业务服务经子任务契约层提交，子任务有一次性与交互两种模式。平台不定义 Agent 角色，也没有主 Agent。M3 交付开发会话所需的任务容器与 TaskRunner 底座，M5 在同一底座上交付业务子任务契约层。

### 0.1 本版范围与编号

任务编号 `Tn.m` 对应里程碑 `Mn`，只用于追踪。旧编号全部保留：被删除或作废的任务保留行并标注（v0.3.7 作废 T4.12 与 AT-51）；v0.3.2 新任务在各阶段末尾追加：T0.11–T0.12、T1.12–T1.14、T2.12–T2.14、T3.14–T3.16、T4.10–T4.12、T5.9–T5.10、T6.11。验收编号同理：AT-20 已删除，AT-03 等按新模型改写，新增 AT-44–AT-55；v0.3.8 新增 AT-56（RFC-019）；v0.3.9 新增 AT-57、AT-58（RFC-021），T6.7 与 AT-24 中的「暂停项目」作废；v0.3.10 新增 AT-59（RFC-022）。除 T0.10 已于 2026-09-11 完成候选确认外，所有任务初始状态为未执行。

里程碑名称：M2 改为“有状态应用、标签发布与蓝绿切流”；其余沿用 v0.3.0。

不按未经估算的日历天数承诺交付。以可运行结果、依赖关系和验收门槛推进；每阶段给出当前源码版本、锁定依赖与证据。数百数字人并发、数百节点是设计目标，负载参数在 T5.7 定义，压测在 M6 按该档位报告。

RFC-011 在不重编号既有任务与 AT 的前提下扩展 R49：三类角色默认进入能力市场，开发者自建并自动成为负责人，试用成员从 Beta 卡片进入应用；全局 Agent 动态移除。增量任务和逐项验收见 [RFC-011 计划](./rfc/RFC-011-role-based-home/plan.md)，实际证据单独记录，不将设计条目视为已执行。

RFC-010 新增 R54/D53：受管集群目录、用途归属与管理员持久运维操作，增量任务 T1…T11 与 CM-01…CM-25 见 [RFC-010 计划](./rfc/RFC-010-cluster-management/plan.md)。自动化、真实部署只读、真实动作与精确 SHA CI 分开记录；本机权限变更未获执行批准时，不将整个 RFC 标 Done。

## 1. 实施原则与交付档位

### 1.1 先打通一条真实路径，再扩展适配

先做一个最小样例模板（实现语言在评审时确认）、一个任务容器镜像（tini、独立 UID 的 TaskRunner、OpenCode 与 Claude Code 两个驱动）、一种公司 GitLab 兼容接入（本机复用已运行的测试 GitLab）、每服务一份生产库与一份开发库、一个内置 GitLab 格式 EventProducer 与一个参考 APIProxy。双驱动是首版必需。

安全与数据隔离从基础阶段进入：每项目一个命名空间、源 Pod IP 身份、本地放行表从 M1 起就位。正式公司接入可晚于模拟接口，但不能把模拟登录、模拟放行的结果表述为公司已经授权。

### 1.2 两个明确交付档位

| 档位 | 应具备什么 | 不应宣称什么 |
|---|---|---|
| **开发／体验版** | 本机 kind 集群；管理员代建项目、建仓、最小样例到 preview 槽、开发会话与并行多 Agent、标签发布到待命槽与切流、业务任务契约层、GitLab 事件、配置与日志页；控制面副本数可为 1 但 HA 配置项与多副本能力必须存在 | 不宣称公司身份、公司 GitLab Group 与真实数据访问已获授权；不宣称生产隔离；单节点不能代表故障切换已验证 |
| **组织试点／正式候选版** | 真实身份、真实托管 Group、真实上游连接；控制面多副本与元数据库高可用实测；目标档位压测报告；安装升级恢复证据 | 公司审批与未验证模式显式阻塞；不承诺未测规模和任意无损回退 |

“正式候选”不是自动生产批准。

### 10.1 自动化测试分层

- **契约测试**：三种 Manifest、平台 API、事件与 EventDelivery、放行表与 Pod 身份索引、TaskRunner 接口、接入约定表、状态迁移。
- **单元测试**：操作匹配、开放策略、放行表生成、身份索引更新、幂等、版本条件、迁移兼容判断、删除保护、配额准入、契约校验。
- **组件集成测试**：数据库、S3、任务容器、双驱动、网关两域、GitLab、日志采集的实际版本适配；模拟上游与真实上游分别标识。
- **端到端测试**：代建项目、开发会话、发布、切流、接口、事件、数据、配置与恢复全过程。
- **故障与升级测试**：副本被杀、元数据库切换、超时、失联、重投、部分供给失败、节点 cordon、CRD 变更。
- **安全测试**：不可信代码、命名空间边界、网络策略边界、身份伪造、Cookie 与 CSRF、缓存泄露、TaskRunner 凭据文件不可读。
- **规模测试**：目标档位下的并发、吞吐与连接数。

外部推送、标签、切流、迁移等副作用必须使用专属测试资源和唯一幂等标识；清理只针对测试新建且可销毁的资源。

### 10.2 业务任务最小验收脚本规范

以下为待编写的测试步骤，不是本次已经执行的结果。

1. 业务服务以源 Pod 身份创建业务任务，默认 follow-container；记录 taskId 与 traceId。
2. 同时提交一个 `analysis-v1` 的 oneshot 子任务与一个命令子任务；断言两者并发运行，互不阻塞。
3. oneshot 子任务结束，TaskRunner 按 `analysis-report-v1` 契约校验；业务程序经文件接口读取报告并核对摘要。
4. 提交一个 `coding-v1` 的 interactive 子任务；经 messages 端点续一条消息；结束后运行测试命令；核对 cwd、退出码、输出。
5. 提交一个只读 profile 的子任务做审核；发现问题应为 `Succeeded, businessOutcome=findings`。
6. 注入一次半写失败；重试生成新 attempt，不覆盖失败证据。
7. 取消一个子任务，确认其进程树停止、其他子任务与文件不受影响；清理不确定时该子任务标 Failed。
8. 以 persistent 模式重复 1–4，暂停后恢复，核对卷内容、授权重验与 CLI 会话目录；关闭任务后卷与配额释放，仓库与业务数据保留。
9. 用 traceId 索引出全部 sessionId、子任务、命令与产物引用。

### 10.3 开发会话与蓝绿发布完整验收脚本规范

1. 管理员用 CLI 代建项目并指定负责人；确认唯一远端 Project、命名空间、初始提交、首标签构建、最小样例在 preview 槽显示当前用户。
2. 开发者查看分支列表与落后数，开启开发会话选择默认分支；第二个会话被拒。
3. 容器就绪，预览自动启动；同时启动一个 OpenCode 与一个 Claude Code 流式交互 Agent，打开终端与编辑器；各自修改文件，预览实时更新。
4. 在 Swagger 调试页试调一个默认开放接口与一个未开放接口；前者经开发容器以本服务身份成功，后者被网关拒绝；申请定向接口，管理员审批后可调。
5. 申请只读诊断数据访问，负责人批准后连接成功；申请生产变更，负责人拒绝并给理由。
6. 在配置页设置开发组与生产组值；开发会话读到开发组值。
7. 点发布：存在未提交内容时提示；提交后再发布，平台代推、打标签、构建、兼容迁移、部署待命槽；手工推送一个 v 标签，确认不触发；Agent 经操作 MCP 再发布一次，确认走同一链。
8. 负责人添加一名测试者；测试者可访问 preview 域，非成员被拒；负责人切流，prod 域承接新版本并读到生产组值；开发者尝试切流被拒；负责人回退。
9. 触发一条 GitLab 事件，确认经服务域到达样例 prod 槽处理路径，待命槽未收到；样例页面显示该事件。
10. 让会话空闲超过配置时长，确认提醒到达且会话仍在；负责人强制释放；核对未推送提示、Pod 与卷删除、配额释放；再次开启会话，容器重建并从所选分支检出。

## 13. 延后项目与触发条件

| 延后能力 | 何时再做 |
|---|---|
| 更多 Agent 驱动 | 双驱动稳定后按需求扩展 |
| 更多模板与实现语言 | 最小样例模板稳定、约定表被两种以上语言实现验证后 |
| 多集群调度、跨区域灾备 | 单集群目标档位稳定后 |
| 业务服务发布自定义事件 | 有明确跨数字人协作需求 |
| 平台定时触发 | 业务自实现方案不足以支撑时 |
| agent-workflow 作为业务应用接入 | 其 OIDC 登录改为网关身份的改造完成后 |
| 开发会话暂停或持久卷 | 一项目一会话与释放即回收不满足需求时 |
| 空闲会话自动释放 | 只提醒不释放导致配额长期被占且负责人无法兜底时 |
| 同一项目多个并行开发会话 | 单会话串行开发成为瓶颈且冲突策略明确 |
| preview 与 prod 之间的数据隔离 | 业务在 preview 域无法自控副作用且需求普遍时 |
| 每 Grant 独立上游凭据 | 上游要求区分调用方主体时 |
| 知识提取与召回 | 追溯链稳定后按价值决定 |
| 资源级接口授权 | 上游或业务把关不足且能在目录标注资源语义 |
| 任务时长与模型用量预算 | 并发配额不足以控制成本时 |
| 告警渠道多样化 | Q20 首选渠道稳定后 |
| 通用 DAG 与平台侧编排 | 明确违背“平台不编排开发过程”原则，需重新评审 |
| Kafka、Redis、Istio、Knative、OPA、Temporal、Buildpacks、Longhorn、业务缩容到零 | 条件性选项，触发条件见 tech-evaluation.md 各项备选 |

延后不意味着忽略安全与数据；不能因为某组件可选就延后生产隔离门槛。

## 14. 启动项目时的第一组行动

从 M0 开始，先锁定版本（T0.2）并冻结三种 Manifest、放行表、Pod 身份索引、EventDelivery 与业务接入约定表（T0.3），然后做四条原型：

1. 一个任务容器镜像内以独立 UID 常驻 TaskRunner，同时运行 OpenCode 与 Claude Code 两个流式交互 Agent、一个终端与一个命令，会话可恢复、进程可清理、MCP 连接可注入。
2. 网关用户域 ForwardAuth 与身份注入；服务域按源 Pod IP 反查身份、本地放行表与来源令牌注入；CNI 源 IP 保留验证。
3. 在本机测试 GitLab 的获准 Group 自动建仓、推送、以平台身份创建保护标签；两种任务持久卷模式的释放与暂停恢复。
4. 控制面运行时原型：Bun 上的多副本 Hono 服务、PostgreSQL 驱动、WebSocket、OpenTelemetry。

随后 M1 建好项目、命名空间、身份、路由与经首个标签到达 preview 槽的最小样例，M2 打通数据、完整发布链、兼容迁移、切流回退、配置与日志，M3 交付开发会话与工作台，M4 交付接入容器、开放策略、放行表与事件中心，M5 交付业务契约层、配额、追溯、健康告警与最小样例验收，M6 验证 HA、目标档位、一键发行、分层升级与恢复。

**整套计划最终验证的是：业务团队在一个常驻 TaskRunner 的开发容器里，用自己的方式和自己的 Agent 开发数字人；发布只是一个平台创建的标签，上线只是负责人的一次切流；业务服务不写登录代码、不带凭据就拿到身份，按开放策略调用内部接口，经服务域接收公司事件，经契约层运行业务执行 Agent，有配置、日志与告警；平台在数百服务的规模下以高可用形态独立升级公共能力。**
