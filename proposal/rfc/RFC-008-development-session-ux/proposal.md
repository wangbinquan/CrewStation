## 1. 问题与证据

实机项目 `demo`（`prj_01a090f72dea7000b5ff6d3841cbaf7b`）的会话 `tsk_01a0954107447000b7936485fb80d15d`：
旧 Pod 仍为 Running；2026-09-20 日志持续报 `Runner 协议版本 1，平台要求 2；请基于当前平台底座镜像重建镜像`。
页面主视图只显示“开发容器未连接”；“＋ CLI”禁用，空态却要求点击它。展开“会话”才看到协议错误，唯一生命周期动作是释放会话。
这不是缺少用户自填连接地址：TaskRunner 由平台创建并自动连接。

| 问题 | 当前事实与证据 | 改进 |
|---|---|---|
| 连接故障无出口 | `runnerLifecycle.ts:28–43` 只记录拒绝；`rebuildInspection.ts:10–12,24–26` 只接受已失败且 Pod 已结束的环境 | 首屏解释原因，提供检查与保卷升级恢复；临时断线单独处理 |
| 重要信息藏在浮层 | `DevSessionWorkbench.tsx:70–76` 把数据申请、审批、容器详情与释放放在右上角 details | 数据访问、会话与环境成为常驻页签 |

| 两类页签混在一起 | `NativeWorkspace.tsx:59–66` 动态工作区与预览／代码／差异并列，新增页签与名册跨视图显示 | 固定功能导航；CLI 视图内管理工作区和窗口 |
| 工具密度没有优先级 | `NativeToolbar.tsx` 首窗为空仍展示全部排布按钮 | 首次创建集中为档位＋创建；有窗口后呈现布局操作 |

上表简称路径均位于 `apps/console/src/features/dev-session/` 或 `modules/task-runtime/application/`；完整链路见 design.md。

## 2. 目标与边界

**用户进入后能立即知道：现在能不能开发、卡在哪里、下一步点哪里。**

- 正常路径：进入项目 → 环境就绪 → 创建一个 CLI → 输入需求 → 看预览／改代码 → 检查变更 → 准备发布。
- 故障路径：页面显示实际故障 → 就地检查 → 明确影响后保留工作树恢复 → 手动创建 CLI。
- 保留全部既有原生 CLI、工作区、分屏、预览、代码、版本比较、数据申请审批、历史对话与释放能力。
- 不新增用户必须配置的 Runner 地址、模型密钥或驱动参数。算力配置仍由管理员提供，项目开发者只选档位。
- 不改变生产发布、数据库授权和自动切库语义；不自动结束会话、删除卷或重启 CLI。

## 3. 页面结构

```text
开发会话   环境状态 · 分支                          准备发布
[仅异常时：具体原因 + 下一步 + 检查连接／恢复环境]
CLI 工作区 | 预览 | 代码 | 变更 | 数据访问 | 会话与环境
─────────────────────────────────────────────────
CLI 页：工作区 1 · 2 | 工作区 2 · 1 | ＋ 工作区     全部 CLI
       算力档位 [默认]  创建 CLI     排布／并排预览／更多
       原生终端内容，保留窗口状态、可拖动分隔线和后台动态
```

- 页首保留身份、状态和“准备发布”。故障提示不埋在页签里；健康态不长期占据大卡片。
- “数据访问”：说明开发数据默认配置与保留规则，展示生产只读／读写申请、有效期、审批记录。获批与实际加载状态分别说明。
- “会话与环境”：连接状态和恢复操作在前，创建时分支、任务 ID、预览地址等详情在后；历史对话作为独立入口；释放在明确标注影响的末尾区域。
- “变更”集中版本比较与未提交／未推送清单；健康 CLI 页保留精简版本摘要，未知不能显示为零。
- 固定页签使用 URL 定位，刷新和返回保持所选内容；CLI 的个人工作区布局继续使用原有保存接口。
- 桌面健康态保持四窗可用；390px 页签条独立滚动，表单与工具栏换行，内容不撑宽整页。支持明暗主题、键盘与中英文。

## 4. 使用旅程

| 情况 | 用户看到 | 下一步 |
|---|---|---|
| 无会话 | 简短说明、可用分支、开始开发按钮；分支读取失败有重试 | 选分支，平台自动准备环境 |
| 正在准备 | 当前准备状态、真实错误或等待原因、任务日志 | 等待自动连接；可检查状态 |
| 浏览器断线 | “页面连接中断”，草稿保留 | 重新连接页面通道，不创建环境或重发输入 |
| 容器失联且原因未知 | “开发环境未连接”，明确仍在核对 | 检查状态、打开该任务日志；不声称重连可以修好容器 |
| 已确认协议不兼容 | “开发环境需要更新”，实际协议错误可读 | 检查并保留工作树重建；确认前列出对象与进程影响 |
| 已失败 | 失败原因、原工作卷恢复入口 | 优先保留原工作树；另建远端工作树保留独立确认 |
| 环境就绪、没有 CLI | 档位、创建一个 CLI、创建后在哪里输入 | 创建后直接进入该终端 |
| 档位不可用／读取失败 | 具体档位原因与刷新入口；管理员有管理入口 | 选择另一可用档位或联系管理员 |
| 已有 CLI | 终端、实际状态、当前工作区、常用操作 | 输入、切预览、看变更；后台完成不抢焦点 |

## 5. 能力影响

没有删除功能。右上角的两个展开入口迁入页签；“＋ 页签”改称“＋ 工作区”，含义仍是个人显示布局。
现有链接 `view=cli|split|preview|code|diff|changes|conversation` 继续有效，新增 `data|session`。
普通断线不会获得重建运行中环境的能力；**仅服务端已记录协议不兼容的当前开发容器**可在用户明确确认后升级恢复。
恢复替换该开发容器，会终止其中仍运行的旧进程；工作卷、文件、未推送提交、taskId 与个人布局保留。
独立执行 Pod 的 CLI 不因切换页签或页面重连被终止；重建时按其真实生命周期展示，不自动重复启动。
