## 2. 实施门

1. 设计批准门：独立页、覆盖上线和历史流程是已确认方向；需批准design中拟新增阶段留存／验证记录／普通切流防重及兼容实施，才能修改生产代码。任何进一步能力收缩另列影响由作者确认。
2. 数据一致门：首次发布与各次重新部署独立；事件来自原状态事务，后台重放不重复；旧缺失不造记录；新表必须同时纳入已完成RFC-037的完整项目删除边界。
3. 功能门：原正常、离线、未知回执、SHA／target变化、角色限制、迁移与回退断言保持，新增行为自带正向／错误／边界用例。
4. 候选门：共享main保留并行WIP，精确路径；任务候选不变不因移动HEAD重启全量检查。范围外在制门失败按现有规则如实留证，不改别人的文件。
5. 发布／实机门：准确提交CI、实际部署源码与真实应用发布分别取证；原型、HTTP202和模拟事件不计作上线成功。真实验证项目／上线／资源操作须其具体授权。
