# 发布向导交互预览

此处为 RFC-038 的设计稿，使用明确标注的示例数据，不连接真实项目。正式页面的路由、共享组件、服务器进度和历史留存见上层三件套。

## 可查看的交互

1. 初始发布页签有当前版本、继续发布及五条历史记录。
2. 「发布新版本」打开五步向导；同屏选来源、分支、版本、说明；「构建并继续」走示例自动阶段。
3. 「稍后继续」回发布记录，从同一行接着处理；验证说明保留在当次历史。
4. 「验证通过，继续上线」进入正式版本与目标版本的核对；明确确认后先观察生效再显示完成。
5. 成功、失败、重新部署和升级前记录可逐步回看。后续步骤未执行的失败历史不会显示上线成功。

预览身份和下一次异常场景使用宿主的设计选项，可选择负责人／开发者、正常／构建失败／来源变化／目标被替换。地址入口只展示本地反馈，不真的打开业务应用。示例自动进度以短时计时器演示；正式实现依据服务器实际阶段。

## 再次预览与检查

使用 visualize 技能的 `scripts/render.py` 加载 `release-wizard.html --serve --port 0`，按输出的本地 URL 打开。服务启动时固定读取片段；改完源文件须重启预览，避免检查旧缓存。

`browser-check.cjs` 使用 Node.js、Playwright 与本机已安装 Chrome，运行形式为：

```sh
node browser-check.cjs <本地预览URL> <检查输出目录>
```

Playwright 来自宿主工作区依赖时，先把其 node_modules 设为该命令的 `NODE_PATH`。只运行此设计检查，不启动生产服务或调用发布接口。一次结果通过后，只有修改候选或发现未覆盖问题才重新检查。
