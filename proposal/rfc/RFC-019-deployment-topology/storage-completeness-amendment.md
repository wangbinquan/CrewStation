# 部署拓扑的持久存储完整性修订

2026-09-28，用户批准修正、提交上库并部署本机。

## 问题与范围

只读核查发现：26 个 PVC 全在盘点中，系统图漏 4 个，业务图漏 17 个已结束任务留下的卷；系统固定组件表漏存储探针及本机身份组件，PV 与挂载路径未进入拓扑。原来“快照完整”只证明采集成功，不能证明图覆盖完整；旧回归只逐一核对 Pod，PVC 只抽一个查文案。

本修订覆盖受管工作负载、Pod、PVC、PV 的展示与实际挂载/绑定；网络与配置对象继续在资源清单与关联详情中展开，不把静态调用线当实测。服务槽仍无持久卷，业务执行面继续使用任务卷。只改观测和显示，不新建、重建或删除业务资源。

## 设计

- PV 作为集群级来源只采一次；仅通过双向绑定和 claimRef UID 确认归属到已受管 PVC，不因名称相同关联新实例，不把其他租户 PV 暴露给项目。PV 只读，不新增删除权限；不回传主机目录和 CSI 凭据。
- 盘点增加可选挂载元数据（容器、PVC 名称、路径、subPath、只读及初始化标记），兼容历史快照。PVC/PV 提供安全的容量、存储类与绑定事实。
- 系统图分页读取受管系统资源，静态架构节点保留稳定 ID；新增实际组件自动补入。每个 PVC/PV 有节点，工作负载到 PVC 为观测挂载，PVC 到 PV 为 UID 校验的绑定。
- 项目图保留台账状态与稳定 ID，并补齐盘点中未被台账节点代表的 Pod/工作负载及存储；未挂载卷独立进入存储横带。节点只按真实 UID/资源 ID 去重。当前 Pod 的挂载来自观测，不能仅按父子关系虚构挂载。
- 明确标记分页截断与缺失的绑定来源；采集完整不等于推断所有配置关系。项目返回上限造成截断时 complete=false。
- 节点详情使用共享 Dialog；关闭保持筛选、图滚动与触发点焦点，嵌套确认 Esc 只关闭最上层。

1. 先复现：保留卷、系统未知组件、PV UID 错配、跨项目 PV、挂载路径、来源失败与分页截断。
2. 后端真实模块验证采集与成员投影；前端组图核对全部工作负载/Pod/PVC/PV，实际边端点不得悬空。
3. 三宽（1440/1024/390）真实页面核对资源集、绑定、弹窗可见性、关闭焦点与滚动；中英文/明暗主题；不执行资源管理动作。
4. 完整门禁、精确路径提交、精确 SHA CI；构建提交镜像，更新必要控制面与 console，核对现有业务 Pod/PVC UID 不变、集群盘点与页面一致。
