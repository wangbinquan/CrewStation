# I9｜代理服务的受控 HTTP 出站

作者已在 2026-09-15 全权委托后选定 I9(a)：代理服务复用管理员维护的全局及项目白名单。此文件展开该批准范围，属于 RFC-003 的真实 API 调用旅程。

现有 `egress` 模块负责条目、审批、被阻记录，尚无运行时执行器；当前项目网络只允许代理 Pod 访问平台和 DNS。标准 NetworkPolicy 无法完整表达已有通配 FQDN 语义，因此不把域名临时解析为 IP，也不放开代理的直接出站。

平台在既有 cs-api 内提供 `POST /internal/egress/http`。请求通过服务域网关取得代理自身的服务身份；仅 active 的 APIProxy 可以使用，项目从服务目录解析，不接受调用方提供 projectId。每次请求读取当前全局＋该代理项目规则，沿用精确域名／通配子域语义；未放行写入 `source=slot` 被阻记录，返回明确错误，管理员批准或撤销后下一次请求立即采用最新规则。

请求包含 HTTP(S) 目标、方法、请求头及可选 Base64 请求体；响应保持上游状态、业务头和二进制内容。请求体上限 1 MiB、响应 4 MiB、头部 32 KiB、目标 URL 8 KiB，单次上游总期限最长 8 秒。不跟随重定向，不自动重试；错误明确说明请求可能已执行。平台身份及逐跳头不传给上游，已配置的上游认证头只用于本次匹配的目标，日志不记录凭据／请求体。

参考 APIProxy 根据平台已注入的 `CS_PLATFORM_API_URL` 使用该通道；独立本地运行未注入平台地址时保留原直连方式。已部署的旧业务镜像须按正常发布流程升级，规则变化本身不要求重发版。原有 APIGrant、目录与消费端网关裁定保持，出站许可不能代替消费者的 API 授权。

落位：跨进程请求形状在 contracts；规则编排、服务目录／HTTP 端口、fetch 适配器和 HTTP 路由在 egress 的对应层；参考代理的协议接入在自身 platform 层。本批不新增常驻进程，不声称任务／构建的通用出站代理已完成，不提前实施 RFC-004。

验证包含真实数据库的批准／撤销即时生效、其他项目条目不串用、来源归属与被阻记录；实际 HTTP 传输的二进制、状态与分页头、重定向、体积及超时；参考代理经平台通道的单次发送；最终以部署后的浏览器 API 试调和同一服务身份的真实调用闭环关闭相关 UX 条目。
