# RFC-003｜能力市场与应用可见性

> 已获批准，实施中 · 2026-09-13。作者最新要求：能力接入属于管理员；能力市场显示当前用户有权查看的应用；应用负责人配置可见性。本规格替代此前“租户能力接入”和“不建设应用市场”的范围描述。代码与验收证据见 `implementation.md`，不能把隔离数据的排版验收当作真实集群权限旅程。

## 1. 入口和职责

工作台全局有“能力市场”和“数字人项目”。市场面向应用使用者，项目列表面向应用建设者；应用使用者无需先成为开发成员才能发现已向其开放的应用。有开发权限的人可从应用详情进入对应项目，普通使用者只有应用入口。

项目内只保留五项：概览、开发、发布与上线、运行与诊断、项目设置。“能力接入”只在管理空间出现，包含接入容器、接口开放策略、事件来源；接入创建、开发、发布、上游连接维护与审批均由平台管理员操作。

开发者原有消费能力接续到“项目设置 → 开发资源”：查看已获准 API 的文档、申请定向开放、经当前开发会话试调、查看已发布事件订阅、数据说明、档位／配额、平台约定。此处没有平台接入创建与开放策略按钮。事件投递和故障仍在运行与诊断，数据访问申请仍在开发会话。

## 2. 能力市场

- 展示应用名称、图标、用途、负责人、当前正式版本与上线状态；卡片进入应用详情，已上线应用提供真实正式地址，在独立浏览器页签打开。
- 展示全部有权查看的 DigitalWorker 应用，而非只列当前用户参与开发的项目；APIProxy 与 EventProducer 是管理员供给对象，不混进应用市场。
- 有权查看但尚未上线的应用也列出，明确“尚未上线”，不能借用 preview 地址冒充正式应用。暂停／归档／服务状态未知分别按事实呈现，不用一个“在线”掩盖。
- 搜索名称与用途，只在已授权结果上计算匹配数和分页。无匹配、无可见应用、查询失败分别有恢复路径。
- 详情只含使用应用需要的元数据。能看到市场卡片不等于获得项目管理界面、源码、开发容器、生产数据或服务间 API 授权。
- 市场可见性约束目录与详情。本轮不改变正式应用已有的登录和业务权限规则，也不把“市场隐藏”宣称为禁止通过已有链接访问应用；preview／dev 继续用现有权限。

## 3. 负责人配置

入口为“项目设置 → 应用可见性”，应用详情中有负责人快捷入口。配置者为该应用负责人，管理员沿用既有项目管理权限；开发者与测试者可读当前范围，不能保存。配置对象是应用，不是某个 CLI、开发页签或发布标签。

| 范围 | 结果 |
|---|---|
| 项目成员 | 负责人、开发者、preview 测试者可见 |
| 全部登录用户 | 平台已登录用户均可见，不表示互联网匿名公开 |
| 项目成员与指定用户 | 项目成员加已选择的注册用户可见；首版以用户为粒度 |

管理员有管理范围内的查看权。新增应用默认“项目成员”；现有应用首次迁移同样仅建立该市场展示默认值，不修改原来的生产访问或成员关系。指定范围必须至少有一位有效用户；用户去重，以稳定 UserId 保存，查找复用项目内精确账号匹配。首版没有已证实的组织／用户组目录，不假造部门选择器。

表单初始显示范围及作用，选择与保存分离；取消恢复已保存内容，保存成功刷新该应用详情与市场查询。提供按已保存设置检查指定用户是否可见的负责人查询；不以未保存草稿声称生效。并发编辑保留本地选择并提示最新设置，不能覆盖另一位负责人的更新。

## 5. 接口和代码落位

应用展示资料及可见范围属于 project L2。建议增加本模块的 application listing／visibility 记录，保存 projectId、description、icon 引用、mode、指定 UserId、revision 与更新时间；不新增独立后端模块，不跨模块 join 表。

| 接口 | 契约 |
|---|---|
| GET `/v1/market/apps?cursor=&limit=20&q=` | 当前登录用户范围内的应用卡片与 nextCursor；先可见性、后搜索和分页，不返回隐藏应用计数 |
| GET `/v1/market/apps/:projectId` | 同一可见性规则的详情；缺失或不可见不返回应用元数据；不能调用完整项目详情绕过市场投影 |
| GET `/v1/projects/:projectId/app-visibility` | 有项目 view 的成员读取当前 mode、指定用户及 revision；非项目市场访客不取得名单 |
| PUT `/v1/projects/:projectId/app-visibility` | 负责人提交 `{mode, userIds, expectedRevision}`，成功返回保存结果；冲突 409，普通开发者／测试者 403 |
| GET `/v1/projects/:projectId/app-visibility/check?userId=` | 仅有配置权者检查指定注册用户；返回基于已保存 revision 的 visible 和依据，不扩成普通用户任意查询 |
| GET／PUT `/v1/projects/:projectId/app-presentation` | GET 供成员读取用途与图标；PUT 由负责人提交 `{description, icon, expectedRevision}`，和可见范围共用 listing revision，冲突不覆盖其他字段 |

展示元数据与可见性查询在 project L2 公开 API 内完成。正式版本和运行摘要由 capabilities L6 调用 project、release 等公开读接口聚合，不能让 project 反向依赖 release；每个状态标记 freshness 和 unknown。列表有界，缓存含当前用户及范围修订；变更范围／成员／登录身份后重新校验，后台旧响应不能覆盖新范围。打开详情和后续请求均再次裁定，不能只靠前端隐藏卡片。

前端由 features/capabilities 承接市场列表／详情，features/projects 承接应用可见性，features/admin 承接能力接入；features/catalog 保留消费者文档／申请／试调和管理员策略各自导出入口，由 app 路由装配，features 不互相内部 import。服务端 API 文档与 MCP 描述继续同源；人员匹配沿 RFC 的 member-candidates 查询实现。

首批实现界限：用途最多 400 字；图标是固定本地矢量引用 `station|assistant|workflow|book|chart|spark`；指定名单最多 200 人；市场每页默认 20、最多 50 项，无隐藏应用总数。游标绑定当前用户和搜索词，SQL 先按范围过滤再搜索；聚合并发最多 4、单个部署来源截止 2.5 秒。正式状态来自部署槽记录，不把它当成即时 Pod 健康探针。精确人员定位支持完整邮箱或 UserId；邮箱非唯一时返回无唯一候选，不随机选人。

## 6. 验收

T16 必须覆盖管理员、负责人、开发者、测试者、非项目应用使用者；三种可见范围、名单去重／无效用户／空名单、保存／取消／并发、分页搜索与直接访问一致性。应用详情不能泄漏完整项目数据。只调整市场范围不能授予开发权限、扩大 APIGrant 或改写生产访问规则。
