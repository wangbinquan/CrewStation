# RFC-003｜多 CLI 开发工作台与生产版本对比

> 状态：设计已批准／实施中 · 2026-09-13 · 本文细化并修订 proposal J2、design §2.3；实际完成范围见 implementation.md。
>
> 作者最新明确要求：CLI 一个一个启动；新建工作页签，在单页签内灵活排布多个 CLI；开发界面紧凑、信息密度高；数据访问使用直观名称。独立实时预览和当前工作树对生产部署的差距继续保留。本文取代上一稿的批量启动入口。

## 1. 最终使用方式

进入开发会话，直接看到紧凑的版本状态与 CLI 工作页签。点击“＋ CLI”只启动一个原生 Agent，并放入当前页签；需要几个就逐个新增。移除数量输入和批量启动按钮。启动前不强制填写首条任务；档位复用上次选择，操作前可修改。

每个窗口对应一个独立 Agent 进程与 PTY，支持原生 CLI 输入、流式终端输出、交互提示、滚动、缩放与 Ctrl+C。工作页签可新建、命名与关闭，CLI 可调整顺序、移至其他页签、放大、收起／恢复或逐个结束。没有主 Agent、固定角色或平台自动派工。

所有窗口默认在同一个开发容器、同一个当前工作树内并行开发，看到彼此已写入的文件。窗口数量不代表容器或分支数量；平台不会因此自动建分支、worktree、合并或串行化 Agent。多人／多 Agent 改同一文件仍遵守现有工作方式；内置编辑器继续保留 expectedVersion 冲突提示。

平台仍按 RFC-001 提供算力档位，用户不重新配置驱动、模型或模型凭据。CLI 本身可显示其原生界面；平台不额外把驱动／模型选择变成租户必填项。既有结构化 Agent 对话移至“会话 → 历史对话会话”独立页面，保留消息、新建与取消能力；用 L-id 和“返回 CLI 工作区”明确它不是当前 CLI 的另一种显示。开发页取消“对话模式”按钮，不把 JSON 输出涂成终端来替代原生 CLI。

## 2. 布局与独立预览

从上到下：

1. **紧凑上下文**：一行开发标题、当前 branch／HEAD、数据访问、准备发布；下一行生产实际标签／SHA、双方独有提交数、未提交文件数与未推送数量。详情点击展开，不再占一个大卡片。
2. **工作页签**：可命名的开发页签、关闭按钮、“＋ 新页签”；同栏保留预览、代码和差异入口。
3. **当前页签工具栏**：“＋ CLI”、算力档位、高级选项；横排／纵排／网格、均分、并排预览、已启动 CLI。高级选项收纳 Agent 文件／工具操作权限，数据范围在会话级入口管理。
4. **工作内容**：CLI 平铺与可拖动分隔线；并排预览在右侧；独立预览占满工作内容区，也有真实开发预览地址可在另一浏览器页签／显示器打开。

预览直接访问当前开发容器的预览服务，观察的是当前工作树的实际结果，包含已经保存但尚未提交的修改。支持热更新的项目由自身开发服务器实时更新；其余项目按真实开发命令的重载行为运行，并提供刷新／重启和日志入口。不能承诺任意应用都具有 HMR，也不能用定时动画冒充更新。

开发预览标明当前会话、工作分支和开发数据绑定；与“发布后试用版本”及正式访问保持区分。切换独立预览、代码、版本差异或离开工作台，只分离显示连接，不中止 CLI，也不重复启动进程。预览进程失败保留 CLI 工作区可用。

顶栏与会话摘要的连接提示先表达任务生命周期，再表达开发容器和浏览器通道的状态。失败任务即使可以回放历史也保持“失败”；运行中的任务若 Runner 失联则显示“开发容器未连接”，正在收尾／关闭分别提示；只有运行中且浏览器与 Runner 都连接时才显示“已连接”。回放条数、重连次数继续单独呈现，不能把读取历史成功当作容器恢复，也不因状态更新重新创建工作区或清除草稿。

桌面默认紧凑网格，四窗时为 2×2，三窗时第三窗横跨下排，单窗占满。正文保持 14px，终端与辅助文字 12px；缩减标题、重复状态、卡片内边距与输入区，不靠缩小到难读字号实现密度。1280×720 的正常四窗状态应完整展示四个终端标题、至少六行输出和输入区；首窗内容区域距产品顶端不超过 210px。表单／错误主动展开时可以增加高度，不裁掉必要反馈。

### 2.1 页签与分屏规则

- “＋ 新页签”创建空布局，不启动进程、不创建开发会话或工作树。页签可命名，CLI 用“移至”放到现有或新页签，也可调整前后顺序。
- 每页签各自保存布局、窗口顺序与分屏比例。横排优先并列，纵排上下排列，网格默认两列；窗口过多或空间不足时换行。桌面网格可拖左右／上下分隔线，提供键盘方向键调整与“均分”复位；最小可用宽高优先于保存的比例。
- 放大只改变当前页签可见布局；恢复后回原顺序与比例。切页签不会重启 CLI、清空未发送输入或改变其他页签布局。
- 关闭页签只收起其显示窗；全部 CLI 在“已启动”列表保留，并可放回当前页签。只有“结束进程”停止指定 CLI。关闭最后一个页签生成空页签，CLI 保留。
- 1024 及以下按内容宽度换行，窄屏以单列／放大模式阅读，保留桌面布局偏好，回宽屏恢复；标签可换行或有明确溢出菜单，关键操作不被裁切。单页签窗口数量与全会话进程数量分别显示，不能误认为切页签停止了其他 Agent。
- 开发页签是个人的显示组织；同项目的其他成员继续使用同一开发会话，但不被迫共享某个人的窗口排布。生产实现恢复布局后必须与真实 CLI 名册对账。

### 2.2 布局状态落位

`features/dev-session/model/` 拥有 `{activeTabId, tabs: [{id, name, layout, paneOrder, ratios}], hiddenAgentIds}`，CLI 草稿与终端显示按稳定 terminalId 保存，不能以 React mount 生成进程 ID。`shared/ui/` 的 Tabs／SplitPane 只负责通用显示与尺寸，不拥有 Agent 生命周期。

正式实现通过 dev-session L5 的 `GET／PUT /v1/tasks/:taskId/workspace-layout` 保存个人布局，按当前用户＋taskId 定位并携带 revision，冲突保留本地布局供重新应用；名册不从布局记录推断。新增 contracts／api-client 形状，存储归 dev-session 本模块。只保存显示配置；终端输出仍走原有有界回放。记录失效的 terminalId 标记已结束，不自动重启。原型只在页面内存保留，刷新重置，不能作为持久化验收。

## 3. 版本差距必须回答的五件事

| 信息 | 含义 | 不能混淆为 |
|---|---|---|
| 正式版本 `v… @ P` | 当前承担正式流量的 Release 与部署 SHA | 最新标签、待命版本、远端 main |
| 工作树 `branch @ H` | 开发容器实际 Git HEAD；分支切换后更新，detached 时如实标明 | 建会话时记下的 branch、远端分支缓存 |
| 已提交但未上线 A 个 | H 可达而 P 不可达的提交 | 未推送数量、简单版本号相减 |
| 工作树缺少生产提交 B 个 | P 可达而 H 不可达的提交；A、B 都大于 0 时为分叉 | 只有一个正负数字、默认建议覆盖工作树 |
| 未提交修改 N 个文件 | 已暂存、未暂存、未跟踪文件分别列明 | 不计入比较、伪装成一个已提交版本 |

另显示“相对上游未推送／缺少远端提交”，但这是仓库同步关系，与生产差距是独立事实。一个已经推送到 main 的提交，仍可能尚未部署到生产。

差异详情有四个页签：**待上线提交、缺少的生产提交、相对生产的文件差异、未提交改动**。文件页可看路径、增删行、文本 patch、重命名与二进制说明；未跟踪文件单列，不漏掉。生产与工作树文件净差异不能用“提交文件数＋未提交文件数”相加，避免重复计数或遗漏抵消。

首屏示例为演示值：生产 `v0.1.2 @ 3975d02`，工作树 `main @ 9fd01fc`；2 个已提交修改待上线、缺少生产提交 0、未提交文件 0。修改文件后未提交数变化，而提交数不会凭空增加。生产切换到相同 HEAD 后，提交差距归零，未提交修改仍保留。

未首次部署显示“尚无正式版本”；缺对象／浅克隆／历史不足显示“暂不可比较”；无共同历史显示“无共同历史”；后台计算或生产版本变化时显示更新中／已过期。上述状态都不能显示为 0 或“已一致”。零提交差距但还有未提交文件时，显示“提交一致，工作树有修改”。

## 5. CLI 启动、恢复与失败契约

新增 `POST /v1/tasks/:taskId/agent-terminals`，单窗输入为 `{clientRequestId, compute?, permission, cwd?, cols, rows}`，返回 `{agentId, terminalId, state: 'starting'}`。一次“＋ CLI”只固定一个请求 ID、启动一个进程。资源不足仅在本次新增窗口反馈，不影响已有 CLI；不引入窗口数量表单或业务 DAG。

以调用者＋taskId＋clientRequestId 幂等识别已受理启动；重复使用同一 ID 但内容不同必须冲突。新增失败保留既有窗口，只允许重试明确失败项；断线／超时不等于失败，先查询原 ID 的真实受理状态，再决定是否重试。

新增 `GET /v1/tasks/:taskId/agent-terminals` 返回窗口名册、进程状态、terminalId、compute、permission、启动／退出时间和退出原因。名册由 dev-session 的启动记录与 TaskRunner 当前注册表对账，不靠浏览器内存假定进程存在。连接不可达时状态为未知；重连原 PTY，不自动恢复为新 CLI 进程。TaskRunner／容器重启后进程已丢失时如实显示结束／不可恢复，继续会话必须由用户显式操作。

`POST /v1/tasks/:taskId/agent-terminals/:agentId/stop` 为显式结束；Ctrl+C 是原生终端输入语义，不等于释放开发容器。收起／关掉一个显示窗仅 detach，结束进程有独立动作。释放整个开发会话沿既有确认停止全部进程；保留现有强制释放能力。

TaskRunner 增加 `startAgentTerminal`／名册查询等协议及终端 started 事件，复用 terminalInput／Output／Resize；Agent 进程状态不通过猜测输出文字判断。cs-session 按 terminalId 路由，终端恢复有有界回放／快照及缺口说明，不能把截断后的 ANSI 尾部当作完整屏幕。多个浏览器附着同一终端时，只由显式取得输入控制的视图发送输入／尺寸，其余视图可读；这不限制不同 Agent 并行运行，也不引入工作树单写锁。

> **2026-09-23 修订（作者当面裁定，直接修改，不另立 RFC）。** 作者反馈「获取控制权的按钮一点都不显眼」「没被其他人占用时，操作 CLI 框就应自动获取；被占用就提示谁在占用」。逐项裁定后，上一段的「显式取得」改为：
>
> - **自动取得**：点进终端、Tab 进终端、在终端里按键、切回停着焦点的终端，都自动取得输入控制；只打开页面不取得。原「获取输入控制」按钮删除。没有控制时的按键仍不排队、不重发（原规则不变），只触发取得。
> - **焦点在终端才保持**：只在终端有焦点、页面可见且窗口在前台时每 10 秒续约；点到别处、切走标签页或窗口后不再续约，Runner 的 30 秒租约自然到期并释放。
> - **占用只对别人成立**：同一用户的另一个窗口来取，控制直接转过去；别人占着时取得被拒。粒度仍是每个 CLI 窗口各一把，两人可以各用一个 CLI。
> - **占用人常驻实时显示**：终端上方的状态条按颜色区分「你正在输入」（绿，整窗加绿框）「空闲 · 点击终端即可输入」（蓝）「你在另一个窗口中输入」（蓝）「某某 正在输入 · 只读」（黄）。持有人由 cs-session 按浏览器连接的网关身份（用户 ID＋显示名）注入取得命令，浏览器自带的一律丢弃；Runner 记住持有人，换人、释放、到期都推 `terminalControl` 事件（只实时转发、不落库，带单调递增的 `revision`），`attachTerminal` 快照带当前状态。Runner 在 hello 声明能力位 `terminalControl: 1`，协议号不变；旧 Runner 没有这些字段，页面退回「其他窗口正在输入 · 只读」且不实时更新——只有基于新底座重建并重新保存的算力档位新开的 CLI 才显示名字。
>
> 落位：契约 `packages/contracts/taskrunner/{nativeTerminal,protocol}.ts`；Runner `runtimes/task/src/terminal/terminalControl.ts`；cs-session `modules/session/domain/terminalViews.ts`、`application/browserStreams.ts`；工作台 `features/dev-session/model/native/{nativeTerminalAttachment,terminalControlView}.ts`、`hooks/native/useTerminalFocus.ts`、`components/native/NativeTerminalView.tsx`。

平台在 dev-session L5 解析档位，继续注入已有 MCP、权限、环境与 Git 身份。`packages/agent-drivers` 各自生成原生 TUI 启动计划，`runtimes/task` 复用 PTY／进程监督；租户 API 不接受任意驱动 flags，也不在普通 shell 内拼字符串来间接启动。具体 argv 以实施时安装的 CLI 帮助与原生交互实跑确认；同时保留现有 headless 计划及 oneshot 测试。

## 6. 工作树与部署的比较契约

新增 `GET /v1/projects/:projectId/dev-session/version-comparison?target=prod|preview`，默认 prod。dev-session L5 经既有 releases port 读取目标实际 releaseId／tag／SHA，经 runner port 读取当前容器的实际分支、HEAD、Git index 与文件状态；不向 SCM 的远端分支查询借用“当前 HEAD”。

响应分别描述 `workspace`、`deployment`、`commits`、`uncommitted`、`upstream` 和 `checkedAt`。每部分独立有 ready／unavailable 等状态，整体还包含 `comparisonId` 与 `freshness`。提交关系状态为 equal／ahead／behind／diverged／unrelated／unavailable／undeployed；只有明确计算成功时才返回数字。详情接口按 comparisonId、tab、cursor 有界返回提交、文件和 patch；工作树变化导致旧比较失效时要求刷新，不静默把新内容挂在旧快照标题下。

对固定的 P、H，待上线提交用 `git rev-list --count P..H`，缺少的生产提交用 `git rev-list --count H..P`；先验证对象完整与共同历史。浅历史不足不能当成无共同历史。文件差异比较 P 与当前实际工作树，已暂存与未暂存结果一起体现，另列未跟踪文件；提交列表和文件净差异分开，不用 GitLab compare 返回的一页长度充当完整数量。

Git 对象不在容器时，首次只读查询明确返回缺失原因；用户可显式“补齐历史并重算”。该操作只获取对象到平台自有比较引用，不 checkout／reset／merge、不改开发者当前分支或文件；失败仍为未知。禁止为了展示对比自动覆盖工作区。

读取过程固定 production releaseId／SHA 与 H；计算前后检查 HEAD／index／工作文件标识和部署来源，变化则标 stale 并有界重查，不宣称并发写入中的文件快照原子一致。大仓库有超时、分页和截断；所有限制在正式 contracts 中明示并测试。

进入开发、重新聚焦、文件保存、CLI 写入／提交后经去抖刷新；对无法获得细粒度事件的外部写入，用仅在页面可见时的有界轮询和手动刷新补齐。执行发布／释放前仍做权威预检。生产切流／回退后失效对应比较；生产 P 未重新核验时旧差距显示上次检查时间和过期状态。

## 7. 必须验证的行为

- 每次新增一个真实 CLI，连续新增后各自可输入与并行运行；首条任务可空，原生交互提示与 Ctrl+C 实跑；不能用 stub 输出作为此验收。
- 某窗启动失败、双击、请求超时和重连不会重复生成成功窗口，恢复不会把别的 Agent 会话附上。
- 独立预览、代码、放大／收起、离开／返回保持进程；显式结束只作用于指定 Agent。
- Agent 保存文件后预览按项目实际热更新能力变化，工作树改动数同步更新，生产仍不变。
- 对比覆盖相同、领先、落后、分叉、未首次部署、无共同历史、浅历史、对象缺失、生产已切换、计算中产生新提交。
- 文件覆盖已暂存、未暂存、未跟踪、删除、重命名、二进制、冲突与截断；未推送独立于未上线，已有推送仍可显示待上线。

布局与交互可在原型中评审；真实 PTY、模型、HMR 与 Git 对比必须在正式实现后独立验收。平台尚无模型输出的已知环境事实不变。

## 8. 数据访问的名称与真实含义

会话顶部入口命名“数据访问”，完整呈现下面三类。Agent 的 `read-only／edit／full` 另放“高级 → Agent 操作权限”，保留全部选项；不能把文件权限下拉简单换成数据库名称。

| 界面文案 | 现有值 | 真实含义 |
|---|---|---|
| 开发数据 · 可读写 | `development` | 服务的独立开发库，默认可用、跨会话保留 |
| 生产数据只读 | `diagnostic-readonly` | 申请读取生产数据，由负责人批准，受有效时长约束 |
| 生产数据读写 | `production-change` | 申请读写生产数据，由负责人批准，受有效时长约束 |

作者给出的“开发临时数据”用于表达开发用途；当前资源实际不会随页签或开发会话关闭而清空，因此采用“开发数据”，不改变数据生命周期。依据：`proposal/design.md:167, 775–785`。

三项是可并存的数据绑定，不是互斥的自动切库开关。`modules/data/application/taskBindings.ts:9, 62–67` 分别产生开发、生产只读、生产读写三种环境变量；批准不等于运行中的进程已载入，也不等于业务应用已选用该连接。界面分别表示未申请、待批准、已批准／接入待确认、实际可用、到期、撤销和拒绝。预览显示自己的真实数据源，生产申请不能自动把“开发预览”标签改成“已连接生产”。

申请复用既有 mode／reason／ttlMinutes 和 decision API，不新增审批角色或规则。用途可选、最多 500 字，有效时长 5–1440 分钟；错误按字段展示。获批绑定的作用域是整个开发会话中的所有 CLI、普通终端及应用进程，不是某个页签或 Agent 的私有授权。保留已有绑定列表与撤销入口；若同会话已有生产读写可用，申请只读不表示写能力已经撤销。收起面板后仍有生产访问状态提示，不能显示一个选择值掩盖并存的绑定。

## 9. 每个 CLI 的执行状态与后台提示

作者要求每个会话明确表达执行中／结束，并在其他页签的会话完成或需人工介入时提示。这里的“会话”以每个原生 CLI Agent 为单位，不能只显示开发容器在运行或 WebSocket 已连接。

| 状态 | CLI 标题与内容 | 页签／全局提示 |
|---|---|---|
| 启动中 | 正在启动当前 CLI | 不计为已执行 |
| 等待任务 | CLI 已准备好，还没有执行本轮指令 | 无需打断用户 |
| 执行中 | 明确“执行中”，可见最近动作与执行起点 | 页签显示执行数量 |
| 需要你处理 | 显示需补充的输入／确认及其关联原生提示 | 页签“需处理 N”与顶部动态入口常驻，直到请求已解决或失效 |
| 本轮完成 | 本轮结果可看，CLI 仍运行，继续输入开启下一轮 | 后台页签显示“新完成 N”，产生一次可定位的动态 |
| 已中断 | 当前轮次中断；CLI 是否保留单独标明 | 未完成不当成成功 |
| 已结束 | CLI 进程已经退出，显示退出原因 | 与本轮完成区分；需要继续时显式重启 |
| 失败 | 启动／执行失败与错误位置 | 进入需处理列表，有直达和可用恢复动作 |
| 状态未确认 | 连接中断、状态源不可用或缺少语义事件 | 显示最后已知状态及时间，不能假称完成／仍执行 |

每个工作页签聚合其中 CLI 的需处理数、未读完成数、执行数，按需处理优先展示；收起或关闭页签后的 CLI 仍进入顶部“Agent 动态”。顶部入口跨开发、预览、代码和项目其他页保留。新完成／需输入只产生一次轻量提示，不抢焦点、不切走用户当前页签、不弹浏览器模态框；持续执行不反复刷通知。

点击“前往处理／查看结果”按 projectId＋taskId＋agentId＋terminalId＋turnId＋eventId 定位并展开目标终端；已收起的窗口恢复显示。查看只清除本人未读标记，不能自动答复、批准操作或消除仍未解决的等待状态。下一轮开始后，上一轮结果不继续标成当前完成；待输入超时、撤回或取消后按源事件消除待办，不能仅凭查看通知清除。

### 9.1 真实状态来源与契约

`packages/contracts/taskrunner/agentEvents.ts:5–7` 已有 `permission／status／completed／cancelled`，但它是现有结构化驱动输出的契约；原生 PTY 输出只是一串终端字节，不能默认获得等价语义。T13 必须补原生 CLI 的受支持状态通道；以实际安装版本的结构化事件／hook／控制接口确认轮次开始、待输入、解决、完成、失败。没有可靠通道则显示“状态未确认”，不能从终端静默时长、文本关键词、某个工具完成事件或“进程还在”猜测整轮结果。

新增 CLI activity 形状包含稳定 agentId／terminalId、turnId、单调 seq、kind、occurredAt、summary，以及待处理 requestId／requestKind／resolvedByEventId；生命周期 processState 与连接状态单独返回。开始、待处理、解决、完成和退出必须能关联同一轮次；一条 tool-end 或 step_finish 不直接等同于整个用户轮次完成。

dev-session L5 拥有投影与个人已读游标，session L5 只转发；不能同层深 import，跨层取状态继续通过 task-runtime 端口或 contracts 事件。名册查询返回最新状态；`GET /v1/tasks/:taskId/agent-activity?cursor=&limit=` 有界补齐断线区间，`POST /v1/tasks/:taskId/agent-activity/read` 以 `{agentId, turnId, throughSeq}` 更新当前用户的已读位置，只作用于目标 CLI。流事件按 agentId／turnId／seq 去重，乱序或旧轮次的完成不得覆盖新轮次执行；同一项目另一成员查看不会替本人清除通知。

验收必须覆盖后台完成、等待回答／原生确认、解决后恢复执行、下一轮、只完成工具未完成任务、Ctrl+C、进程退出、断线重连、重复／乱序事件和关闭页签后的提示。两种原生 CLI 各有真实证据，不用附件的定时模拟代替。

正常使用时若原生 CLI 仍不能可靠区分执行／人工等待／本轮完成，T15 不得验收为完成。“状态未确认”是降级事实，不能替代正常链路实现。

状态通道的固定版本原生实测与尚存缺口见 [native-activity-evidence.md](native-activity-evidence.md)，不能只凭钩子名称或文档字段宣称轮次完成。
