# RFC-003｜多 CLI 开发工作台与生产版本对比

> 状态：Draft · 2026-09-13 · 本文细化并修订 proposal J2、design §2.3。本文中的流程为目标设计，尚未实现。
>
> 作者本轮明确要求：一键启动多个 CLI 窗口、运行多个 Agent 并行开发；独立预览实时效果；显示当前工作树与生产部署版本的差距。

## 1. 最终使用方式

进入开发会话，先看到版本状态条与 CLI 工作区。选择窗口数量（例如 3）和平台算力档位，点击“一键启动 3 个 Agent”，直接出现三个独立的交互式 CLI 窗口。启动前不强制填写首条任务；可以先开窗口，再在各 CLI 内输入不同任务。再次使用保留本会话的数量和档位选择，操作前仍可修改。

每个窗口对应一个独立 Agent 进程与 PTY，支持原生 CLI 输入、流式终端输出、交互提示、滚动、缩放与 Ctrl+C。窗口可命名、平铺、放大、收起／恢复；可逐个追加或结束。没有主 Agent、固定角色或平台自动派工。

所有窗口默认在同一个开发容器、同一个当前工作树内并行开发，看到彼此已写入的文件。窗口数量不代表容器或分支数量；平台不会因此自动建分支、worktree、合并或串行化 Agent。多人／多 Agent 改同一文件仍遵守现有工作方式；内置编辑器继续保留 expectedVersion 冲突提示。

平台仍按 RFC-001 提供算力档位，用户不重新配置驱动、模型或模型凭据。CLI 本身可显示其原生界面；平台不额外把驱动／模型选择变成租户必填项。既有结构化 Agent 对话能力保留为明确的“对话模式”入口，不把 JSON 输出涂成终端来替代原生 CLI。

## 2. 布局与独立预览

从上到下：

1. **版本状态条**：工作树分支／HEAD，生产实际标签／SHA，双方独有提交数，未提交文件数；点击查看提交与文件差异。待验证版本可切换比较；远端同步信息单独标示。
2. **工作视图与启动栏**：CLI 窗口、实时预览、代码、版本差异；窗口数量／档位、一键启动、追加窗口、准备发布。
3. **工作内容**：默认 CLI 窗口平铺；“预览并排”保留 CLI 工作区并在右侧呈现预览；“独立预览”占满工作内容区，也有真实开发预览地址可在另一浏览器页签／显示器打开。

预览直接访问当前开发容器的预览服务，观察的是当前工作树的实际结果，包含已经保存但尚未提交的修改。支持热更新的项目由自身开发服务器实时更新；其余项目按真实开发命令的重载行为运行，并提供刷新／重启和日志入口。不能承诺任意应用都具有 HMR，也不能用定时动画冒充更新。

开发预览标明当前会话、工作分支和开发数据绑定；与“发布后试用版本”及正式访问保持区分。切换独立预览、代码、版本差异或离开工作台，只分离显示连接，不中止 CLI，也不重复启动进程。预览进程失败保留 CLI 工作区可用。

桌面以两列平铺 CLI 为基础；多个窗口可纵向继续，单窗可放大。选择并排预览后按实际宽度调整；1024 及以下优先保留可用终端宽度，支持切换独立预览。窄屏单窗切换，所有 Agent 继续运行。没有被隐藏的永久按钮，也不要求把四个终端硬塞进一屏。

## 3. 版本差距必须回答的五件事

| 信息 | 含义 | 不能混淆为 |
|---|---|---|
| 正式版本 `v… @ P` | 当前承担正式流量的 Release 与部署 SHA | 最新标签、待命版本、远端 main |
| 工作树 `branch @ H` | 开发容器实际 Git HEAD；分支切换后更新，detached 时如实标明 | 建会话时记下的 branch、远端分支缓存 |
| 已提交但未上线 A 个 | H 可达而 P 不可达的提交 | 未推送数量、简单版本号相减 |
| 工作树缺少生产提交 B 个 | P 可达而 H 不可达的提交；A、B 都大于 0 时为分叉 | 只有一个正负数字、默认建议覆盖工作树 |
| 未提交修改 N 个文件 | 已暂存、未暂存、未跟踪文件分别列明 | 不计入比较、伪装成一个已提交版本 |

另显示“相对上游未推送／缺少远端提交”，但这是仓库同步关系，与生产差距是独立事实。一个已经推送到 main 的提交，仍可能尚未部署到生产。

差异详情有四个页签：**待上线提交、缺少的生产提交、相对生产的文件差异、未提交改动**。文件页可看路径、增删行、文本 patch、重命名与二进制说明；未跟踪文件单列，不漏掉。生产与工作树文件净差异不能用“提交文件数＋未提交文件数”相加，避免重复计数或遗漏抵消。

首屏示例为演示值：生产 `v0.1.2 @ 3975d02`，工作树 `main @ 9fd01fc`；2 个已提交修改待上线、缺少生产提交 0、未提交文件 0。修改文件后未提交数变化，而提交数不会凭空增加。生产切换到相同 HEAD 后，提交差距归零，未提交修改仍保留。

未首次部署显示“尚无正式版本”；缺对象／浅克隆／历史不足显示“暂不可比较”；无共同历史显示“无共同历史”；后台计算或生产版本变化时显示更新中／已过期。上述状态都不能显示为 0 或“已一致”。零提交差距但还有未提交文件时，显示“提交一致，工作树有修改”。

## 5. CLI 启动、恢复与失败契约

新增 `POST /v1/tasks/:taskId/agent-terminals`，单窗输入为 `{clientRequestId, compute?, permission, cwd?, cols, rows}`，返回 `{agentId, terminalId, state: 'starting'}`。数量只是界面批量操作：一次点击为每个目标窗口固定一个请求 ID，再按有界并发派发，不创造业务 DAG。数量必须为正整数，资源不足逐窗报告；数量限制若需要，由实际资源策略明确给出，不以原型中的 3 作为平台硬上限。

以调用者＋taskId＋clientRequestId 幂等识别已受理启动；重复使用同一 ID 但内容不同必须冲突。同一批部分成功时保留成功窗口，只允许重试明确失败项；断线／超时不等于失败，先查询原 ID 的真实受理状态，再决定是否重试。

新增 `GET /v1/tasks/:taskId/agent-terminals` 返回窗口名册、进程状态、terminalId、compute、permission、启动／退出时间和退出原因。名册由 dev-session 的启动记录与 TaskRunner 当前注册表对账，不靠浏览器内存假定进程存在。连接不可达时状态为未知；重连原 PTY，不自动恢复为新 CLI 进程。TaskRunner／容器重启后进程已丢失时如实显示结束／不可恢复，继续会话必须由用户显式操作。

`POST /v1/tasks/:taskId/agent-terminals/:agentId/stop` 为显式结束；Ctrl+C 是原生终端输入语义，不等于释放开发容器。收起／关掉一个显示窗仅 detach，结束进程有独立动作。释放整个开发会话沿既有确认停止全部进程；保留现有强制释放能力。

TaskRunner 增加 `startAgentTerminal`／名册查询等协议及终端 started 事件，复用 terminalInput／Output／Resize；Agent 进程状态不通过猜测输出文字判断。cs-session 按 terminalId 路由，终端恢复有有界回放／快照及缺口说明，不能把截断后的 ANSI 尾部当作完整屏幕。多个浏览器附着同一终端时，只由显式取得输入控制的视图发送输入／尺寸，其余视图可读；这不限制不同 Agent 并行运行，也不引入工作树单写锁。

平台在 dev-session L5 解析档位，继续注入已有 MCP、权限、环境与 Git 身份。`packages/agent-drivers` 各自生成原生 TUI 启动计划，`runtimes/task` 复用 PTY／进程监督；租户 API 不接受任意驱动 flags，也不在普通 shell 内拼字符串来间接启动。具体 argv 以实施时安装的 CLI 帮助与原生交互实跑确认；同时保留现有 headless 计划及 oneshot 测试。

## 6. 工作树与部署的比较契约

新增 `GET /v1/projects/:projectId/dev-session/version-comparison?target=prod|preview`，默认 prod。dev-session L5 经既有 releases port 读取目标实际 releaseId／tag／SHA，经 runner port 读取当前容器的实际分支、HEAD、Git index 与文件状态；不向 SCM 的远端分支查询借用“当前 HEAD”。

响应分别描述 `workspace`、`deployment`、`commits`、`uncommitted`、`upstream` 和 `checkedAt`。每部分独立有 ready／unavailable 等状态，整体还包含 `comparisonId` 与 `freshness`。提交关系状态为 equal／ahead／behind／diverged／unrelated／unavailable／undeployed；只有明确计算成功时才返回数字。详情接口按 comparisonId、tab、cursor 有界返回提交、文件和 patch；工作树变化导致旧比较失效时要求刷新，不静默把新内容挂在旧快照标题下。

对固定的 P、H，待上线提交用 `git rev-list --count P..H`，缺少的生产提交用 `git rev-list --count H..P`；先验证对象完整与共同历史。浅历史不足不能当成无共同历史。文件差异比较 P 与当前实际工作树，已暂存与未暂存结果一起体现，另列未跟踪文件；提交列表和文件净差异分开，不用 GitLab compare 返回的一页长度充当完整数量。

Git 对象不在容器时，首次只读查询明确返回缺失原因；用户可显式“补齐历史并重算”。该操作只获取对象到平台自有比较引用，不 checkout／reset／merge、不改开发者当前分支或文件；失败仍为未知。禁止为了展示对比自动覆盖工作区。

读取过程固定 production releaseId／SHA 与 H；计算前后检查 HEAD／index／工作文件标识和部署来源，变化则标 stale 并有界重查，不宣称并发写入中的文件快照原子一致。大仓库有超时、分页和截断；所有限制在正式 contracts 中明示并测试。

进入开发、重新聚焦、文件保存、CLI 写入／提交后经去抖刷新；对无法获得细粒度事件的外部写入，用仅在页面可见时的有界轮询和手动刷新补齐。执行发布／释放前仍做权威预检。生产切流／回退后失效对应比较；生产 P 未重新核验时旧差距显示上次检查时间和过期状态。

## 7. 必须验证的行为

- 一次启动多个真实 CLI，各自可输入与运行；首条任务可空，原生交互提示与 Ctrl+C 实跑；不能用 stub 输出作为此验收。
- 某窗启动失败、双击、请求超时和重连不会重复生成成功窗口，恢复不会把别的 Agent 会话附上。
- 独立预览、代码、放大／收起、离开／返回保持进程；显式结束只作用于指定 Agent。
- Agent 保存文件后预览按项目实际热更新能力变化，工作树改动数同步更新，生产仍不变。
- 对比覆盖相同、领先、落后、分叉、未首次部署、无共同历史、浅历史、对象缺失、生产已切换、计算中产生新提交。
- 文件覆盖已暂存、未暂存、未跟踪、删除、重命名、二进制、冲突与截断；未推送独立于未上线，已有推送仍可显示待上线。

布局与交互可在原型中评审；真实 PTY、模型、HMR 与 Git 对比必须在正式实现后独立验收。平台尚无模型输出的已知环境事实不变。
