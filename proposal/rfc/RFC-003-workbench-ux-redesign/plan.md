建议按可用闭环逐批交付：

1. **先把开发与交付跑顺**：T3、T4、T13、T14、T15、T5、T6；多原生 CLI、独立实时预览、工作树对生产差异与发布上线完整衔接。
2. **补完运行与能力使用**：T7、T8、T9、T16；让用户能从错误走到定位、从能力说明走到真实调用。
3. **收口入口和管理员供给**：T10、T11、T12；完整管理路径、项目列表和全角色验收。

以上是代码依赖顺序，不是缩减本 RFC 范围。每一批都应能独立验证，不能仅交几个漂亮静态页面便标记整轮完成。

## 2. 可用性验收脚本

| 编号 | 给使用者的任务 | 可观察通过条件 |
|---|---|---|
| UX-AT-01 | 找到指定数字人并继续开发 | 能按名称／slug 找到项目；已有会话直接继续；不需记 ID |
| UX-AT-02 | 第一次开发一个样例 | 选择分支、看到真实准备状态；每次点击新增一个原生 CLI，不要求先填任务 |
| UX-AT-03 | 同时使用多个 Agent | 独立 CLI 可平铺、放大、收起／恢复；每个输入／中止只作用于对应 Agent |

| UX-AT-38 | 查看和申请三类数据访问 | 开发数据、生产数据只读、生产数据读写语义准确；并存绑定不误报互斥切库，批准不伪称已接入；字段错误齐全 |
| UX-AT-39 | 切至其他页签、预览或发布时某 CLI 完成 | 目标页签及顶部新完成提示更新；不抢焦点、不丢当前草稿；点击直达正确轮次与终端 |
| UX-AT-40 | 后台 CLI 等待输入／确认，再解决请求 | 待处理持续可见；查看不自动解决或批准；显式答复后恢复执行，失效请求不能继续提交 |
| UX-AT-41 | 完成本轮后再次输入、Ctrl+C 或退出 CLI | 本轮完成与进程结束区分；新轮次显示执行中；旧结果不能覆盖新轮次；中断不算完成 |
| UX-AT-42 | 重复、乱序、断线补发、状态通道缺失 | 每事件至多一条通知；按轮次／seq 对账；未知不展示成功，工具完成不等同整轮完成 |
| UX-AT-43 | 关闭后台页签并由不同成员查看状态 | 隐藏 CLI 的待处理仍在动态入口；查看恢复原终端；个人未读与个人布局不被他人清除 |
| UX-AT-44 | 开发者／测试者／应用使用者进入工作台 | 无能力接入和平台开放策略入口；管理员在管理空间完整创建／开发／发布接入 |
| UX-AT-45 | 非项目成员浏览和搜索市场 | 返回其所有获准查看的应用；不返回隐藏应用、名称、计数或项目内部数据 |
| UX-AT-46 | 负责人切换三种可见范围并保存／取消 | 默认项目成员；指定用户去重并验证存在；空指定名单有字段错误；取消不改变已保存结果 |
| UX-AT-47 | 成员角色及指定名单变化，列表和详情访问 | 同一可见性裁定，旧缓存不保留已撤销结果；市场可见性不授予开发、生产数据、APIGrant 或改变原 prod 链接规则 |
| UX-AT-48 | 可见范围并发保存和查询失败 | expectedRevision 冲突保留草稿；失败不伪装为成功／无应用；普通开发者不能更新或任意查询他人可见性 |
| UX-AT-49 | 打开已上线／尚未上线／状态未知应用 | 使用准确正式版本和真实地址；未上线不跳 preview；未知如实呈现 |
| UX-AT-50 | 从开发资源申请接口并试调，管理员处理 | 消费与接入入口分离，文档／MCP 同源，调用仍使用当前服务身份与原授权 |
| UX-AT-51 | 顶栏、favicon、登录页及单色标识 | 同一协作舱原稿，16／24／32／64px 可辨，明暗主题正常，不把图标当运行状态 |
| UX-AT-52 | 从会话菜单查看并继续历史对话后返回 | 没有“对话模式”按钮；明确独立历史对象，CLI 数量、页签、输入草稿与后台状态完整保留 |

“一次上下文跳转”等为待验收的设计目标，不是当前原型已测结果。生产验收要记录实际账号角色、项目、分支、tag、SHA、releaseId、环境与结果，不能只报“点过页面”。

## 3. 自动验证

- 纯状态模型：主动作优先级、未知数据、来源选择、版本校验、回退候选、字段错误、日志 URL 参数。
- CLI／布局状态：进程与轮次分离、待处理解决、通知去重与旧轮次、个人已读、布局移动／关闭／恢复和最小尺寸；真实事件契约与端到端输入共同验证。
- 真实路由树渲染：兼容链接、两空间守卫、项目切换迟到响应、角色显示、未保存输入、异步错误恢复；延续现有 happy-dom 测试约定。
- 协议与后端：workspace-status 真失败、不吞退出码；成员精确匹配的可见范围；试调通道的超时／断线／大响应／服务错误；项目分页有界与部分失败。
- 现有回归：RFC-001 租户档位投影、RFC-002 管理空间守卫、发布来源与槽迁移、终端控制、文件 expectedVersion。
- 最终运行 `bun run check` 和 console build。发布后查本次精确 SHA 的 GitHub Actions；跳过的集成测试单独记录，不把跳过算实跑。

## 4. 设计附件的验证

`prototype.html` 是独立演示：项目概览、逐个 CLI、新建页签／分屏、执行／待处理／完成与独立输入、独立／并排预览、工作树版本差异、发布检查／试用／上线／回退、失败日志定位、能力市场／可见性、独立历史对话、品牌标识、能力申请、配置表单、管理员创建的界面反馈都只更新本地演示状态。

演示中固定显示“交互演示 · 示例数据”，不会向本机集群提交操作。原型里的 Agent 输出不代表真实模型执行；发布进度不代表真实流水线；管理创建不创建真实项目。页面范围与已验证交互记录在同目录 `prototype-review.md`。

## 5. 不属于本次 UX 实现的已有问题

STATE 中的受保护分支推送、worker HOME 与访问令牌回收，需要各自的领域方案；本 RFC 只保证在相关失败处给出真实原因与恢复入口，不绕开它们。M6 安装／HA／规模验证、模型凭据配置也不因 UX 改造而变成已完成。
