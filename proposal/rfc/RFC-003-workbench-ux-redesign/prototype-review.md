## 附件范围

默认以“平台管理员同时担任项目负责人”的示例身份查看。固定显示“RFC-003 · 交互演示 · 示例数据”。所有交互只更新页面内存，不连接 CrewStation API，不运行模型，不修改集群、成员、授权或配置。

本附件用于评审布局、入口、对象关联、操作顺序、字段错误与反馈。平台设置目录、接入容器内部、数据访问和部分高级能力展示信息结构，完整增删改与真实生命周期以 design／plan 的规格为准。

## 本轮开发工作区修订的浏览器验证

作者明确要求多原生 CLI、独立实时预览与工作树对生产版本差异后，开发页已替换首稿聊天优先布局。以下记录仅验证新的演示行为：

| 场景 | 实际结果 |
|---|---|
| 一次启动三个 CLI | 未填首条任务，点击一次后有三个独立窗口，先启动中再已连接 |
| 独立输入 | 只给 Agent 1 输入时仅该窗口增加示例输出，其余两个输出不变 |
| 未提交与预览 | 示例修改后未提交文件变为 1，已提交待上线仍为 2；独立预览显示新增状态筛选的效果 |
| 跨视图保留 | Agent 2 的未发送输入跨独立预览／CLI 切换仍保留；窗口名册保持三个 |
| 放大／收起／恢复／结束 | 单窗可放大、收起和恢复；只结束 Agent 3 后其显示已结束，另两窗继续已连接 |
| 比较目标 | 生产 SHA 与当前 HEAD 不同；切到与 HEAD 相同的待验证版本后提交差距为 0，未提交文件仍为 1 |
| 未提交 patch | 显示 `src/Welcome.tsx`，未暂存 1，已暂存／未跟踪 0，并有示例文本差异 |
| 响应式 | 1024 宽并排模式主体 992／scrollWidth 992；390 宽 CLI 主体 358／358；320 宽独立预览与版本差异主体 288／288 |
| 桌面与运行 | 明色桌面 CLI／并排预览检查，最后浏览器 error／warn 为空；原型脚本语法检查通过；视口已恢复 |

演示的 1–6 窗限制仅用于附件；正式产品数量由真实容器资源约束决定。原生终端在附件中用简化输入和输出展示交互顺序，没有运行 xterm／PTY 或实际模型；正式实现不能沿用这个模拟输入方式冒充 CLI。独立预览展示的是页面内工作视图，真实浏览器新页签、HMR、终端恢复、版本分叉／历史缺失、批量部分失败、窗口命名等仍按专项设计与 AT-28–34 在实现后验收。设计选项可切换部分示例状态，但本记录不把未执行的选项算作测试通过。

## 首稿浏览器记录（提交 a4a5e1a）

以下为首稿检查的历史记录；其中对话优先布局已被本轮开发页修订，不能拿它作为新 CLI 布局的验证证据。

| 场景 | 本轮实际观察 |
|---|---|
| 项目概览 | 项目名称可读，当前开发与两种版本有明确入口，技术详情可展开 |
| Agent 消息 | 输入后出现对应消息与明确的演示回应，输入框清空 |
| 新建 Agent | 空首条指令提示字段错误；有效指令创建第二个示例会话，原对话保留 |
| 多 Agent 并排 | 两个面板分别绑定 Agent 1／2；保留各自输入与示例消息 |
| 开发工具切换 | 未发送输入跨代码／预览切换仍保留；保存示例文件后标记未提交 |
| 未提交内容发布 | 准备面板列出 `src/Welcome.tsx`，会话发布按钮不可执行，有返回代码入口 |
| 版本输入错误 | `incorrect` 提示版本格式错误，未开始模拟构建 |
| 发布到试用 | 有效 `v0.1.5` 先显示受理／构建，再显示可试用；正式版本仍为 `v0.1.2` |
| 上线与回退 | 行内确认明确 `v0.1.2 → v0.1.5`；确认后版本及对应 SHA 更新；回退后正式恢复 `v0.1.2` |
| 失败日志 | 从 `v0.1.1` 失败行进入构建日志，保留版本上下文；搜索 ERROR 只过滤当前示例行 |
| 能力申请 | 空理由有错误；有效理由提交后显示待审核状态 |
| 两空间处理申请 | 管理空间批准示例申请，返回原能力详情后状态更新为可调用 |
| API 试调反馈 | 输入示例项目编号后显示带编号的“示例响应”，不声称执行了真实接口 |
| 创建数字人 | 空表单一次显示名称、标识、负责人三项错误；逐步进入确认，受理后明确没有新建真实项目 |
| 配置约束 | 生产组选中时显示共用与生效条件；真正清空 GREETING 后显示字段错误 |
| 1024×768 | 开发对话与预览保持双栏；附件主体宽 992、scrollWidth 992，无主体横向溢出 |
| 390×844 | 切为单工作视图；对话与预览可切换；主体宽 358、scrollWidth 358 |
| 320×760 | 概览、发布与上线、能力接入、项目设置、管理创建均为主体宽 288、scrollWidth 288 |
| 控制台 | 本轮最后检查未见 error／warn；脚本通过 Node 语法检查 |

宽度差 32px 来自本地预览包装页左右各 16px 的外边距，不是产品设计的横向损失。检查后已恢复默认浏览器视口。

## 已修正的演示问题

- 沙箱预览不允许原生表单导航，改为在按钮上派发本地 submit 事件，保证表单验证与反馈真实触发而没有外部提交。
- 新 Agent 改为先填写档位、权限与首条指令；不再直接复制已有 Agent 的对话内容。
- 对话／代码草稿保留，开发与生产配置值分开保存。
- 上线与回退后，标签和 SHA 一起切换；管理员拒绝理由能在租户详情保留。

## 尚未作为验收通过的项目

真实模型输出、Kubernetes 开通与发布、真实服务身份试调、角色授权、成员候选后端、日志保留、并发与断线重放均未在此附件中执行。平台设置全量增删改、接入容器的完整内页、明色主题浏览器检查、屏幕阅读器和全部键盘路径尚需正式实现时验证。

交互原型没有持久化和真实 URL 路由；刷新重置演示数据。目标产品的深链接、浏览器历史、草稿恢复和跨项目缓存约束见 design.md，不以此附件的页面内导航代替实现。
