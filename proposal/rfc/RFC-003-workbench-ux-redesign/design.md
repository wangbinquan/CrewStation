## 1. 导航与路由

### 1.1 稳定的对象上下文

工作台全局有能力市场与数字人项目列表，项目内固定五个入口。页头只保留项目名称、当前页、主要动作，slug 为辅助定位。切换项目是显式动作，不以浏览器本地缓存推断成员权限。

`projectId`、当前路由与有效 query 决定页面上下文；API 缓存键至少含 projectId／serviceId，按实际查询另含 taskId／releaseId／slot。切换项目清除前项目的异步动作目标；迟到响应不能覆盖当前项目。技术详情包括完整 ID、SHA、镜像、容器、命名空间与原始错误。

### 1.2 目标路由和旧链接接续

| URL | 导航位置 | 说明 |
|---|---|---|
| `/`、`/market` | 能力市场 | 已授权应用列表，名称／用途搜索；详见市场规格 |
| `/market/$projectId` | 应用详情 | 再次校验可见性，打开真实正式应用 |
| `/projects` | 数字人项目 | 原列表保留，服务应用建设者 |
| `/projects/$projectId` | 概览 | 带条件主动作与状态摘要 |
| `/projects/$projectId/dev-session` | 开发 | 保留 URL；`view=cli|preview|split|code|diff`，`agent=`、`file=`、`target=prod|preview` 可定位；默认 cli |
| `/projects/$projectId/release` | 发布与上线 | 保留 URL；`release=` 选版本，`source=session|repository` 标识来源 |
| `/projects/$projectId/operations` | 运行与诊断 | `tab=health|logs|deliveries|trace`，按 tab 校验对象参数 |
| 旧 `/projects/$projectId/capabilities` | → 项目设置的开发资源 | 保留各文档／消费能力和 operation 参数；不渲染管理接入 |
| `/projects/$projectId/dev-session/conversations` | 历史对话会话 | 旧版结构化 Agent 独立页面，可返回原 CLI 布局 |
| `/projects/$projectId/settings` | 项目设置 | `tab=members|visibility|config|resources|repository|lifecycle`；`env=development|production` |
| 旧 `/catalog` | → 项目设置 `tab=resources&resource=api` | 保留 proxy／operation 等有效参数 |
| 旧 `/events` | → 运行诊断 `tab=deliveries` | 保留同屏“查看订阅”入口；有 subscription 参数则定位相应对象 |
| 旧 `/logs` | → 运行诊断 `tab=logs` | 保留 source、slot、taskId、releaseId、since、limit |
| 旧 `/config` | → 项目设置 `tab=config` | 保留 env；无 env 默认 development |

旧开发链接 `view=conversation` 重定向到独立历史对话页面，保留原 agent 参数并明确历史对象。

开发地址的显式 view 优先于个人保存的视图；无 view 时 file 定位代码、agent／terminal 定位 CLI、target 定位差异，其余继续个人布局（首次默认 CLI）。`changes` 兼容为 `diff`。视图和文件切换进入浏览器历史，返回可恢复相应视图；关闭文件仅替换当前地址、清除 file。页签名称、窗口位置及分屏比例仍属于个人布局。普通 CLI 链接只恢复名册中的原窗口，完整动态链接继续由原事件校验与个人已读流程处理。task 不匹配时明确提示，不在替换后的会话读取文件或定位 CLI。

文件树、发布预检、释放前清单与差异文件可进入真实代码视图；删除项保留文件名，差异中的二进制项不提供文本编辑动作。切换未保存文件先具名确认，取消保留当前地址和草稿；保存回执未到不能确认切换，仍可取消导航。读取失败或缺少有效文本时保留原草稿，关闭文件需原有放弃确认。比较区可选择实际生产／待验证目标，分别缓存并核对回执，标题、提交计数与详情采用对应目标的名称，补历史同样传递该目标；顶部紧凑条仍以生产为基准。

兼容重定向使用 replace，浏览器返回不会在旧／新 URL 之间循环。参数无效时回到该页有效默认值并保留项目，不把未知 releaseId 当成最新发布。

### 1.3 管理空间

管理总览保留 `/admin`。原有八页路径继续可达，新增 `/admin/projects`、`/admin/capabilities`、`/admin/requests`。出站待办与 API 申请可在申请页分栏查看，规则维护留在原 `/admin/egress`。

能力接入入口为 `/admin/capabilities?tab=integrations|api|events`；旧 `/admin/integrations` 与 `/admin/api-catalog` 保留重定向到对应分类。接入容器详情采用 `/admin/integrations/$projectId`，后缀 dev-session／release／operations／settings 对应复用的业务页面。由 app 路由装配注入 projectId 与空间上下文，feature 不硬编码必须在租户 projectRoute 下运行。

访问旧 `/projects/$projectId` 下的接入容器时，管理员跳到管理详情；普通用户遵守现有拒绝行为。原来租户页里的平台开放策略按钮迁到管理 API 目录，管理员可从开发资源的文档上下文定位管理目录，普通开发者无该管理入口。

## 2. 页面布局与交互规格

### 2.1 项目列表

首屏是“数字人项目”标题、搜索、状态筛选和列表；管理员看到进入管理空间创建的入口，不常驻表单。项目列以名称＋slug 为主；版本与开发摘要需从真实 API 获取，加载／未知状态独立显示。

默认每页 20 条是本 RFC 的界面设计值，不是已测容量。采用服务端有界分页；在分页接口未接通的开发切片中，仅显示 ProjectDto 已有的开通状态，不把它命名为“运行健康”。不对数百项目逐个轮询全部资源。

空态区分未获项目、无搜索结果、加载失败。无项目时说明管理员开通职责；“复制开通信息”只复制需求模板，不伪装已经提交申请。名称、slug、负责人查找都支持清除条件。

### 2.2 项目概览

顺序为：项目名与角色 → 主动作 → 当前开发／待验证／正式三个事实 → 需要处理的事项 → 最近发布活动。健康不可用时显示“状态暂不可用”，不把空返回当成正常。

主动作优先级：

1. 开通失败／未完成：查看开通问题／查看准备状态。
2. 本项目有失败中的发布：处理该版本问题，次动作继续开发。
3. 有开发会话：继续开发；有待命版本时给独立试用入口。
4. 无会话：开始开发；无开发权的人不展示可执行开发按钮。

成员管理、配额编辑、归档都移出概览主体，概览通过链接到完整详情。活动只使用实际发布与切流记录，不拼出不存在的模型输出或业务任务统计。

### 2.3 开发工作区

作者本轮明确开发主界面为多个原生 CLI 窗口，独立实时预览，以及当前工作树与生产版本差距；这修订首稿的默认聊天布局。完整规格与契约见 [development-workspace.md](./development-workspace.md)。

顶部常驻容器实际 branch／HEAD 与生产实际 Release／SHA 的对比，分别显示待上线提交、缺少生产提交、未提交文件，远端同步信息另列。点击进入提交与文件 patch；同 SHA 但存在工作区改动不能称为完全一致。

每次点击“＋ CLI”只启动一个原生 PTY／Agent，首条任务可空；不再提供批量数量。工作页签可新建、命名、关闭，单页签支持横排、纵排、网格和分隔线调整，CLI 可排序／跨页签移动。每页签保存自己的布局，全部 CLI 共用工作树。原生输入、Ctrl+C、放大、收起／恢复、显式结束均保留。旧版结构化会话改由会话菜单的“历史对话会话”独立进入；不再提供“对话模式”切换，也不把历史 L-id 当成当前 CLI AgentId。

> 2026-09-23 修订：工作页签、横排／纵排／网格与跨页签移动改为 Xshell 式标签组——每个 CLI 一个标签，拖动标签排列与分屏，× 即结束进程，新开入口在页头；见 [development-workspace.md §2.1](development-workspace.md#21-页签与分屏规则) 同日修订。

TaskRunner 的屏幕快照通过 `runtimes/task/src/terminal/terminalSnapshotView.ts` 对 SerializeAddon 提供只读可见列视图，避免 xterm 缩窄后保留的旧行容量被错误序列化。跨右边界、无法完整显示的宽字符在快照中以同样式空格占位，不能导致后续行移动；原模拟器内容不变，再次放宽可继续读取。仍使用当前 cols／rows、throughSeq 和既有协议，颜色、光标、模式及滚动历史边界由原序列化器保留；`terminalScreen.test.ts` 覆盖旧侧栏、未发送草稿、宽字符／颜色和非破坏性放宽。

历史消息草稿在 feature hook 中按 AgentId 独立保留，切换对象或暂时打开新建表单不清空。每个对象独立控制发送在途状态，重复快捷键不重复派发；只有成功回执且草稿版本未变时才清空对应输入，失败显示原错误并保留草稿，不自动重发。同页历史对象链接可切换，缺失对象不能默默选中另一 Agent；离开页面复用共享输入保护，在途期间不能确认放弃。测试采用真实历史页面／mutation 和可控 HTTP 回执，覆盖并行、失败、迟到成功、对象切换和返回 CLI。会话元数据中的 branch 标为“创建时分支”，当前分支仍取容器工作树查询。

历史 Agent 名册由 dev-session 从持久事件还原。驱动明确发出 `status: waiting` 时显示“等待输入”，不设置结束时间；下一轮实际执行事件恢复“执行中”，保留同一 AgentId、原生会话 ID、算力档位和权限。明确的 `status: running` 可恢复执行态，其他说明性状态不推测执行。只有 completed／error／cancelled 记录结束时间，不能把交互轮次的结束当作整个会话结束。

历史页面收到明确等待／运行、权限及结束事件时重读名册；旧驱动下一轮没有单独开始信号时，以该 Agent 首条实际文本／思考／工具事件触发一次重读。同轮后续片段不逐帧查询，等待或结束后重置该 Agent 的查询标记；不同 Agent 分别记录。标记只控制读取频率，呈现状态仍来自平台 DTO，刷新不切换对象或清空草稿。真实路由与 HTTP／WS 边界回归核对状态标签、焦点和请求次数。

历史新建 Agent 的首条指令、档位与权限也归当前会话持有，收起表单后保留，并与消息草稿共用离开确认。启动同步防重，固定当次输入且在途不可修改；可以返回已有对话，收到结果前不能确认离开。失败保留且不自动重发，成功清除新建输入；只有仍停留新建表单时才选中新 Agent，返回旧对话后的迟到成功不切换对象或抢焦点。这里只延续已有历史会话功能，不改变原生 CLI 逐个启动和免首条指令的主路径。

开发模式默认紧凑：上下文与版本各一行，工作页签与当前页工具栏紧接其后，终端区域成为主体。桌面四窗 2×2，首屏可见各自输出与输入；不用大标题、重复状态卡片、巨大等待占位。数据访问三类名称、共享范围与接入状态见专项设计 §8。

每个 CLI 区分连接、进程生命周期与本轮执行状态；执行中、需人工处理、本轮完成、已结束明确呈现。页签聚合状态，顶部 Agent 动态跨项目页保留，点击定位而不自动确认／答复。原生状态通道、个人未读与去重契约见专项设计 §9。

实时预览可占据独立工作视图、与 CLI 并排或通过真实地址在另一浏览器页签打开。预览反映已保存的工作树文件；是否热更新依赖实际开发命令。代码保存继续带 expectedVersion。预览失败仅影响预览；代码、CLI 和日志继续可用。

工作树、提交和文件比较共享同一上游失败时，每份比较摘要只显示一次相同原因；不同失败原因仍分别保留。不把不可比较替换成零差距，实际部署标签继续显示。复用 `ComparisonSummary` 同时作用于顶部紧凑条和详情，`versionComparisonView.test.tsx` 覆盖两种形态及独立原因。

预览工具栏的“查看开发会话日志”携带实际 taskId，保留管理／租户空间，沿用有界容器日志来源；Runner 的预览 stdout／stderr 已写入该日志，不新增假预览日志源。状态按连接世代读取，后来收到的结构化事件优先于较早的查询回执；断开、换任务或无效状态时不沿用可用地址。重启与刷新串行受理，同轮重复操作只发一次；重启失败和当前预览状态分别保留，后续就绪读回不抹掉失败，不自动再重启。

detach 显示与结束进程分开。关闭浏览器、切换工具、跳转发布均不发送 closeTerminal／stop；重新进入重新附着既有 PTY。结束指定 Agent 和释放整个会话均是明确操作；释放前读工作区事实，未保存编辑器草稿与 Git 未提交／未推送仍为三类状态。窄屏切换单窗并保留后台执行。

### 2.4 发布与上线

页面上方并列“正式版本”和“待验证版本”，各自包含标签、SHA、地址、就绪状态和动作；下面是当前选中发布的详情与步骤，再下面是紧凑历史列表。

发布准备打开行内面板，步骤是“确认来源 → 查看检查结果 → 确认版本与发布”。发布本身仍是独立显式动作，不添加自动发布。

| 来源 | 输入与承诺 | 实际调用 |
|---|---|---|
| 当前开发会话 | 显示当前会话 taskId 的可读关联、实际分支、HEAD、未提交文件；不能用另一个下拉分支偷偷承接当前 HEAD | `api.devSession.publish`，保留服务端未提交检查和代推 |
| 已推送分支 | 从远端分支选择；明确“只包含远端已推送提交”；显示远端 SHA；不声称已检查容器 | `api.services.publish`，保留无开发会话发布能力 |

来源确认采用 `expectedCommitSha`（完整 40／64 位 SHA）；开发来源另带 `expectedTaskId`。两字段可选以兼容既有 CLI／MCP，新工作台始终发送。开发发布先核对会话和实际 HEAD，再推送固定 SHA 到已确认分支，不在推送命令里重新取 HEAD；release 经原 tagger 端口把 SHA 传给 scm，scm 核对远端分支后按固定 SHA 打标签。检查时来源变化返回 precondition／conflict，保留输入并要求重新检查；检查后分支继续前进也不能把标签改打到后来提交。该修正分别落在现有 contracts、dev-session L5、release L4、scm L3 和 platform 装配，不新增模块或改变层级。

版本递增仍发送已有 major／minor／patch；UI 计算的下一标签只是候选，服务端返回的 tag／SHA 是事实。版本冲突时保留输入并刷新已存在标签，不能静默换版本重发。

发布进行中自动定位到该 releaseId，用户离开后从概览／历史可继续查看。返回 202 只代表已受理，不能显示“发布成功”。构建、迁移、部署步骤以后端状态为准；没有状态数据的细分步骤显示待查询，不用计时器模拟进度。

待命槽角色是 preview，当前线上角色是 prod；蓝绿物理槽不成为用户必须选择的概念（`modules/release/domain/slots.ts:34–39`）。确认上线直接写“正式版本 vA → vB”，并显示源与目标 SHA；带现有 expectedActiveRelease。冲突后刷新并要求重新确认，不能自动重试切流。

上线／回退检查重新读取实际两槽及其发布记录，固定两个 ID、标签与完整 SHA；未知、身份不一致、待命未就绪或无可用副本不提供确认。较早创建且仍在待命位置的发布显示“回退”；迁移限制由服务端最终裁决，回退不会恢复生产数据。只有实际就绪槽提供访问入口，历史 ready 记录不直接提供试用／任意回退。成功只表示切换已登记，网关异步生效须实际访问核对。槽、历史和选中发布采用当前项目有界读取；后台暂停轮询，返回前台补查。切换后失效槽、历史、工作树版本比较及差异详情。

发布／切换共用本页写入互斥和一份离开确认，各自说明草稿在取消、失败和内部导航后保留。切换前的服务槽锁内还检查进行中的发布，避免构建／迁移期间将即将覆盖的待命位置切成线上；返回冲突关联 releaseId，等待后重新确认。发布登记先以不覆盖已有行的方式初始化槽，再加锁复查正在进行的发布，覆盖打标阶段的并发窗口。若另一发布已受理，说明本次标签已经创建、未启动流水线并返回 createdTag 与已有 releaseId；不自动删标签或修改版本重发。两处仍在 release L4 的既有事务与端口内完成。

确认另固定 `expectedTargetRelease`，防止待命槽被后来发布替换；`expectedActiveRelease: null` 明确表示用户确认时还没有正式版本，省略则兼容旧调用方。两项在 release 既有领域判断中核对，持久化 UnitOfWork 的写事务对同一 service_slots 行加更新锁，防止两个请求同时读到旧快照而都通过。普通查询不加更新锁。上线／回退 UI 始终携带当前（允许 null）与目标 ID；失效后不重用旧确认。本项只修正既有迟到切流保证，不更改权限、物理槽或迁移策略。

回退只针对当前待命槽仍保留的版本。兼容性由服务端裁定；破坏性迁移明确显示不可回退的原因与修复指引，不能仅灰掉按钮。历史记录即使很多，回退候选也最多是当前仍可切回的那个槽。

**固定的数据语义**：开发预览默认开发数据；发布试用和正式访问共享生产数据。发布到待命槽会执行生产迁移，确认时必须说明；不能把待命槽称作隔离的测试环境。

### 2.5 运行与诊断

健康页呈现两槽的就绪副本和状态，异常项带到具体日志。日志默认最新 200 行，可选择现有上限；来自发布页面时默认 `source=build|migration`＋`releaseId`，来自开发页时为 `source=dev-session`＋`taskId`。固定上下文以可清除的筛选项显示。

“全部部署槽”省略 slot，后端在当前项目命名空间内按服务名与 `workload=service` 查询，涵盖蓝绿两槽并排除同服务的开发任务；明确 prod／preview 时仍按当前部署角色映射到物理槽，不把未指定槽默认成正式槽。

停止跟随只停止前端定时刷新；新日志到达时用户可选择回到底部。日志尾部数据不能伪装为全历史。告警订阅与 trace 回放使用已有 HTTP 接口补齐客户端；不新增业务任务编排界面。事件投递详情包含类型、状态、attempt、最近错误、trace、重试结果及关联订阅。

死信重放的项目授权在锁外完成，随后在 events 的既有事务中按投递 ID 锁行重读、转换状态并入队（`modules/events/application/replayDelivery.ts:13`、`modules/events/adapters/persistence/drizzleDeliveryRepositories.ts:32`）。事务 scope 的点查持有锁，普通查询保持快照读取；并发或迟到请求读取到 pending／delivered 后返回原 precondition，不覆盖状态。入队适配器检查去重回执（`modules/events/adapters/queue/queueDeliveryScheduler.ts:17`）；旧队列任务尚未收尾时返回 412 并回滚完整死信记录，收尾后可再次重放。重放受理状态为 pending，实际 delivered 由 worker 持久化；队列公共语义和数据库结构沿用既有实现。真实数据库、HTTP 订阅者及 worker 回归覆盖并发、迟到成功、队列收尾与恢复。

日志时间取 Kubernetes `timestamps=true` 返回的容器时间，按毫秒规范化；只剥离有效 ISO 时间前缀，正文日期、数字和缩进保留。时间缺失或非法时 `ts` 缺省，界面显示“时间未知”，不以查询时间代填；这些记录保持读取顺序并排在已知时间之后。默认 Pod 日志没有逐行 stdout／stderr 来源，`stream=combined` 如实表达，正文未指明级别时显示中性 LOG；原 stdout／stderr 记录继续兼容。已有 Pod 的日志读取失败返回错误，不能静默跳过并呈现为空或完整结果。仍沿用现有标签范围与有界尾部，不扩大日志保留承诺。

告警页从现有接口读取最近 100 条，按触发中／已恢复在这些记录内筛选，并保留指定 alertId；未找到时不换成另一条记录。健康告警从本模块标准 key 导出可选 slot，不解析自由文本猜测目标；当前没有发布 ID 的告警只链接该角色当前日志，明确无法据此定位当时版本。订阅仍沿用每用户／项目一条的 PUT／DELETE 语义；用成员名称选择，完整 User ID 输入保留；显示渠道／地址约束、替换前后材料、具名删除与草稿确认。后台查询失败不伪装为零，表单失败或收起保留输入，页面内部筛选不卸载草稿；写入共用同步锁。

当前 platform 装配的告警 Notifier 仅记录日志（`modules/platform/wiring.ts` 的 composeAggregates），并未按订阅投递工作台个人通知或 Webhook。界面明确“订阅配置已保存／通知送达未验证”，不提供假发送测试或送达标记。本 RFC 此项补齐既有接口与真实状态呈现，不把新增通知投递基础设施夹入 T7；真实通知通道接入仍为原能力的后续工作。

### 2.6 能力市场、开发资源与管理接入

能力市场是全局应用入口，项目侧移除“能力接入”。市场显示所有有权查看的应用、负责人、用途和正式状态；负责人维护市场可见性。具体范围、列表／详情一致性与接口见 [market-visibility.md](./market-visibility.md)。

项目设置的开发资源承接已获准 API 文档／申请／试调、事件订阅、数据说明、档位／配额与平台约定。API 详情保留 projectId／serviceId／operationKey，试调继续使用当前开发会话。

2026-09-23 修订说明（[RFC-020](../RFC-020-project-workspace-ia/design.md) D2／D5／D7）：「开发资源」不再是项目设置分组，也不再是左栏入口——API 接口、事件、平台接入三个主题住在开发页的参考面板（侧栏紧凑、放大即整页），数据与存储在开发页的数据面板，项目与仓库在项目设置「项目信息」组；旧地址一次 `replace` 重定向并保留参数。左栏改为「概览／开发／发布与上线／运行与诊断／项目设置」五项生命周期顺序；概览底部的「项目快捷入口」卡删除（左栏即入口），发布页的发布历史与切流记录合并成一条带人名与标签的时间线。

管理员“能力接入”包含接入容器、接口开放策略和事件来源，供给与审批动作只在管理空间出现。市场可见性不等于 APIGrant。

### 2.7 项目设置与管理空间

项目设置分成员、应用可见性、配置、开发资源、仓库、生命周期。成员按可辨识名字与已注册账号匹配，角色含完整说明；保留开发者、负责人、preview 测试者。配置默认开发组，切生产组明确显示影响的正式与待验证版本；保存成功同时显示生效条件，不声称已注入正在运行的进程。

> **2026-09-23 修订（作者当面裁定，直接修改，不另立 RFC）。** 「切生产组明确显示影响的正式与待验证版本」作废：生产组下的「生产配置与部署版本」对照卡已删除（RFC-009 proposal §3.3 同日再修订）。保存成功显示生效条件、不声称已注入在跑进程的要求不变。

可见范围与展示资料分别保存自己的修订和草稿，共用一份离开确认；成功保存一项不清除另一项，取消修改明确指向当前表单。后台设置变化保留本地输入并要求显式采用最新修订，读取失败暂停保存和采用修订；输入留在页面内存。成员查找文字、高级 ID 与角色在切换选择方式时保留，但只按当前方式确定提交目标；身份读取失败或角色变化保留可核对的草稿并暂停相应写入，刷新同时重查身份和成员。已打开的负责人转移确认重新核对当前管理员身份。保存中的重复提交只发一次，离开确认说明已发送请求不会撤销，迟到回执不改变当前页面。以上均落在 projects feature，复用 shared 的导航确认与表单组件，不新增后端权限或持久草稿能力。

创建数字人／接入容器按对象分入口，固定相应 kind 范围，模板与套餐从真实目录选择。第一步名称／负责人，第二步模板／资源，第三步检查与创建；回上一步保留输入，服务器字段错误映射回原字段。开通状态只展示已有事实，未提供阶段明细时写“开通中”，不画全绿的假步骤。

创建向导离开、返回历史或切换创建范围时保护未保存输入。确认创建固定当次输入，回执须是有效且名称／标识／类型／负责人均匹配的项目；正常成功解除草稿保护并接续该项目开通页，用户已确认离开后的迟到回执不再导航。目录、创建失败或未知回执保留原输入，不自动重试。

服务套餐和任务容器套餐沿用各自目录接口，展示名称与资源约束、字段错误及具名编辑。提交前和最终确认前分别重读，同名项展示完整新旧值，目录变化更新材料并要求再次确认；原接口仍是整体覆盖，没有新增后端 CAS 或并发合并保证。保存成功与后续读取失败分开提示，前者不表示运行中资源已变化：服务在下次发布采用，已有任务容器不变。新建、换编辑对象、失败与离开都保护草稿。数量字段维持原字符串契约，界面提供既有格式示例与非空校验，不自行缩窄资源数量的合法写法。

实现落位：SCM（L3）从控制面实际的 `templates/`／`integrations/` 源码目录提供管理员 `GET /v1/catalog/project-templates`，返回名称、Manifest 类型、模板原套餐及尚需配置的键名；缺失或非法目录报错，不伪装空目录。保留两处源码目录，发行包布局 I8 不在本 RFC 裁定。project（L2）保存创建时实际校验过的 `initialPlan`，原 `template` 字段继续存用户选择；单项目内部开通查询经 platform（L7）接到 provisioning 和 SCM。初始套餐只改首次提交前的模板副本，已经有远端默认分支的重试不覆盖代码。旧项目无初始选择记录则保持未知，不回填成当前默认套餐。目录不会承诺模板必定首发成功：缺少生产配置或密钥仍由既有开通状态和失败信息反馈。

管理员总览中的待办只从现有 API 申请、出站申请与项目失败读取。可部分加载；某来源不可用时保留其错误，不用 0 覆盖。进入接入容器内开发与发布，保留项目导航及返回项目管理入口。

2026-09-21 作者实机修订：接入项目侧栏不再嵌套折叠的“平台管理”菜单，仅保留当前项目的页面与“返回项目管理”。返回固定到 `/admin/projects`，包括项目不存在时的返回入口；管理员在项目详情点击顶栏“平台管理”也进入该目录，使“项目管理”成为当前项。概览底部的发布、成员、仓库、开发资源改为同一张紧凑的“项目快捷入口”卡片，每项包含用途说明与方向标识，保持当前项目与空间的目标地址；窄屏按两列／单列排列，整项可点击且键盘焦点清晰。回归覆盖从项目目录进入接入项目、子页面返回、顶栏返回、缺失项目返回以及两类项目的四项实际导航。

管理有界读取契约：API 申请和出站申请各增加 `/page` 查询，兼容原全量端点；按项目与裁定状态先筛选，再按创建时间及 ID 倒序取默认 20、最多 50 条。游标绑定账号、管理员身份、项目与状态，翻页不依赖锚点仍处于原状态。当前页关联项目通过 project 公开批量基础查询取得名称／类型，最多 50 个 ID，一次本模块 SQL；名称读取失败保留申请与真实项目 ID，不假造对象。总览每类待办只读取前五条，说明当前范围并导航到实际管理页，数量不是全局总数。 总览申请入口进入对应项目的待审批列表，开通失败进入实际项目开通页；加载、错误、空态和各来源读取时间分别展示。只读管理摘要按账号缓存，进入、前台周期及恢复可见时核对身份和来源，后台停止周期读取；管理身份失败可重试。审批页和项目管理页以 URL 条件及服务端游标分页；管理项目列表保持管理员上下文，接入容器仍只包含 APIProxy／EventProducer。

审批页只读取活动页签的当前 20 项，URL 分别保存 API 与出站游标，切页签保留两种范围；改变项目或状态时清空游标。当前页项目名称来自申请回执，缺少名称保留实际 ID，两个来源都可按行进入项目范围。编辑页不做周期或默认焦点刷新，读取错误保留意见并暂停裁定。

同一查询范围内 API 与出站表单常驻，意见按申请 ID 保留在页面内存。翻页、改项目／状态或离开前共用草稿确认，在途空意见同样保护；确认离开不撤销已发请求。刷新后不在当前待审批记录中的输入单独保留为具名副本，审批结果以最新记录为准。裁定固定当次对象及意见，有效匹配回执才显示成功并清除该份未变意见；其他草稿及失败输入保持。错对象或未知回执不自动重试，迟到回执不导航回旧页。原申请／授权／出站规则失效关系继续保留。

## 3. 状态和失败恢复

| 对象／状态 | 呈现 | 可行动作／恢复 |
|---|---|---|
| 初次加载 | 内容骨架、保留项目上下文 | 超时后重试当前区块 |
| 未获项目 | 明确由管理员开通，无虚假统计 | 复制开通需求；有项目但筛空时清除筛选 |
| 创建会话中 | 显示分支与已知就绪项，未知项待查询 | 查看原因；禁止重复创建，不禁止离开 |
| 已有他人会话 | 创建者、分支、连接状态 | 进入既有会话；既有授权决定操作范围；不建议先释放 |
| Agent 未配置／失败 | 原因与该会话的失败状态 | 保留输入，重试明确创建新的执行，不冒充模型输出 |
| 连接断开 | 连接状态条＋保留最后数据 | 自动重连；不重复发送已受理消息；未受理输入留草稿 |
| 开发容器已失败 | 首屏显示原 taskId 与已记录的原因；保持原工作区显示和页面草稿 | 不自动启动 CLI；显式新建从远端分支使用新工作树，确认说明旧卷不会因此删除、页面未保存输入会丢失；另按本次委托确定的 I14(a) 实现保卷重建 |
| 编辑冲突 | 本地草稿保留，明确磁盘已变 | 比较／重新载入；不能把取消提示当成覆盖确认 |
| 工作区检查失败 | “无法确认未提交／未推送内容” | 重试或人工检查；不展示空清单表示安全 |
| 有未提交文件 | 文件列表，定位编辑器 | 自行提交后重新检查；平台不自动提交 |
| 推送失败 | 分支、原始错误摘要、“未创建标签” | 回开发检查／按需联系管理员，不绕开保护分支 |
| 版本已存在／发布并发 | 保留用户输入、关联已有发布 | 查看现有发布，或显式修改版本后再提交 |
| 构建／迁移／部署失败 | 精确失败阶段与日志上下文 | 继续开发修复，或在满足既有策略后新版本发布 |
| 待命就绪 | “可试用”，版本地址＋生产数据提示 | 打开试用；负责人可上线 |
| 上线并发冲突 | 展示最新版本和变化来源 | 刷新后重新确认，不自动覆盖 |
| 无法回退 | 当前版本、原因及可行下一步 | 发布修复版本／维护窗口，不能伪装回滚成功 |
| 接口／配置变更未生效 | 已保存／待审批／待部署分别显示 | 按实际需要刷新授权、发布或重启 |
| 无权限 | 对象与原因；保留可用的返回路径 | 不发无权写请求，不把拒绝写成“暂无数据” |

## 4. 数据与接口

### 4.1 优先复用的现有接口

2026-09-15 多角色实机修正：开发者的生产配置只读，字段、覆盖和删除入口按当前身份与取值组决定；身份暂不可读时停写并保留草稿。测试者仍只有既有 `view-preview` 权限，不扩大 `view`：release 提供仅待验证槽的授权查询，经当前项目摘要返回独立 `preview` 来源；只含当前待验证版本与地址，不附带正式槽、发布历史、配置、日志或工作树。测试者在项目列表和详情看到试用及就绪状态，旧开发／设置链接转为试用说明，不挂载原无权子页面；仅实际 ready、有效 SHA 和新鲜来源可打开。未部署、读取失败、角色撤销及正在部署均没有假试用入口。

| 目标 | 已有契约／实现 | 前端需要做的事 |
|---|---|---|
| 项目和角色 | `packages/api-client/resources/projects.ts`、me、members | 可读名称、统一项目上下文，保留服务端作用域 |
| 会话、Agent、分支 | `packages/api-client/resources/devSession.ts`、任务流 | 跨视图复用同一连接，恢复选中对象和输入草稿 |
| 发布、槽、切流 | `packages/api-client/resources/services.ts` | 两种来源同一页面，按 releaseId 恢复进度；不重复实现发布领域 |
| 精确日志 | `packages/contracts/api/observability.ts:7–15` | 接线 taskId、releaseId、since 与 URL；保留尾部限制 |
| 告警／订阅／trace | `modules/observability/http/observabilityRoutes.ts:21–25` | 补 api-client 方法与 UI；不新增同义后端接口 |
| 能力、申请、事件、配置 | api-client 已有 resources | 改交互布局、补深链接、按成功动作精确失效缓存 |

### 4.2 工作区检查（本 RFC 新增，P0）

新增 `GET /v1/projects/:projectId/dev-session/workspace-status`，由 dev-session L5 应用用例拥有，沿既有 runner port 读取事实，无写入、无 push、无 tag。供准备发布／释放权威预检；开发首屏版本比较共享其工作区读取逻辑，按可见页面与变更事件有界刷新，不做高频全树扫描。

响应采用可区分联合：

- 可读：`{ status: 'ready', taskId, branch, headSha, uncommitted: [{path,status}], unpushed: [{sha,subject}], checkedAt }`。
- 无法检查：`{ status: 'unavailable', taskId, reason, checkedAt }`。没有会话仍用既有 404；禁止把失败映射为成功的空数组。

Git status 命令退出码异常必须判失败。UI 预检只是用户决策材料，发布 POST 必须继续执行权威检查。释放前需要重新读取上述结果并展示具体清单；确认时调用既有释放动作。这里不宣称快照与删除之间原子一致，也不新增平台工作区单写锁：有运行中的 Agent／终端时说明可能仍有写入，让使用者自行停止和保存；负责人强制释放保留既有能力和明确后果。后端释放日志查询失败要保留 unknown 语义，不返回“已推送全部”的虚假事实。

### 4.3 成员定位（本 RFC 新增，P1）

为有现有成员管理能力的项目负责人提供精确身份匹配：`GET /v1/projects/:projectId/member-candidates?identity=<完整账号或邮箱>`。返回最多一个已注册用户 `{userId,name,email}` 或无匹配；不提供无条件全局人员枚举。新增客户端接口用于选择结果后继续调用现有 setMember。查询失败保留输入；不存在时解释对方需要先登录注册或管理员处理。

身份匹配由 project L2 用例调用 identity L1 的公开查询，角色裁定复用现有规则。该能力明确是本 RFC 的新增查询，不假定现有全局 `/users` 已对负责人开放。UI 保留高级 UserId 输入，避免缩减已有使用路径。

### 4.4 结构化 API 试调（本 RFC 新增，P1）

工作台经开发会话转发结构化 `{operationKey, pathParameters, query, headers, body}`；响应为 `{status, headers, body, truncated, durationMs}`，其中 durationMs 仅显示实测值。具体接口为 `POST /v1/projects/:projectId/dev-session/api-invocations`，复用已有会话授权与当前服务身份。

dev-session L5 可依赖 api-catalog L3 的公开操作查询，不经深路径读取内部表。由 runner port 执行请求，runtimes/task 的执行器经服务网关调用，不把用户字符串拼进 shell 命令。请求方法／地址由 operationKey 与当前目录解析；端到端试调与部署后使用同一放行表。请求超时、未连接、目录变化、响应过大都返回可展示错误；默认响应截断阈值和超时以实现时 contracts 中的明确常量为准并测试，不能宣称无限流式调试。

这不是浏览器直接代理任意 URL；Swagger 的 Execute 与详情试调共用这一条通道。现有终端调用仍保留。

实现契约：请求另带必填 `expectedTaskId`，防止把旧输入发送到新会话；响应固定 `{taskId, operationKey, result}`。路径参数必须与当前模板逐项匹配，query 允许重复值；请求体是可省略的 UTF-8 文本，GET／HEAD 不接受请求体。请求体与响应体各 64 KiB，请求／响应头各 16 KiB，完整 URL 8 KiB；参数／请求头最多 64 项，查询每项最多 16 个值。15 秒包括等待响应头及读取响应流，另给命令传输留 10 秒余量。响应为 UTF-8 文本视图，响应体与头分别提供截断标志；4xx／5xx 与 3xx 原样展示，重定向不跟随。超时、传输中断或回执不合法不能说明业务未执行，禁止自动重试。

新 Runner 命令 `invokeApi` 只接收目录解析出的 proxy、method、path 及有界输入，从既有 `CS_INTERNAL_API_BASE` 经服务网关发出。hello 的可选 `capabilities.apiInvocations:1` 在 socket 派发前检查，老容器／未配置通道保留普通 CLI 并返回明确提示；跨副本转发保留该错误码。Bun 连接复用曾在响应中断后自动重发 POST，试调链中的 HTTP 请求显式关闭连接复用；Runner 的响应中途断线回归验证只调用一次。dev-session 使用注入的 api-catalog 公开查询端口，不读其他模块表；新增两份生产源码后模块为 40 个文件，后续增长须先遵守结构文档 §11。

跨进程自动验收落在结构文档约定的 `tests/e2e/`，纳入根 typecheck；串起真实客户端、HTTP、PostgreSQL 连接注册表、两个 session 副本和 Runner。该测试中的目录与目标 HTTP 服务是夹具，不替代共享集群中源 Pod 身份与实际放行表的 J5 验收。

真实试调发现目录退役记录会遮蔽活动代理名，且 gateway 与 api-catalog 独立消费 `release.registered`，先更新路由再登记目录时无法收敛。api-catalog L3 通过公开 `activeProxyNameOf(serviceId)` 只返回该服务的活动代理；历史目录照常保留。目录事务完成后的回调由 platform L7 装配，调用 gateway L5 的既有路由重算与放行表刷新；发布登记只从这一条有序路径刷新，gateway 不再重复消费同一发布事件，避免已读旧目录的迟到请求覆盖新路由。项目与切流事件仍由 gateway 处理，不引入低层对高层的依赖。失败沿现有事件消费重试，目录登记保持幂等。组合根回归覆盖代理改名、撤下、未知服务、消费者先后与旧计划迟到的并发交错；实际共享网关仍须独立验收。

详情表单和 Swagger 共用固定会话、同步写入锁与响应校验。开始编辑时绑定 taskId，后台读取发现变化或失败后保留草稿；显式重新检查并绑定才能向新会话发送。每次结果带实际所属会话、操作键、容器耗时及头／正文截断提示。草稿按详情或 Swagger 具体操作记录，成功仅清除该请求已发送的输入标记，在途新增输入与其他操作不受影响。收起不清空；换操作、代理、文档或离开页面前确认未发送输入。输入和结果只在页面内存中保存。

Swagger 5.32.15 使用自身提供的 React 扩展操作与响应，按需加载；fn.buildRequest 负责序列化，fn.execute 转换为同一 api-invocations 请求，不调用原浏览器执行器。平台文档地址、具体路径和方法必须对应当前可调操作；文件、form 对象及不支持的路径序列化明确拒绝，原终端仍可调用。刷新文档不自动重建输入，变化后暂停 Execute，用户明确重新加载才应用。当前身份变化通过配置更新调整写入口并保留输入；原生输入事件立即记录草稿，不能等 Swagger 防抖提交后再记录。

### 4.5 有界项目摘要（本 RFC 新增，P1）

为列表提供 `GET /v1/workbench/project-summaries?cursor=&limit=20&q=&state=`：返回项目基础字段、当前用户角色、会话摘要、两槽版本摘要、可用的健康摘要以及 nextCursor。先从 project 公开查询得到授权项目，再做当前页聚合；单项失败分别标 unknown，不导致整页全空。

聚合落既有 capabilities L6，经各模块公开读 API，低层 project 不反向依赖 release 或 task-runtime。Project 基础分页查询和适配器在 project L2 内补齐。限定当前页、查询并发和缓存过期，后台页不持续轮询，不新增全企业活动仓库或物化视图。字段接口按引用数据的真实可用程度逐项添加，不能为填满卡片捏造数值。

实施契约：基础 `GET /v1/projects/page` 及摘要列表共用 q／state／ownerUserId／kind／cursor／limit，默认 DigitalWorker、20 项，上限 50；q 按名称与 slug 做不区分大小写的文字包含，通配符没有额外含义。project 在本模块 SQL 内联查成员角色、服务与项目，先限制当前成员或管理员范围，再筛选、按 ID 排序并 LIMIT；多取一项判断 nextCursor。游标绑定账号、管理员身份与筛选，改变条件从第一页重新查。负责人名称按当前页去重、最多四个并发查询，名称来源不可用时保留实际负责人 ID，不伪造名字。批量复核只接受最多 50 个项目 ID。

`GET /v1/workbench/project-summaries/:projectId` 返回同一项目摘要，另含最近五笔发布和五笔切流记录；原 release 查询每类最多读取 50 笔，再稳定排序截取。开发摘要从 task-runtime 的当前会话记录读取，仅含 taskId、生命周期、connected、分支、创建者与时间，不调用 Runner，不以连接状态推断原生 CLI 轮次或预览就绪。两槽来自 release，健康来自 observability 真实观察，各自带 checkedAt 和 ready／unknown／restricted。读取失败、重复／错对象回执、缺少版本 SHA、空健康来源均不会显示健康或已部署。

当前页的可选来源读取最多四个同时在途，先读各项目的会话和版本，再读取健康；这段聚合的预算为 2500ms，不包含基础分页与最终作用域复核。达到截止后不再派发剩余读取，尚未完成的项标 unknown；已发出的只读调用可能继续完成，但不会改变已返回的快照或借超时继续扩大并发。返回前通过 project 批量复核当前页；移除的成员项目不返回，降为测试者或服务身份改变时丢弃旧内部材料。测试者仍可看到原项目列表已有的基础信息，其内部摘要标 restricted，沿用既有读取边界。服务端不缓存摘要，两条摘要与基础分页 HTTP 入口均 no-store；客户端刷新与过期展示在 T11 界面批接续。

platform 的单项目服务解析改为 project 的公开定点读取，供摘要健康及既有开发会话使用，不再先列出全平台服务再 find。原无分页 projects.list 继续兼容既有调用方；页面批需将项目列表和管理入口接到有界查询，不能据后端接口完成就标记 T11 完成。

管理 API 调用方选择采用同一每页 20 项的基础项目分页与名称／标识搜索；当前已选项目独立定点读取，不因目录翻页、搜索或目录错误丢失。只有该项目资料确认后才使用其 serviceId，未知／错误不退回平台范围；清除调用方是显式操作。目录条件写入 URL，未应用输入在重读和翻页时保留；编辑入口只手动刷新，先查当前管理身份。

租户列表已接摘要分页：默认 20 项，名称／slug、开通状态与负责人条件保存在 URL，改变条件清掉游标；下一页、回到第一页及浏览器返回均读取对应范围。负责人下拉提供本页可辨识的负责人和当前账号，不额外浏览全平台用户目录；共享 URL 可保留原 ownerUserId 条件。项目名称与开通状态、负责人、开发、待验证、正式、健康和下一步并列；命名空间、创建时间、完整负责人 ID 等原资料保留在本行展开项。无项目可复制开通需求模板，复制不发送申请或创建项目；无匹配、未知数量、载入失败各自呈现。

概览复用单项目摘要，以当前角色和真实状态选择主动作：管理员处理开通、定位最新失败发布、继续已有开发或进入开发页；概览不直接创建会话、发布或切流。当前开发／待验证／正式并排，实际健康、待处理／待确认项以及具名最近活动保留各自来源。两个部署入口仅在记录仍有效、槽实际就绪且有可用副本时出现，待验证与正式共用生产数据明确显示。项目 active 的显示改为“已开通”，不再用“正常”暗示健康。

摘要以 checkedAt 判断 30 秒有效期，来源未知或过期不推断为无会话／健康／已部署；发生整页读取错误时可保留上次记录，但停止基于这些记录的开发主动作与直接访问入口。初次身份失败不会被未启动的摘要查询遮成加载或零项。客户端每次进入即重读，前台每 30 秒先刷新当前身份再读取摘要，后台暂停、恢复补查，未应用的搜索输入保留；刷新期间暂停状态操作入口。身份响应中原有的完整成员关系仍保留，但 platform 改用 project 的一次本模块成员查询，避免刷新身份时逐项目读取服务和角色。

### 4.6 独立状态与开通进度

本轮不额外造一套生命周期。现有状态来源：ProjectDto state/message、SessionDto state/preview、连接流、AgentInstanceDto、ReleaseDto 与 SlotDto。UI 的就绪行只能展示这些来源明确支持的状态。

完整的仓库／数据／模型独立准备进度属于基线目标，但当前响应不足以逐项确定。首个实现切片可如实标未提供；若要给分项进度，必须由 provisioning L6 或 dev-session L5 对其已有步骤结果提供契约，单独验收，不把绿色图标当成实现。

失败开发容器的保卷恢复按已选定 I14 (a) 实施，具体接口、原子准入、持久队列、UID 绑定及补偿见 [workspace-recovery.md](./workspace-recovery.md)。

新增接口和协议详见 [development-workspace.md §5–6](./development-workspace.md#5-cli-启动恢复与失败契约)。CLI 启动不能直接复用现有 headless JSON argv；需补原生终端启动计划、幂等名册、detach／attach、显式结束与有界回放，以及逐轮执行／人工介入／完成状态。个人布局与动态未读契约另见专项设计 §2.2、§9。版本比较固定生产实际 SHA 和容器当前 HEAD，覆盖双方独有提交、工作树文件、未推送以及未知／过期状态。

这两项是满足本轮用户需求的实现依赖，不可只做多窗口 CSS 或把远端 BranchDto 换个标题便标为完成。保留业务 Agent oneshot／interactive 契约和 RFC-001 的档位归属。

- 品牌使用 [协作舱标识](./brand-design.md)，双色与单色资产同源；正式 favicon／登录／顶栏一致。
- 字体沿用系统中文字体；正文 14px，次级信息 12px，页面标题 22px，行高适合中英混排。以上为待实施设计值。
- 间距沿用 4／8／12／16／24／32，圆角以 6／8 为主。主动作使用现有蓝色，不用彩色状态装饰空内容。
- 桌面全局导航约 208px（开发页同宽），主区域内边距 8–12px、窗口间隙 8px；终端标题与工具栏约 28–34px，四窗时复用一屏。普通业务表格行约 48–56px，开发页优先终端密度。2026-09-22 作者实机裁定：开发页左栏不再收窄到 156px，与其他页签完全同宽；开发页的密度只体现在正文——仍用 8–12px 内边距并去掉最大宽度，左栏宽度只由 tokens 一处定义，页面不得改写。2026-09-22 作者再裁定（RFC-019 原型评审时提出）：内容区不再设 1200px 最大宽度，全部页面随窗口铺满，`--cs-content-max-width` 令牌删除；开发页只保留更紧的内边距。
- 所有表单初始展示格式／长度／范围／生效条件；提交时同时展示各无效字段，聚焦首个错误。只用禁用按钮不是完整验证反馈。
- 新按钮／页签／确认区先扩展 shared 既有组件，不能在 feature 中另写一套同义组件。CSS 使用产品 tokens。
- 2026-09-23 作者裁定（直接修改，不另立 RFC）：动作型跳转——新建、返回、查看日志、打开配置、新窗口打开外部地址——一律是按钮样子，用 `shared/ui/navigation/ButtonLink.tsx` 的 `ButtonLink`（站内）与 `ExternalButtonLink`（新窗口；原先样式生成的 ↗ 已按下一条去掉）；它们仍是 `<a>`，可新标签页打开、可复制地址。名字、版本标签、文件路径、域名这类引用型链接与导航项仍是文字链接。原先四处各自手写的「按钮样子的链接」样式收回到 `Button` 的档位（新增 `size="small"`）；`apps/console/src/tests/actionLinks.test.ts` 阻断文案取自 `t(...)` 的裸 `<Link>`／`<a>`。
- 2026-09-23 作者裁定（直接修改，不另立 RFC；按钮统一）：
  - **两档高度**：标准 32px（页头、卡片、表单、空态）与紧凑 26px（`size="small"`：表格、列表、时间线里的行内动作，复制这类随值出现的小工具，开发页工具条）；同一行不混用两档。尺寸只在 `shared/ui/Button.module.css` 定义，页面不再改写按钮的高度、内边距与字号。
  - **位置**：代表一个对象的卡片（版本、维护、会话、档位、项目归档……）把针对它的动作放卡片底部操作条（`Card` 的 `actions`），主按钮最左、危险动作最后；装列表的卡片把「新增／添加」放标题行右侧（`extra`），行内动作放在行末、用紧凑档。侧栏详情（拓扑节点、集群资源详情、接口详情）的动作按同日 RFC-019 修订仍在顶部。
  - **样式**：主按钮蓝底；危险动作的触发按钮红字红框（`danger`），最终确认红底白字（`dangerPrimary`）；取消、关闭、收起、放弃一律无边框（`ghost`）。
  - **文案**：按钮上不放＋、↗、▾、↑↓ 这类非正式符号（「＋ 预置文件」改「添加预置文件」，步骤「↑／↓」改「上移／下移」，外部链接不再自动加 ↗）；「＋ 创建开发Agent会话 ▾」拆成主按钮「创建开发Agent会话」与描边按钮「选择算力档位」（原裁定为「档位与权限」，D59 起不再选权限）。
  - **刷新**：页面自动局部刷新，不提供刷新按钮（含 RFC-020 的页头「读取于 ↻」）。页面数据每 30 秒在原位静默重读、回到前台补读一次（`AUTO_REFRESH`）；网络中断与 5xx 的读取失败每 15 秒自动再读，失败文案写「稍后会自动重新读取」，不写「请刷新」；读不到项目（403／404）时每 30 秒再读，刚加入成员不必手动重读。例行重读不得用 `isFetching` 禁用入口或显示载入中。进度类对象按各自节奏（启动中每秒、发布进行中与告警每 5 秒、集群摘要 15 秒、趋势时间窗每分钟前移）。开发预览的「刷新」保留并改名「重新加载」（重载预览里的应用页面，不是重读平台数据）；保存冲突后的「放弃修改，读取最新内容」「重新读取当前角色」与 Swagger 的「重新加载文档」（装入新文档会丢掉输入）是动作，不算刷新按钮。`apps/console/src/tests/buttonConventions.test.ts` 阻断刷新按钮、带符号的按钮文案与页面里另定的按钮尺寸。
- 列表使用真实 table 与表头；选择用语义原生控件；键盘可到达所有动作。图标只辅助文字，不依赖 hover 获取必要信息。
- 行内确认支持取消，取消不清表单。确认必须写对象和效果，删除／归档／切流／重启不能共用模糊“确定”。不使用 alert／confirm／prompt。
- 2026-09-23 作者裁定（直接修改，不另立 RFC）：不可撤销的动作——归档项目，删除算力档位、登录接入方、配置项，集群「删除／结束」，工作区不干净时释放会话——改用页面内的模态弹窗 `shared/ui/dialog/ConfirmDialog`。它是页面里的 `<dialog>`，不是浏览器原生弹窗，不会冻住调试用的浏览器自动化。弹窗写清对象与后果，要输入英文确认词确认键才可用：归档 `archive`，删除 `delete`，释放会话 `discard`；中英文界面一律用英文，不分大小写，忽略首尾空格。确认键红底、排最左，取消无边框；Esc 关闭，点遮罩不关。释放会话在工作区干净时沿用上一条的行内确认；有未提交文件或未推送提交、页面上有没保存的输入、工作区检查失败或结果不可用时，行内确认之后再弹窗。其余确认仍用行内。
- 2026-09-23 作者裁定（直接修改＋回填，不另立 RFC；表单与确认改弹窗）：点了在页内展开的表单一律改为页面内的模态弹窗（`shared/ui/dialog`：`Dialog` 底座、`FormDialog` 表单、`ConfirmationDialog` 确认）；带核对材料或输入的确认面板，放弃、换对象、离开页面的提示（含 `UnsavedChangesGuard`）也改为确认弹窗。一行式的 `InlineConfirm` 仍在行内，「释放会话」工作区干净时的确认仍在页内，接口「试调」工作台保持原样（只有它的放弃确认改弹窗）。弹窗标题栏有 ✕；取消、✕、Esc 只关窗，草稿静默留在页面上、页面上不提示，再打开同一个入口恢复上次输入，操作条最右的「清空」回到初始值、弹窗不关；离开页面才丢草稿，离开确认写明哪些草稿会丢。弹窗经 `DialogHost` 画在应用根上；所在区域被身份守卫或页签藏起时随之不画（`DialogVisibility`），离开确认除外。上一条所说的「行内确认」自此只指 `InlineConfirm`。受影响的区域：发布（准备发布、上线／回退、进入／调整维护、重新部署）、项目设置（成员、应用展示与可见范围、环境变量）、目录「申请定向开放」、集群重启／调整副本／恢复发布配置、通知订阅、管理空间（身份提供方、项目规则、自动下线时长、复制档位、资源目录的两个确认、用户角色）、开发页（恢复原工作树、另建工作树、新建 Agent、数据访问审批、结束 CLI、编辑器放弃输入）。编辑器的保存冲突提示是持续的状态提示，仍在页内。工程约定见 `docs/engineering/development-rules.md` §7。
- 未保存草稿跳转给应用内选择；长时间处理有状态但不乱抢焦点。请求重试需要区分读与写，写操作不因切页自动重放。
- 明／暗主题均检视；1280×720 能同时看到开发输入与预览主体；1024、768、390、320 均检查长中文、长路径和错误文案。移动端不是缩小桌面四个面板。
- 原生 CLI 与普通终端复用 `features/dev-session/model/terminalTheme.ts` 的主题读取／监听。已挂载的 xterm 同时响应系统 prefers-color-scheme 变化和根元素主题覆盖；仅重读产品 tokens 更新配色，保留实例、输入与 PTY，卸载时释放该实例的监听。
