# RFC-003｜保留工作树重建容器

> 2026-09-15；I14 方案 (a) 已由作者全权委托选定并实现，真实保卷恢复见 implementation 第七十五批。属于 RFC-003；RFC-004 Hook 仍排队。

## 1. 用户操作与边界

失败开发会话优先提供“保留工作树重建容器”。先重新检查原任务、实际 Pod 和工作卷，再显示管理员提供的任务套餐。确认写清原 taskId、保留的工作卷和新容器资源；存储容量保持。旧 CLI 进程、未完成轮次不会自动重跑。原“从远端新建”保留为单独入口，并明确不能带回原卷中的未推送提交和文件。

读取检查失败时显示实际原因，不把未知卷当作空卷。工作卷不存在、正在删除、不是 Bound、UID 与检查对象不符，以及原 Pod 仍在运行时均不能重建。创建新容器失败仍保留原工作卷，提供重新检查后再确认的入口；不自动改选套餐，不自动扩大资源。

## 2. 接口与记录

dev-session L5 提供 `GET /v1/projects/:projectId/dev-session/rebuild` 检查与 `POST` 受理。两者都要求既有 develop 权限；提交固定 expectedTaskId、检查修订、expectedVolumeUid 和 requestId，选择现有任务套餐。检查带回原 Pod UID、工作卷 UID／容量、当前套餐和可选套餐，不返回凭据。

同一 requestId 和相同输入重复提交返回同一恢复记录；不同输入复用 requestId 拒绝。旧修订、已有新开发会话或并发恢复拒绝并要求重新核对。202 只表示恢复请求已受理；页面显示正在检查、替换容器、等待 Runner、就绪或失败，不把 202 当作恢复完成。

task-runtime L4 保存恢复记录及原／新容器身份，在同一数据库事务中登记、原子占用项目额度并入队。原 taskId、projectId、serviceId、pvcName、branch、个人布局和历史 Agent 身份保持；新 Pod 使用独立名称和新的 Runner 凭据。恢复记录持有 requestId、输入摘要、原 Pod UID、新 Pod UID、卷 UID、资源快照、阶段和失败说明。新凭据不进入记录、接口、日志或队列 payload；放在本次容器专用 Kubernetes Secret 中。

## 3. 生命周期与恢复

恢复由 controller 的持久队列处理，复用平台队列的租约和心跳，不依赖浏览器连接或 API 进程常驻。每个阶段只操作记录绑定的对象；租约失效即停止后续副作用。读取失败不能当作不存在。

1. 受理事务锁住当前项目准入与目标环境，确认仍为当前失败会话，原子占用一次额度并入队。旧 Runner 凭据立即失效，普通对账跳过恢复尚未创建 Pod 的阶段。
2. 重读原卷和 Pod；UID 必须与确认对象一致。删除只针对原 Pod UID，等待删除完成，不删除、重建或缩容工作卷。原 Pod 仍存活或已被替换则停止并报错。
3. 幂等准备新 Runner Secret，持久保存相应凭据哈希，再创建有本次恢复标记的新 Pod，挂载原卷。恢复不执行源码克隆，不签发新的 Git 检出凭据，不覆盖已有文件。
4. Pod 已存在时核对任务、恢复 ID、卷与凭据引用后才能采用。进程重启或回执丢失不重复创建另一个 Pod。预览路由随新容器恢复，旧 CLI 名册只能作为历史／不可附着显示。
5. 新 Runner 连接必须与本次环境和凭据一致，才能完成恢复；旧连接的迟到回调不能把新环境标为运行。普通对账在创建阶段完成后再处理 Pod 失败／丢失。
6. 失败补偿只清理本次新 Pod 与本次 Secret，固定 UID；原卷始终保留。额度只释放一次，恢复记录保留原因。已经创建但响应丢失的容器先核对再决定继续或清理，不以请求超时推断没有创建。

准备与补偿失败按队列退避重试。重试耗尽仍有待处理恢复意图时，对账按 requestId 去重补投，继续原步骤或清理，不创建另一份恢复。新 Pod 准备完成后 5 分钟仍无有效 Runner 连接则进入失败补偿；已连接环境不适用这个启动时限。原卷在预置环境后、创建 Pod 后均再次核对 UID；正常释放在恢复阶段明确拒绝，完成后回收本次 Pod、专用 Secret、原预览路由与 follow-container 卷。

正常释放仍按原规则回收 follow-container 卷；释放与恢复通过同一环境／项目锁和修订校验协调。个人草稿、布局与历史记录不由恢复流程清空。

## 4. 落位与验证

`packages/contracts/api/` 与 `packages/api-client/resources/devSession.ts` 管接口；`modules/dev-session/` 管授权及页面对象转换；`modules/task-runtime/` 管恢复记录、配额、队列和集群步骤；`packages/k8s/` 只扩展通用 UID 删除前置条件。组合根仍为 `modules/platform/wiring.ts`，不新增后端模块或修改层次。

必须验证：正常保卷恢复；缺卷／非 Bound／UID 变化／Pod 仍运行；重复和并发提交；旧修订及另一个活动会话；配额不足；每阶段进程中断或 K8s 回执丢失；新建失败与精确补偿；旧 Runner 迟到连接；历史 CLI 不自动重跑；正常释放。自动回归之外，在原失败 workbench QA 实际核对恢复前后 HEAD、原文件摘要、PVC UID、新旧 Pod 和 Runner 身份，再恢复预览及手动启动一个 OpenCode。

I15 的逐 CLI Pod 隔离仍单独实现和验收；恢复后能使用旧文件不等于已解决新增 CLI 影响其他窗口的问题。
