# RFC-030：能力市场的紧凑目录与发现体验

状态：In Progress · 2026-09-27 · 作者已批准实施，包含 Beta 布局稿。

## 背景与现状

作者要求重写能力市场，解决信息密度低、没有项目负责人、重复无效信息多和难以找到能力的问题。

源码核对：

- `MarketAppCard.tsx` 未渲染已有的 `MarketAppDto.owner.name`；后端已经提供负责人，无须新建负责人字段。
- `Market.module.css` 使用最小 290px 自适应卡片、44px 图标、纵向大间距与简介最小高度；“打开应用”另占一行，空简介也缺乏紧凑布局。
- `MarketPage.tsx` 只有名称／用途搜索及前后翻页，查询只保存在组件状态，不能分享检索条件。
- 项目层 SQL 先裁定可见范围，再查名称与简介、按 ID 分页；能力层再聚合正式／试用／维护状态。不能只对浏览器当前 20 条做过滤并称为全市场检索。
- 正式版、成员 Beta、维护放行、未知状态与读取失败撤下旧投影已有产品约束，必须保留。

## 调研与取舍

查阅日期：2026-09-27。来源是官方产品说明，未登录供应商控制台，不能当作供应商当前页面像素测量。

| 来源 | 有依据的发现方式 | 本次采用 |
| --- | --- | --- |
| [AWS Serverless Application Repository](https://docs.aws.amazon.com/cli/latest/reference/serverlessrepo/) | 按名称、发布者、事件源搜索，以类别关键词发现应用 | 名称／用途关键词、可见负责人、一键看同一负责人的应用 |
| [AWS 应用消费流程](https://docs.aws.amazon.com/serverlessrepo/latest/devguide/serverlessrepo-how-to-consume.html) | 先浏览搜索，再查看权限、能力及说明，最后部署 | 列表先帮助判断用途与可用性，长说明按需看；CrewStation 主动作仍直接打开应用 |
| [阿里云函数计算应用中心](https://www.alibabacloud.com/help/en/fc/manage-applications) | 按业务场景选择应用，卡片可进入详情 | 用途简介优先于运行参数；不把部署配置塞进市场 |

紧凑行目录是本次针对 CrewStation 的设计判断，不是声称这些厂商都采用表格。现有数据没有分类、评分、调用热度或最近使用记录，不造假指标，也不按图标猜分类。

## 目标与页面方案

1. 默认以紧凑目录展示。桌面每行四列：**能力（名称＋用途）／项目负责人／状态／操作**；图标缩为 28–32px。普通行目标 64–80px，异常／长内容按需增高。
2. 搜索栏与筛选摘要各不超过一行常规高度。删除标题下“点击卡片即可开始使用”、搜索字数提示、重复打开提示及固定简介空白。
3. 名称与用途支持多关键词匹配，不区分英文大小写；空格分词后词间 AND、每词在名称或用途中匹配。搜索覆盖全部有权看到的应用。
4. 负责人始终可见。点击名字使用 `ownerId` 筛选其应用，筛选以具名条件显示并可单独清除。先提供这条可靠路径，不加全企业人员选择器；自由输入搜索本期仍明确标为“名称或用途”，不声称支持人名搜索。
5. 名称直接打开应用；右侧另有明确“打开”按钮，键盘与触屏均可发现。原整卡点击改为明确链接，避免选字或点负责人误跳转。
6. 正常状态简短展示“可使用”，异常显示“维护中／暂不可用／状态待确认”，Beta 明确标识。维护原因、预计恢复时间保留在对应条目，Beta 共用业务数据警告紧邻试用动作，不能作为无效信息删掉。
7. 列表简介最多两行；需要读完整简介时通过“详情”进入共享 `Dialog`，不在列表末尾追加。详情只含用途、负责人、当前状态与入口，不引入项目管理入口。
8. 当前页计数写“本页 N 项”，没有权威总量就不显示全市场总数。保留上一页／下一页，并提供每页 20／50 项。
9. 320／390px 时每条重排为名称用途在上、负责人与状态在中、动作在下；不用缩小字体或横向滚动解决拥挤。

## 能力影响

没有关闭应用使用、成员试用、访问申请或维护放行能力。整卡热区变成名称和显式动作；完整简介由详情弹窗补足。市场仍是应用使用入口，API 接口目录、算力、运行镜像继续各归现有入口。

## 验收标准

- MD-01：1440×900、100% 缩放、至少 30 条普通夹具时首屏完整显示至少 8 条，每条可直接读到用途、负责人、状态和动作；同时保留旧版同条件截图作比较。
- MD-02：按名称、用途、多关键词查找；目标在原第 2 页时仍可命中，负责人筛选同样覆盖全部授权目录。
- MD-03：负责人筛选、搜索、每页数量与翻页正确组合，改条件回第一页；条件可分享，浏览器前后退可还原。
- MD-04：长列表末行详情在统一弹窗内，关闭后查询、分页、滚动保留，焦点回原按钮；Esc 只关闭最上层。
- MD-05：普通使用者、成员与管理员仍遵守现有可见范围；正式／Beta／维护放行与禁止／未知状态均不改变入口判定。
- MD-06：后台重读在途保留当前 DOM 和滚动；失败或撤权立即移除过期授权投影；空页有下一页时不可误报“没有匹配”。
- MD-07：320／390／1024／1440 宽度、中英文、明暗主题、键盘均无页面横向溢出，无依赖 hover 的唯一信息入口。
- MD-08：实际浏览器验证、必要的模块与工作台回归、静态检查及生产构建通过；部署验收与夹具验收分别记录。
