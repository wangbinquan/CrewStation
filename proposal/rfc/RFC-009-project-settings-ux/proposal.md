## 1. 问题与依据

当前设置按实现模块分成成员、应用可见性、配置与密钥、开发资源、仓库、生命周期六个页签，默认打开成员。
开发资源再分三层内容，约定、地址、数据、配额、MCP、业务任务接口堆在长页中。
用户必须先了解平台模块，才能判断自己是在读文档、修改平台配置，还是应该回到代码中修改。

实机和源码证据见 [audit.md](./audit.md)。关键事实：

- `ProjectSettingsPage.tsx:17–40` 同时装配可编辑配置、只读仓库和开发资料。
- `ConfigEnvPanel.tsx:55–100` 默认同时铺开列表、写入表单与版本历史。
- `RepositoryCard.tsx:20–40` 只有读取和打开仓库，没有更换仓库或修改默认分支动作。
- `SubscriptionsCard.tsx:11–17` 的订阅来自 Manifest，发布时登记，并非设置页可编辑的对象。
- `ProjectLifecycleCard.tsx:14–35` 仅管理员能归档；开发者在日常设置中看到的主要是说明。

以上路径均相对 `apps/console/src/`，完整链接和核对时间见审查表。

## 2. 目标与范围

**已明确要求**：直观、简化；区分给开发者看的信息和给开发者配置的内容。

**建议方案**：

1. 用户进入设置就能知道可以改什么、当前能否改、保存影响哪里。
2. 日常首屏只呈现当前设置和明确动作，表单在点击新增／修改之后出现。
3. 查看资料、调用 API、了解事件接入有独立入口。
4. 所有既有能力、角色边界、草稿保护和可追溯错误保留。

本 RFC 只重组前端入口、信息密度与交互，不增加后端配置项。不加入项目重命名、仓库迁移、编辑套餐、直接编辑订阅、恢复归档等当前没有的产品能力。
开发工作台的六个视图与连接恢复归 RFC-008，本 RFC 只使用它的代码／数据访问深链接。

## 3. 建议方案

### 3.1 两个清楚的入口

项目左栏新增 **开发资源**，顺序为：概览／开发／开发资源／发布与上线／运行与诊断／项目设置。
原设置中的只读资料迁入开发资源，旧地址继续定位到同一内容。

| 入口 | 回答的问题 | 可以做的事 |
|---|---|---|
| 项目设置 | 我想改变这个项目的什么？ | 改运行参数、应用展示、成员；管理员归档 |
| 开发资源 | 这个项目能用什么，代码怎么接入？ | 查阅、复制、申请 API、试调；跳转到实际修改位置 |

开发资源里的申请和试调是明确的业务动作；不会把整页一概标成“只读”。
每项内容标明来源：**在此配置／在代码中声明／由平台提供**。只在有歧义的位置显示来源，不给每个数值堆标签。

作者已于 2026-09-20 明确批准实施与提交上库，采用独立入口的方案进入生产实现。

### 3.2 设置只保留四组

默认打开「环境变量 → 开发」，每组标题下只有一句用途说明。桌面用窄分组导航＋一个内容区；手机用有标签的分组选择器。

| 分组 | 首屏内容与主动作 | 谁维护 |
|---|---|---|
| 环境变量 | 开发／生产切换，变量列表；「新增变量」，每行「修改」或「更新密钥」 | 开发：开发者、负责人、管理员；生产：负责人、管理员 |
| 应用展示 | 用途、图标、市场可见范围的当前摘要；分别「编辑展示资料」「修改可见范围」 | 负责人、管理员 |
| 成员与角色 | 成员姓名与角色；「添加成员」，每行按已有规则修改／移除 | 负责人、管理员；转移负责人仅管理员 |
| 高级 | 项目状态与归档入口、后果说明 | 归档仅管理员；其他人可查看状态及办理角色 |

“环境变量”包含普通配置与密钥；原能力不变，仅采用开发者熟悉的入口文案。
不把只读字段画成禁用输入框；只读摘要后明确「由项目负责人维护」。
普通开发者进入生产组仍可查看已有可读信息，不出现一组不能操作的保存按钮。
测试者仍只见试用入口，普通应用使用者仍不进入项目工作台。
管理空间中的接入容器不出现应用展示组，其余结构一致。

### 3.3 环境变量：先找变量，再编辑

- 只用「开发」「生产」两个环境标签；生产紧邻说明「正式与待验证版本共用」。
- 列表显示名称、类型、普通值／“已设置，无法读取”的密钥状态，以及具名操作。
- 点击新增或某行操作才展开同页编辑区；主按钮写明「保存到开发」或「保存到生产」。
- 编辑标题显示对象与环境；已存在名称保持可核对。新建同名键沿用现有覆盖语义，显式提示替换，不偷偷改成重命名接口。
- 所有约束在表单首次展开时可见；键名错误贴字段并聚焦。空字符串规则与旧值不可读规则保留。
- 当前组草稿切环境保留；切设置分组／离开页面沿用未保存确认，避免静默丢失。
- 保存成功显示真实版本及生效条件：开发在新任务容器创建时注入；生产在后续发布时采用。都不宣称现有进程已更新。
- 保存时间、修改人、历史版本放在行详情／「版本记录」中。生产配置和两槽发布快照的差异仍显示摘要，需要时展开对照。
- 读取失败有就地重试；已有输入保留。加载失败不能显示成“没有变量”。

> **2026-09-23 修订（作者当面裁定，直接修改，不另立 RFC）。** 「版本记录」与「需要时展开对照」改为直接展示：两张变量卡页脚的「版本历史」不再折叠，生产组的「生产配置与部署版本」卡直接列出两槽发布记录的配置快照对照。编辑区仍按需展开。

### 3.4 应用展示、成员和高级

应用展示把市场用途、图标与可见范围收在一处，但两个保存动作仍各自独立。先看摘要，再编辑；保存其中一项不清另一项草稿。
可见范围继续支持项目成员／全部登录用户／项目成员与指定用户；“检查谁能看到”按需展开。
可见范围只改变市场展示的语义保留，不能用“谁能使用”误导为业务权限配置。

成员页先看人和角色，新增时再呈现账号查找。高级用户 ID／管理员目录保留在“其他选择方式”。
已有成员的角色变更明确显示原角色和新角色，负责人转移仍由管理员确认。

高级页不用“生命周期”这一抽象词。归档前说明路由异步移除、代码与数据保留、已有进程不自动清理、当前没有恢复入口。
项目／服务 ID、命名空间等迁到开发资源 → 项目与仓库的技术详情。

> **2026-09-23 修订（作者当面裁定，直接修改，不另立 RFC）。** 「检查谁能看到」不再按需展开：应用展示组直接有第三张卡「检查保存后的效果」，只对能配置的人显示；两张设置卡仍先看摘要、再编辑。项目／服务 ID 与命名空间现在是项目设置 → 项目信息最上面直接展示的「项目信息」卡（见 RFC-020 proposal §4.6 同日修订）。

### 3.5 开发资源也要收敛

| 主题 | 主要内容 | 下一步 |
|---|---|---|
| API 接口（默认） | 可用操作、授权、请求记录、详情与 Swagger | 查看文档／申请调用／在当前会话试调 |
| 事件 | 事件类型、当前已发布订阅、处理路径 | 打开 `crewstation.yaml`；查看投递诊断 |
| 数据与存储 | 开发／生产的数据资源、变量名与状态 | 前往开发 → 数据访问；按需查看规格 |
| 项目与仓库 | 仓库、应用地址、资源额度和套餐 | 打开仓库／复制地址；技术详情按需展开 |
| 平台接入 | 身份转发、环境变量及路径约定、MCP、业务子任务接口 | 按主题查阅／复制；应用自定义变量指向项目设置 |

避免再做一页默认展开的所有能力清单。资料入口不依赖开发会话在线；只有 API 试调按现有条件依赖会话。
平台提供的值采用文字和复制按钮；代码声明项明确文件和生效方式，不放没有真实接口支持的编辑按钮。

## 4. 完整使用路径

1. **开发者改参数**：项目设置默认进入开发变量 → 找到变量 → 修改 → 保存 → 看版本和生效说明。
2. **负责人改生产参数**：环境切换为生产 → 看影响说明 → 修改 → 保存 → 前往发布与上线。保存不自动触发发布。
3. **负责人邀请协作者**：成员与角色 → 添加成员 → 精确查找账号 → 选角色 → 保存，回到成员列表。
4. **开发者接入事件**：开发资源 → 事件 → 看到“代码声明，发布后生效” → 打开 Manifest → 发布；投递问题跳运行与诊断。
5. **开发者查接口**：开发资源 → API → 文档／授权 → 选择当前会话试调；HTTP 状态、耗时、操作键、任务及 trace 可查看。
6. **用户找错地方**：环境变量页的轻量链接「查看平台自动提供的变量」直达接入资料；资料页「配置应用变量」回到正确环境。

## 5. 能力影响清单

没有关闭能力；入口和展开方式发生变化，迁移如下。

| 现有能力 | 新位置／处理 | 保留项 |
|---|---|---|
| 六个设置页签 | 四组设置＋独立开发资源 | 旧链接兼容；无数据迁移 |
| 开发／生产配置、Secret、删除、版本历史 | 环境变量 | 两组权限、空值、覆盖、只写密钥、生效条件、操作回执 |
| 应用可见性与展示资料 | 应用展示 | 三种范围、指定用户、检查效果、独立修订与草稿 |
| 成员与测试者、负责人转移 | 成员与角色 | 账号查找、高级 ID、管理员目录、角色限制 |
| 仓库 | 开发资源 → 项目与仓库 | URL、默认分支、状态、失败原因 |
| 服务身份、域名、配额、套餐 | 开发资源 → 项目与仓库 | 可复制值、未知态；平台管理边界 |
| 数据资源 | 开发资源 → 数据与存储 | 开发／生产、资源状态、变量名、数据访问路径 |
| API 目录、授权申请／撤销、Swagger、试调 | 开发资源 → API 接口 | 操作上下文、草稿与真实结果 |
| 事件类型与订阅 | 开发资源 → 事件 | 代码声明语义、选中订阅、投递诊断链接 |
| 集成约定、配置键、MCP、业务子任务 API | 开发资源 → 平台接入 | 当前实际身份转发、所有既有段落与复制能力 |
| 归档及状态 | 项目设置 → 高级 | 原角色、状态限制、后果与错误；无伪造恢复 |
| 管理空间对应入口 | 相同布局，去掉应用展示 | 不转到租户空间；管理目录与申请链接保留 |
