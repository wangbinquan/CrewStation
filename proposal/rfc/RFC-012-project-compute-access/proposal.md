# RFC-012｜项目算力授权

状态：Done · 2026-09-20。T1–T6 与 PC-01…PC-12 已完成；功能提交 `5fb7e6c`、共享接线 `b7fb3e5`／`b3d8d0e` 均已上库，包含完整功能的 `a694465` 六项 CI 全部成功。逐项验收、部署与发布证据见 [实施与验证](./plan.md)。

作者在讨论“允许使用的 Agent 档位、项目默认档位、开发容器资源套餐”后明确要求“实现该功能”，并补充“默认可见和默认不可见，默认档位必须默认可见”，据此实施。

## 目标与范围

管理员从项目管理为不同项目分配算力。开发 CLI、历史对话 Agent、业务 Agent 共用一份项目允许清单；项目默认档位必须在清单内且支持业务协议。开发工作区套餐单独配置，不改变 Agent 档位绑定的套餐。项目负责人及开发者只能使用授权，不能修改授权。

## 兼容与影响

作者进一步明确“默认可见和默认不可见，默认档位必须默认可见”。每个档位有 defaultVisible；平台默认档位强制为 true，设默认时同时打开可见性，禁止隐藏当前默认。存量档位迁移为默认可见。未配置项目继承默认可见目录与全局默认档位；配置为限制模式后，只能使用清单内的档位，空清单表示禁止启动 Agent。默认不可见的档位只有经项目显式授权才能显示和启动。

限制模式下不回退到全局默认，CLI、headless、业务子任务、发布引用和项目能力说明统一使用项目策略。撤销只阻止后续受理；已受理实例与固定修订保留。默认或已授权档位被删后，配置保留名称并明确报错，不自动换档。开发套餐变化在新开／恢复开发容器时生效，不原地改动运行中的 Pod。

## 能力影响清单

| 形态 | 变化 |
|---|---|
| 未配置项目 | 存量档位迁移后保持可见；之后随平台的默认可见范围及默认档位变化 |
| 已限制项目 | 未授权档位无法新启动；手写名称、default 和旧页面选择都不能绕过 |
| 发布 | 引用未授权档位时失败并保留原因 |
| 开发恢复 | 配置了开发套餐后，只能按该套餐恢复，不能另选未分配的套餐 |
| 运行中 Agent | 不终止，消息与输出仍可使用 |
