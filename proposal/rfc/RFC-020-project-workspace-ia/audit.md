## 3. 问题与证据

### 3.1 「上手不知道要操作什么」

| 现象 | 证据 |
|---|---|
| 左栏六项平铺，没有先后语义；「开发资源」（资料页）插在「开发」与「发布与上线」两个动作之间 | `ProjectNavSection.tsx:16–23` |
| 概览首屏之下全是别处已有的内容：「当前开发」卡重复页头主动作与版本卡旁的会话状态，「运行健康」卡重复版本卡角标与运行与诊断，「最近发布活动」重复发布历史，「项目快捷入口」四个链接就是左栏的四个入口 | `ProjectOverviewPage.tsx:59–72`；`ProjectQuickLinks.tsx:8–13` |
| 同一事实两套组件：概览的 `DeploymentCard` 与发布页的 `DeployedVersionCard` 各画一次正式／待验证版本，文案与角标不同（「就绪」vs「部署就绪」） | `features/projects/components/summary/DeploymentCard.tsx`、`features/release/components/DeployedVersionCard.tsx` |
| 「读取于 …」时间戳在概览出现四次（两张版本卡、当前开发、运行健康），刷新按钮每页每卡各一个：刷新概览／刷新部署版本／刷新配置／刷新成员／刷新告警／刷新订阅／刷新访问记录／重新检查 | 各 feature `i18n/zh-CN.ts` 共 9 处 `refresh` 文案 |

### 3.2 「页签堆叠、没有逻辑」

| 现象 | 证据 |
|---|---|
| 开发页在终端之上叠四条控制行：标题行（状态、分支、准备发布）→ 6 个功能页签 → 工作区页签行（工作区 1 · 1｜＋ 工作区｜▸ 已启动 5）→ 工具行（算力档位、创建、▸ 高级、横排／纵排／网格／均分／并排预览、▸ 工作区设置）；下方还有版本对比条与页脚 | `DevSessionWorkbench.tsx:77–83`、`NativeWorkspace.tsx:73–96`、`NativeWorkspaceTabs.tsx:18–30`、`NativeToolbar.tsx:33–45` |
| 「变更」页签内再嵌 4 个页签：三层页签 | 实机 `?view=changes`；`ComparisonDetailsView.tsx` |
| 三种二级导航形态并存：开发、运行与诊断用横向页签；开发资源、项目设置用左侧分组导航；概览、发布与上线没有二级 | §1 表 |
| 运行与诊断的 6 个页签里，「健康状态」只有两张小卡，「部署与运行形态」的图已含每个 Pod 的就绪状态，两者回答同一个问题；「调用链回放」进入后是一个空的 Trace ID 输入框 | `HealthCards.tsx:26–58`、`TopologyPage.tsx`、`TracePage.tsx:19–21` |
| 个人布局里记住的 `view` 与 URL 竞争：地址栏是 `/dev-session`，页面打开的却是上次留下的「变更」 | 实机 1024 宽第一次打开；`NativeWorkspace.tsx:44–46` 以 `layout.view` 兜底 |

## 4. 已经做对、要保留的

- 概览的「下一步」横幅与随状态变化的主动作（继续开发／处理 v0.1.3 发布问题）：`ProjectNextStepBanner.tsx`、`ProjectSummaryActions.tsx`。
- 开发页的故障引导（`ConnectionGuide`）、保卷恢复、逐 CLI 状态、个人工作区布局（RFC-008）。
- 发布准备三步与来源固定 SHA、上线／回退的快照确认（RFC-003 §2.4）。
- 项目设置四组、按需展开编辑、草稿保护（RFC-009）。
- 形态图三处入口（RFC-019）。
- 旧地址一律 `replace` 重定向、参数保留（`features/*/routes.ts`）。
- 1280／1024／390／320 无整页横向溢出（本轮实测 1440 与 1024 全部 `overflow=0`，控制台零错误）。

## 5. 改版判据

1. 左栏顺序读出来就是数字人的生命周期；每个入口回答一个问题，入口之间不重复内容。
2. 二级导航只有一种形态；任何页面最多两层导航。
3. 开发时的工具（预览、代码、变更、数据、参考、会话）不替换终端，在旁边打开。
4. 一个主题一个家：数据、事件、地址与仓库、健康各只在一处完整呈现，别处只放一行链接。
5. 名称优先，36 位 ID 不作表格列；刷新每页一处。
6. 不删任何能力；旧地址继续可用（proposal §7）。
