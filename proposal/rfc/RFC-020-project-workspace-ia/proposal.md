# RFC-020｜项目工作台信息架构重构：按生命周期组织入口、统一二级导航、开发工作区改为工具面板

> 状态：Done · 2026-09-23 · 作者裁定 D1 (a)、D2 (b)、D3 (b)、D4 (a)、D5 (a)、D7 (a)，D6 随 D2 成立，并批准「按 plan T3–T10 进入实现并提交上库」；T3–T10 已完成并实机验收（[acceptance.md](./acceptance.md)）。

## 1. 现状一句话

一个项目里有 6 个左栏入口、27 个二级去处、三种二级导航形态（横向页签、左侧分组导航、没有），开发页在终端上方叠四条控制行、局部达到三层页签；同一件事（版本、健康、数据、事件、地址）分散在两到三处各放一半。
逐页元素、到达步数与源码位置见 [audit.md](./audit.md) §1–§3。

## 2. 三句反馈对应的根因

| 作者的话 | 根因 | 证据（audit） |
|---|---|---|
| 上手不知道要操作什么 | 左栏六项平铺、没有先后语义，「开发资源」这份资料页插在「开发」与「发布」两个动作之间；概览首屏之下的四段全是别处已有内容（当前开发、运行健康、最近发布活动、项目快捷入口），把唯一的主动作稀释掉 | §3.1 |
| 页签堆叠、没有逻辑 | 二级导航每页各选一种形态；开发页四条控制行叠在终端上，「变更」里再嵌一层页签；运行与诊断六个页签里有两个回答同一个问题、一个是空输入框 | §3.2 |
| 需要的功能不在手边 | 开发时的预览／代码／变更是整页替换终端的页签；数据、事件、地址各拆在两个入口里；会话日志要离开开发页；管理链接混进租户页 | §3.3 |

## 3. 目标与非目标

**目标**

1. 进入项目十秒内知道：现在什么状态、下一步点哪里——概览一屏说完。
2. 左栏顺序就是数字人的生命周期：做 → 验 → 上线 → 运行 → 设置；每个入口回答一个问题，入口之间不重复内容。
3. 二级导航形态收敛：分段页面里，运行与诊断用横向页签、项目设置用左侧分组导航（作者裁定 D3），其余页面没有二级；任何页面最多两层导航。
4. 开发时的工具（预览、代码、变更、数据、参考、会话）在终端旁边打开，不替换终端；需要时可放大到整页。
5. 一个主题一个家：数据、事件、地址与仓库、健康各只在一处完整呈现，别处只放一行链接。
6. 名称优先、ID 进技术详情；每页只有一处刷新。

**非目标**

- 不改后端接口与权限判定（唯一契约改动是个人工作区布局多一个可选字段，design §5）；不改 URL 路径段，只增减 search 参数；旧地址继续 `replace` 重定向。
- 不改开发会话的连接、恢复与 CLI 生命周期（RFC-008）、发布与切流语义（RFC-003 §2.4）、设置四组的编辑规则（RFC-009）、形态图内容（RFC-019）。
- 不做移动端专门设计；390／320 继续沿用「单栏、无横向溢出」的既有规则。
- 不删除任何能力；迁移清单见 §7。

## 4. 新的信息架构

### 4.1 左栏：生命周期顺序

```text
← 项目开发
演示数字人
demo · 数字人

概览            现在做到哪，下一步做什么
开发            改好这个数字人（终端＋工具面板；参考资料在面板里）
发布与上线      哪一版在试用，哪一版在服务
运行与诊断      哪里出问题，从哪里恢复
项目设置        谁参与，应用用什么配置，项目是什么
```

与现状的差别（作者 2026-09-23 裁定 D2）：「开发资源」不再是左栏入口。它的五个主题各归其家：API 接口、事件、平台接入进开发页的「参考」面板——面板放大后就是整页宽度，没有开发会话时也能打开；「数据与存储」进开发页的数据面板；「项目与仓库」进项目设置的「项目信息」组（§4.3、§4.7、§4.8）。
测试者仍只有「版本试用」一项；管理空间里的接入容器沿用同一顺序，只是没有「应用展示」组。

### 4.2 概览：一屏

```text
演示数字人   demo · 数字人 · 已开通 · 负责人 CrewStation Admin              [继续开发]
仓库 crewstation/demo ↗ · demo.cs.localhost ↗ · preview.demo.cs.localhost ↗       读取于 00:10 ↻
┌ ℹ v0.1.2 已发布，等待验证 —— 打开试用验证，再由负责人正式上线。            查看版本 → ┐
┌ 正式版本 ─────────────┐ ┌ 待验证版本 ────────────┐ ┌ 开发会话 ────────────────┐
│ v0.1.4   健康 · 1/1 就绪 │ │ v0.1.2   健康 · 1/1 就绪 │ │ 运行中 · main · 1 个 CLI  │
│ 9fd01fc · 9月12日 18:54 │ │ 3975d02 · 9月11日 23:55 │ │ 待上线 0 · 未提交 0        │
│ [打开正式应用]           │ │ [打开试用] [上线 v0.1.2…] │ │ [继续开发]                │
└────────────────────────┘ └────────────────────────┘ └─────────────────────────┘
┌ 部署与运行形态 ────────────────────────────────────────────── 查看完整形态 → ┐
│ （RFC-019 横带汇总，不变）                                                        │
┌ 最近动态 ─────────────────────────────────────────────────────── 全部记录 → ┐
│ 9月22日 20:03  dev-admin 把 v0.1.2 切为正式版本                                   │
│ 9月12日 18:54  v0.1.4 发布就绪 · 正式                                             │
│ …（发布与切流合并，最近 5 条）                                                    │
```

- 页头第二行给出仓库与两个地址，都是外链；这是「地址在哪」的家之一（另一处是项目设置 → 项目信息）。
- 第三张卡承接原「当前开发」卡：会话状态、分支、CLI 数、待上线与未提交数（来自现有摘要与版本比较）。
- 健康以角标画在版本卡上；异常时横幅承担「需要处理」（原「需要关注」卡）。
- 删去「当前开发」「运行健康」「项目快捷入口」三张卡与四个「读取于」；刷新只在页头一处。
- 「下一步」横幅与主动作规则不变（RFC-003 design §2.2）；新增一种横幅：负责人有待批准的数据访问申请。
- 负责人的「上线 v0.1.2…」只是进入发布页并展开检查，确认仍在发布页完成。

### 4.3 开发：终端＋工具面板

```text
开发会话  ● 已连接 · main                                    [⧉ 预览] [准备发布]
┌────────────────────────────────────────────┬────────────────────────────────┐
│ 工作区 1 · 2 │ 工作区 2 · 1 │ ＋  [＋ CLI ▾] [布局 ▾] [⋯] │ 预览 代码 变更 数据 参考 会话  ⤢ × │
│ ┌──────────────────┐ ┌──────────────────┐ │                                │
│ │ CLI fcb070 ● 运行中 │ │ CLI a91c33 ● 待处理 │ │  （面板内容，可拖分隔线）        │
│ │                  │ │                  │ │                                │
│ └──────────────────┘ └──────────────────┘ │                                │
├────────────────────────────────────────────┴────────────────────────────────┤
│ main @ 9fd01fc · 生产 v0.1.4 @ 9fd01fc · 提交一致 · 未提交 0 · 未推送 0      重新检查 │
└─────────────────────────────────────────────────────────────────────────────┘
```

- **一条工具行**取代现在的三条：左边是工作区页签与「＋」；右边「＋ CLI ▾」是拆分按钮（主键按记住的档位与权限创建，箭头展开档位与权限），「布局 ▾」收横排／纵排／网格／均分，「⋯」收重命名、关闭工作区与「已启动」名册。
- **工具面板**在右侧，六个页签：预览、代码、变更、数据、参考、会话。可拖宽（30%–60%）、可收起（×）、可放大到整个内容区（⤢，即今天的整页视图）。面板状态记进个人工作区布局，地址栏用 `view` 与新增的 `panel` 表达（design §2）。
- 「参考」是原开发资源三主题的家（API 接口、事件、平台接入）。在侧栏形态下显示紧凑列表：已授权的操作（可直接试调）、本项目订阅与事件类型、身份头与环境变量；放大后是整页宽度的完整内容：操作全表带筛选、选中行的文档／授权／申请／试调、折叠的 Swagger、可订阅的事件类型全表、平台接入的四段说明。没有开发会话时也能打开（只有试调需要会话）。
- 「数据」是数据主题的家：连接变量名（原开发资源 → 数据与存储）＋绑定与申请（原数据访问页签）。
- 「会话」保留 RFC-008 的连接、恢复、历史对话与释放，并**内嵌**最近 200 行会话日志，不再跳到运行与诊断；完整日志仍有链接。
- 页头的「⧉ 预览」在新标签打开真实地址；连接状态芯片可点，直接打开「会话」面板。
- 底部状态条是现有的紧凑版本比较；点它打开「变更」面板。
- 没有会话时：主区是现有的开会话表单，面板只有「参考」可用（放大后即原开发资源整页）。
- 1024 宽：面板默认收起，打开工具时占 45%；内容区窄于 800 时面板只有放大形态（等于今天）。

### 4.4 发布与上线：一页一条时间线

```text
发布与上线                                              [准备发布]      读取于 00:10 ↻
┌ 正式版本 v0.1.4 ── 9fd01fc · 1/1 · demo.cs.localhost [打开] ┐ ┌ 待验证版本 v0.1.2 ── 3975d02 · 1/1 · preview… [试用] [上线 v0.1.2…] ┐
两个版本共用生产数据；试用也可能写入生产数据。
（发布准备：行内三步卡，只在打开时出现，不变）
┌ 发布记录 ─────────────────────────────────────────────────────────────────┐
│ ● v0.1.4  就绪 · 正式        9fd01fc · main         9月12日 18:54   详情    │
│ ⇄ 9月22日 20:03  dev-admin 把 v0.1.2 切为正式版本 · 原因 —                     │
│ ● v0.1.3  已被替代            3975d02 · main         9月12日 00:13   详情    │
│ ✕ v0.1.1  失败 · 构建失败：Job has reached the specified backoff limit   日志 │
└──────────────────────────────────────────────────────────────────────────┘
▸ 标签（非平台标签）
```

- 上线／回退按钮放在待验证卡上（对象旁边），检查与确认流程不变。
- 发布历史与切流记录合并为一条按时间排序的记录，切流条目显示操作人名字与目标标签，不再显示两个 UUID；失败条目自带日志入口。

### 4.5 运行与诊断：横向页签，五个

作者裁定 D3 (b)：保留横向页签，只合并两个页签。

| 页签 | 内容 | 与现状 |
|---|---|---|
| 状态 | 两槽健康卡在上，形态全图在下 | 合并「健康状态」与「部署与运行形态」 |
| 日志 | 不变 | — |
| 告警与通知 | 不变 | — |
| 事件投递 | 不变；顶部一行「订阅 1 条 · 打开参考面板 → 事件」 | — |
| 调用链 | 不变；空态说明 trace_id 从投递与日志进入 | 名称去掉「回放」 |

### 4.6 项目设置：四组加「项目信息」

顺序：环境变量、应用展示、成员与角色、项目信息、高级。「项目信息」是只读定义列表：仓库（含打开）、两个地址、服务身份、配额与套餐、折叠的技术详情（项目／服务 ID、命名空间）。承接原开发资源 → 项目与仓库。默认组仍是环境变量 → 开发。

### 4.7 参考面板（原开发资源）

三段：API 接口、事件、平台接入，同一个面板在侧栏与放大两种形态下内容一致、密度不同。API 段放大后改为「表在前、详情在旁」：操作表带筛选，选中一行在右侧打开文档／授权／申请／试调，Swagger 收进折叠段；36 位 operationKey 移到详情。管理员的两个管理空间链接改为页脚一行「在管理空间处理开放策略与申请 →」。旧地址 `resources?section=api|events|guide` 重定向到放大的参考面板并保留 `proxy`／`operation`／`subscription`。

### 4.8 一个主题一个家

| 主题 | 家 | 其他地方只放什么 |
|---|---|---|
| 数据：资源、连接变量、绑定与申请 | 开发 → 数据面板 | 平台接入的环境变量清单只列变量名并链接过来 |
| 事件：类型与订阅 | 开发 → 参考面板 → 事件 | 事件投递页顶部一行链接 |
| 事件：投递、重试、死信 | 运行与诊断 → 事件投递 | 事件页顶部一行「最近投递」链接 |
| 地址与仓库 | 项目设置 → 项目信息；概览页头一行 | 版本卡上的域名保留 |
| 健康 | 运行与诊断 → 状态 | 概览版本卡角标；异常时横幅 |
| 日志 | 运行与诊断 → 日志 | 会话面板内嵌尾部；发布失败行、健康卡带筛选跳转 |
| 成员 | 项目设置 → 成员与角色 | 概览不再重复入口 |

## 5. 六条旅程

| 旅程 | 角色 | 路径（新） | 与现状的差别 |
|---|---|---|---|
| J1 首次接手 | 负责人 | 项目列表 → 概览（横幅「样例已可试用」、三张卡）→ 继续开发 → 选分支开始；面板「参考」立即可读 | 概览不再要滚四屏；地址在页头 |
| J2 日常开发 | 开发者 | 开发 → ＋ CLI → 输入 → 面板：预览并排 → 代码改 `crewstation.yaml` → 变更看待上线 → 准备发布 | 全程终端可见；日志在会话面板 |
| J3 发布到上线 | 开发者→负责人 | 准备发布（当前会话）→ 记录里看进度 → 待验证卡「试用」→ 负责人「上线 v0.1.2…」→ 确认 → 正式卡更新、记录多一条切换 | 上线按钮在对象上；记录有人名 |
| J4 处理故障 | 负责人 | 概览横幅「v0.1.3 发布失败」→ 记录失败行「日志」→ 日志（source=build）；或横幅「待验证版本不健康」→ 状态 → 查看日志 | 少一次「先找健康页签」 |
| J5 接入能力 | 开发者 | 开发 → 参考 → API：已授权列表、试调；不够 → 放大参考面板 → 全表里申请定向开放 →（管理员在管理空间审批）→ 参考里出现新授权 | 试调不离开终端；申请不换页面 |
| J6 维护 | 负责人 | 项目设置 → 环境变量（生产）→ 保存 → 发布与上线；成员 → 成员与角色；数据访问申请 → 概览横幅 → 开发 → 数据面板批准 | 批准入口从页签变成横幅直达 |

## 6. 交互与视觉规则

在 RFC-003 §6 七条之上追加：

1. **二级导航不再各自发明。** 项目设置用左侧分组导航（`SectionNavigation`），运行与诊断用横向页签（`Tabs`，作者裁定 D3）；横向页签之外只用于内容内部的开关（开发／生产、告警筛选、面板页签）。
2. **工具不替换主工作区。** 开发页的工具在面板里打开；放大是显式动作，收起后终端仍在。
3. **一个主题一个家**（§4.8）；别处只放一行带上下文的链接。
4. **名称优先。** 36 位 ID 不作表格列、不顶格；放技术详情并可复制。同一状态同一词：两处版本卡共用一个组件与一套文案。
5. **刷新一处。** 每页页头右侧「读取于 hh:mm ↻」；卡片不再各自带刷新按钮，轮询不变。
6. **横幅只说需要处理的事**：发布进行中／失败、待验证可上线、健康异常、待批准的数据访问；没有就不显示。

## 7. 能力影响清单

本方案不关闭任何能力，只改入口与摆放。若实现无法保持其中任何一项，按开发规则 §5.5 重新呈作者确认。

| 现有能力 | 新位置 | 旧地址处理 |
|---|---|---|
| 概览的当前开发／运行健康／最近发布活动／项目快捷入口 | 开发会话卡／版本卡角标与横幅／最近动态／页头链接与左栏 | 同地址 |
| 开发页六个整页视图（`view=cli\|preview\|code\|changes\|data\|session`）、`split` | 同名面板；`view` 含义不变，新增 `panel=side\|full` | 无 `panel` 的旧链接按 design §2 映射 |
| 工作区页签、布局、并排预览、已启动名册、高级权限 | 一条工具行内的页签、「布局 ▾」「＋ CLI ▾」「⋯」 | — |
