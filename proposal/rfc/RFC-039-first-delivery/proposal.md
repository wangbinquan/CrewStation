# RFC-039｜首次交付连续引导

> 状态：In Progress · 2026-10-14
> 批准依据：作者已在浏览器体验首次交付原型，并明确回复「好，按你设计的修改」。本三件套将已批准的交互设计落档，不另设重复批准。

## 1. 背景与目标

项目开通、开发会话、Agent、Git 提交、发布验证、正式切流和应用访问范围目前分属不同入口。新手需自行理解衔接关系；项目 active 不等于应用已上线。目标是从创建到可访问的正式应用始终给出当前状态、一个主要下一步和可恢复的失败入口。

## 2. 已批准范围

- 名称自动建议可编辑的地址标识；默认有界面模板和平台资源，保留高级选择。
- 创建成功进入独立项目交付页；刷新、离开后按真实事实继续，不以页面计时模拟成功。
- 首次交付展示创建、环境、开发预览、验证上线、交付进度；项目列表和概览给出一致的下一步。
- 简化开发入口，直接描述需求、使用默认算力启动开发助手、查看实际输出和开发预览；高级 CLI、文件、数据、资源与运维仍可达。
- 发布前列明未提交文件，经用户确认后保存 Git 提交，再沿用 RFC-038 构建、验证、上线、历史流程。
- 上线前明确项目成员／全部登录用户的访问范围；正式版本和访问规则确认后给出地址及身份预览。两档均须登录，不提供匿名公开。
- 环境读取失败、发布失败及配置缺失在原流程给出原因与恢复入口；普通用户可申请开发者角色，管理员处理后继续创建。

## 3. 能力与权限

不删除高级工作区、既有发布历史、版本回退、API-only 模板或原有成员权限。管理员代建接入容器仍使用已有入口。开发、验证、上线与权限管理继续分别接受后端授权；开发助手仅在用户启动制作／发送需求后使用资源。开发数据独立，待验证与正式继续共用生产数据。

## 4. 验收标准

| ID | 可观察结果 |
|---|---|
| FD-01 | 中文名称也有合法建议标识；手改后不再被名称覆盖；重复标识显示真实错误 |
| FD-02 | 创建后到独立交付页面，未知／失败不显示完成；返回列表后下一步一致 |
| FD-03 | 默认开发入口可提交需求并看到真实 Agent 输出和预览；现有高级工具可访问 |
| FD-04 | 确认 Git 文件后才能提交；会话、HEAD、内容变化或未知结果不得继续发布错误版本 |
| FD-05 | 沿用可恢复的五步发布与历史；未验证不能上线，非负责人不能切流 |
| FD-06 | 上线确认可设置访问范围；失败如实展示，最终地址／版本／范围来自真实读取 |
| FD-07 | 成员、非成员、未登录身份预览遵守当前访问规则及申请开关 |
| FD-08 | 普通用户申请、重复申请、管理员批准／拒绝及再次进入的状态均持久正确 |
| FD-09 | 统一弹窗、关闭回焦、长列表上下文、中英键、桌面与窄屏通过 |

## 5. 交付边界

批准的是产品实现；本地代码验证、准确提交 CI、共享平台部署与真实应用上线分别记录。不得把原型中的示例数据、定时进度或验收夹具作为生产成功依据。
