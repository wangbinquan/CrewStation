# RFC-037｜项目创建说明与管理员彻底删除

> 状态：In Progress · 2026-09-30 · 作者已批准完整 RFC 实施、提交远端、本机部署与自主功能验证；创建与完整删除均在实施范围内。
> 配套：[技术设计](./design.md) · [实施计划](./plan.md) · [弹窗交互稿](./prototype/README.md)

## 1. 已明确要求

作者先提出简化项目创建，并要求管理员可以彻底删除项目、回收该项目的全部资源，删除必须二次确认。核实字段用途后，作者进一步明确：

- 保留标识；在创建时写清它用于决定项目域名，并渲染最终域名。
- 保留模板；写清模板的作用，让使用者知道自己选了什么。
- 优化新建界面的布局与外观，不依赖指导书，仅看界面就能理解并完成操作。
- **新建项目使用弹窗，不使用独立页面。**
- 管理员删除项目是不可恢复的完整清理，不能以归档或仅删除项目记录替代。

本 RFC 不再采用此前讨论的“自动生成标识、隐藏模板”建议。

## 3. 创建时的体验

项目列表上的“新建项目”直接打开既有 `FormDialog`。开发者自建与管理员代建都采用同一套清晰表单结构，不跳去独立创建页，不再把表单拆成三个来回跳转的步骤。关闭保存草稿、列表上下文与触发焦点；再打开继续填写；“清空”恢复初始值且不关窗。

弹窗按“项目与访问地址”“初始代码”组织。名称、域名标识和管理员的负责人选择是主要内容；资源设置作为次要的可选区域，默认值与效果始终可见。标题简洁，留白、字段对齐和层级复用工作台设计令牌；宽屏紧凑双列，窄屏单列，正文内部滚动，标题与操作条固定。

“标识”改为明确的“域名标识”，提示“用于决定项目访问域名，创建后不能修改”。字符格式、保留名与重复校验继续有效，但不能盖过用途说明。

输入合法标识后，在字段旁显示完整的“正式访问域名”和“待验证访问域名”，提交前始终可见。数据来自后端实际安装配置和已有域名规则，不从浏览器地址猜后缀，不写死本机域名。尚未创建的域名是预览文字，不能表现成可访问的应用链接；正式访问仍需完成开通与上线。

模板字段直接说明：“用于生成项目的初始代码和发布配置，创建后可继续开发修改。”选中后显示所选模板名称与已有的必配项；必配项缺失仍要明确提示。模板不是算力档位，也不代表已经配置模型、密钥或已经上线。

提交前用一句话交代下一步：“创建后平台会建立仓库并自动开通；先在待验证地址验收，再手动上线。”受理创建后在当前列表显示真实开通状态，进度查看使用弹窗或现有状态详情；不导航回独立新建页。

覆盖开发者自建、管理员代建，以及共用创建组件的接入容器页面。保留现有模板选择、资源配置、负责人规则与开通流程。

## 4. 删除旅程与范围（已批准）

管理员从项目管理列表或项目生命周期操作进入“删除项目”。适用于开通中、活动、开通失败和已归档项目；不要求用户先手工归档。

第一次确认前先显示项目名称、标识、负责人、域名、资源盘点与影响。第二次确认使用统一 `ConfirmDialog`，再次列出对象与不可恢复后果，输入 `delete` 才能点击“永久删除”。取消或 Esc 不受理删除；内层确认关闭时外层盘点保留。

受理后显示清理阶段、实际完成项、剩余项和阻塞原因；可关闭弹窗，后台持续执行。项目显示“删除中”，不再允许新建或恢复资源。失败后管理员可以继续原次清理；不能通过重试创建第二个删除操作。

| 清理对象 | 预期结果 |
|---|---|
| 正式与待验证服务、开发会话、业务任务、Agent、CLI、构建、迁移、镜像验证及辅助容器 | 停止工作并确认实际容器消失，释放项目占用的运行资源 |
| 工作盘、旧策略遗留卷、项目独占 PVC/PV 与对应存储 | 确认消费者停止，再回收原实例及其存储；不能只删 PVC 名称 |
| 开发／生产数据库、运行角色、临时访问角色 | 实际删除项目拥有的数据库与角色，回收相关凭据 |
| 开发／生产对象空间、文件、归档产物与未完成上传 | 排空读写后物理删除项目对象，结清该项目额度与预留 |
| 源码仓库、会话／构建 Git 凭据、项目独占镜像与构建产物 | 删除绑定的仓库及项目独占制品；不能把远端“标记删除”当成彻底完成 |
| 路由、服务身份、API 授权、事件登记／订阅／投递、配置与密钥 | 撤销项目访问和调用关系，清理归属记录、缓存与秘密材料 |
| 项目资源授权、申请、额度、成员、工作台状态及项目执行明细 | 各所属模块清除本项目记录，最后移除项目与服务记录 |
| 项目命名空间与附属策略／额度 | 在工作负载和存储清完后删除，确认原命名空间消失 |

按所有权清理：平台共用的算力、规格模板、存储后端、GitLab 组、镜像仓库服务、用户账户及其他项目资源不会随项目删除。项目借用它们的授权与占用必须释放。项目独占资源若仍被其他项目引用，先显示阻塞与引用方，处理这些引用后继续原次清理。

“彻底删除完成”要求项目独占资源的实际清理证明与各模块清理回执齐全。仅保留最小的管理员删除审计、删除墓碑与幂等回执，防止旧事件重建已删除项目；不保留源码、业务文件、配置值或可恢复的项目执行内容。共享平台监控与备份设施仍由平台管理，不因删除一个项目而整库销毁；其中项目归属的可清理数据须纳入盘点，无法确认清理边界时显示阻塞。

## 5. 能力影响清单（随 RFC 批准确认）

1. 创建继续保留可指定域名标识与可选择模板，增加用途说明与实际域名预览；不收缩这些能力。
2. 原有归档仍可保留源码和数据；新增的永久删除会销毁该项目全部独占资源，包括未推送代码、暂停任务工作盘、业务数据和归档产物。
3. 删除受理后项目不再允许创建、写入、发布、重跑开通、派发、恢复或重新声明资源；只开放管理员清理进度与继续清理。
4. 项目独占镜像等若有外部引用，删除会阻塞，不能连带删掉其他项目的引用或资源。接入项目注销提供的能力时，盘点须展示受影响调用方／订阅方。
5. 操作受理后不可撤销；部分失败只能继续清理。最小审计／墓碑保留，正常项目目录和市场中不保留“已删除项目”。

## 6. 验收标准

新建操作从列表打开共享 FormDialog，标识输入旁的最终域名与创建后 `ServiceDto` 完全一致，模板说明在选择前就可见；两类创建路径和接入组件、中英文、窄屏都覆盖。关闭／再打开保持草稿和列表位置，不再跳独立创建页面。

非管理员无法受理、继续或读取管理员删除材料。未完成二次确认时无删除写请求。长列表末行的盘点与确认位于共享弹窗，关闭恢复筛选、分页、滚动与触发焦点。

活动、开通中、失败、归档、暂停和遗留卷场景均可处理；重启、重复请求、迟到开通／派发、同名资源替换、外部系统失败和盘点不完整均有明确结果。专用项目实机验收要证明原 UID／OID／远端仓库 ID 对应的资源和数据确实回收，其他项目实例及共享资源保持原归属。

## I36：管理员修复旧资源归属（2026-10-06 已批准）

作者回复“按你推荐执行”，采用[方案 B](./legacy-recovery-options.md)。管理员在删除预检的统一弹窗中打开“确认旧资源归属”表单；逐条查看完整来源摘要、当前资源身份、影响与保留范围，再确认本项目清理或保留。界面说明“旧历史未恢复，此处确认的是现在的资源”。保存不开始删除；保存后重新预检，仍需原来的两次确认及输入 delete。

新基线标记 operator-confirmed/v1，未知原历史不改写。当前正文、引用、物理身份或原消费者变化使确认失效；共享、目标关联、未知活跃消费者和无法核实的条目继续阻断。作者追加批准严格保留外项目活跃记录：公开外项目归属及当前实际 UID、全部容器、标签、无目标/共享引用均核对后，管理员可逐项 retain 完整旧行和仍运行的资源；身份或来源变化后该决定失效。专用历史 release.registered 合同仅用于盘点 metadata，完整核对原形状、原迁移及公开 owner，不重投或执行。验收须覆盖权限、重放、变更失效、原 NULL 不改、其他项目资源保留及原专用项目全部22方和独立 after。

## I36-T13：确认先关闭项目准入，完整封存后才清理（2026-10-07）

原专用项目的22方完整计划已通过，但点击二次确认后的第二次六分钟盘点期间，后台持续新增已结束的回调，计划摘要因此失效；平台仍无删除操作。该修复属于已批准的彻底删除和未知结果恢复范围，不新增资源保留裁定。管理员确认未过期的完整计划后，原项目在同一事务进入 deleting；所有22方仍必须先封存和核验，之后才允许停止或清理。来源不完整、原实例或缓存选择变化继续阻断，需对原操作重新盘点和二次确认。

明确的确认拒绝必须可核对原请求后返回重新盘点；网络、未知服务端失败和读取失败继续保留原请求。完整回调原文、固定资源出生与全部外项目资源保护保持。详见[受理与封存修订](acceptance/admission-before-sealing.md)。
