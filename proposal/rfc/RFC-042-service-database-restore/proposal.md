# RFC-042：服务数据库空目标恢复与切换

> 状态：In Progress · 2026-10-16 · 作者明确“按推荐实现”，批准设计和交互原型，进入完整生产实现与用例编写。
> 来源：AW RFC-370 M3 的托管备份恢复要求；与 RFC-040 原生 Agent 材料分开。

## 问题与目标

`modules/data/application/serviceData.ts` 每服务每环境供给一次数据库，之后复用 ready 资源；`envFor` 总是返回该环境现有连接串。当前平台没有新建恢复目标及选择某个数据库世代的合同。AW 已有恢复器只允许同安装身份、同对象空间、原加密主密钥和经过摘要验证的完整备份写入空目标；不能直接用于线上非空库。

提供管理员发起的、可冷恢复的空库还原操作，先恢复并验证独立目标，再明确确认维护与切换。旧生产数据库及原备份继续保留。工作卷恢复属于业务程序，平台不把数据库恢复成功解释为旧任务可以自动续跑。

## 用户旅程

1. 在服务的数据资源页选择“从备份恢复”，打开独立恢复页。选择已发布、声明恢复命令的镜像版本，填写业务生成的不可变备份引用；平台不接受任意 SQL、DSN、命令或环境变量。
2. 展示服务、当前数据库世代、选定镜像、备份引用与影响。创建空目标并运行恢复 Job，此时原正式应用保持运行。
3. 查看恢复及应用只读检查的回执。备份创建之后的数据不会出现在恢复结果中；操作页一直显示这一时间边界。
4. 显式确认进入维护并切换。平台冻结旧执行权，验证旧业务写入者全部停止，启动绑定新数据库的候选槽，核实健康与数据库身份后切流并授予执行权。
5. 任一步失败保留原操作、目标及证据，沿同一操作重试；不自动清库或切回。关闭页面后可以从资源页重新进入，列表筛选保持。

[可交互设计原型](./prototype.html) 使用演示数据，不连接平台、不执行实际恢复。

## 权限与能力影响

- 第一版仅平台管理员操作，项目成员按原 view 权限查看状态；不新增角色。
- 普通发布仍使用当前生产世代，旧 API 和部署不改变。恢复是显式新操作。
- 恢复目标仅由平台命名和供给，凭据不出现在 DTO、URL、浏览器或日志中。
- 切换需要维护期；旧工作流任务暂停且保留，AW 恢复后保持手工续跑保护。当前用户要求保留运行的 AW，验收使用独立服务，未经具体切换授权不对正式 AW 执行恢复。
- 不支持旧单机导入、跨安装迁入、覆盖现有库、自动删除旧库、跨库事务或恢复后自动合并新旧数据。

## 验收

DBR-01：新库具有独立身份，旧库记录及凭据不变，重复请求不多建。
DBR-02：原操作在供给、Job、回执、切换各边界断线后冷恢复；未知状态不得重做不同目标。
DBR-03：非空目标、跨服务引用、变更镜像／备份／世代、过期确认、撤权全部拒绝。
DBR-04：还原失败原正式应用正常服务，失败目标与脱敏证据可查看。
DBR-05：切换前证明旧写入者停止；完成后数据库、槽位、路由与唯一执行权同属一代。
DBR-06：失回执、平台重启及维护中断均保持可恢复状态，不提前开放流量或重复生效。
DBR-07：数据库恢复后旧任务不自动启动；AW 原始对象引用和未完成执行 hold 保持，缺失工作卷在业务恢复页明确呈现。
DBR-08：真实 PostgreSQL、发布／资源台账回归、页面权限／确认／返回上下文、独立服务端到端全部完成；不停止或删除现有正式 AW。
