```sh

```

## 建议审核顺序

1. **项目负责人 / 资源拓扑**：查看 29 项资源的来源、当前状态和配额。顶部查看执行池、CPU 请求总量、对象占用；点击节点看全部属性与关联关系。
2. **领域与状态筛选**：可查看全部或单个领域；搜索／授权状态筛选淡化无关节点，保留连线背景。申请中包含已有资源的配额变更，因此三个状态计数不能直接相加。
3. **展开画布**：使用大画布集中查看拓扑，仍可打开节点详情和管理弹窗；关闭恢复原视图。
4. **资源申请**：点击「申请资源」，查看平台明确开放的服务规格、算力、运行镜像、对象存储、API、临时数据访问。填写理由并提交后，节点显示申请中；已有在途申请直接进入进度。
5. **配额申请**：点击执行并发／项目总量，修改目标值、核对差异并提交；原配额在生效前保持不变。关闭申请表单保留草稿，再打开恢复。
6. **平台管理员**：顶部切换后，原页面出现「分配资源」「调整配额」。从节点可直接修改 CPU、内存、Pod、PVC、并发、对象容量、传输上限、网关限流或项目套餐分配。
7. **审批**：申请详情中批准／驳回；数值额度支持修改批准上限并记录理由，保留原申请值。批准后先显示生效中，再更新有效配额。直接管理写入同一份变更记录。
8. **开发者**：可以看全景、配额和进度，没有提交资源／配额变更的入口。
9. **异常与手机**：演示场景可切换部分采集失败、审批冲突、生效失败；◐ 切换明暗。窄屏默认清单，节点和关系仍在统一详情弹窗中。

## 已检查的原型行为

- 独立 TypeScript 检查、目标目录 ESLint、Bun 静态构建通过；没有执行产品全量门禁，也没有把模拟结果当作后端或集群验收。
- 负责人资源申请、配额申请、撤回；管理员直接调额、批准、改值批准、驳回；已检查旧值 → 生效中 → 新值。
- 示例对象容量申请 100 GiB，管理员批准 80 GiB：原申请保留，最终有效值按 80 GiB 展示。
- 冲突保持原配置，进入「需重新核对」；生效失败保留旧值与重试入口。部分采集不可用显示「未知」，不显示 0。
- 开发者详情中没有写操作；这只是原型可见性检查，正式实现仍需服务端身份与权限用例。
- 二级弹窗 Esc 只关闭最上层；配额草稿重开恢复；焦点返回触发按钮。
- 390 × 844 下，29 项清单末行打开的弹窗位于 `x=16…374`、`y=35.125…808.875`；关闭前后页面滚动均为 `4049.5`，焦点回到末行按钮。整页无横向溢出。
- 桌面 1280 × 720、1440 × 960 以及窄屏检查；短屏压缩上方信息，拓扑内部滚动；明暗使用现有设计令牌。

## 复用与实现边界

直接复用当前 `TopologyDiagram`、`layoutTopology`、测量／缩放计算和 `Dialog`、`FormDialog`、`ConfirmationDialog`、`Tabs`、`DataTable` 等公共组件。`ResourceTopology.tsx` 是设计附件中的连线避障适配层：保留原节点、布局与焦点语义，只预演跨列连线绕开节点。正式实现应把可复用能力纳入既有拓扑布局器，不能复制另一套产品绘图器。

原型覆盖主旅程及典型资源，目录和限额为示例；后端授权、目录保密、审批版本冲突、资源供给、撤销授权、分页展开、双语和真实运行数据都需按 RFC 实施并验收。顶部身份、场景、主题和重置属于评审工具栏，不是产品用户流程。

与旧流程的兼容影响详见 [proposal §5](../proposal.md)：本稿按负责人申请、管理员审批统一 API 与生产数据访问，旧入口权限也需一起对齐。
