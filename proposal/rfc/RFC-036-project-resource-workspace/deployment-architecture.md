# RFC-036｜以部署架构组织项目资源（已批准实施）

日期：2026-10-01。作者要求：以「运行与诊断」的拓扑为基础，资源服务于部署架构。本轮交付可操作原型与设计修订，2026-10-15 作者明确要求按设计完成 RFC，正式实现已获批准。

## 1. 核心调整

项目资源页沿用部署对象、隔离边界和真实依赖，回答「这个服务／工作区／任务正在用什么、还能选择什么、额度够不够、如何申请或管理」。原按项目、命名空间、服务、存储、网络、平台能力生成的六类卡片退出主图；资源类型仍保留为权限列表的筛选维度。

主图按服务部署、开发工作区、业务任务、构建与迁移切换，避免把全部实例和历史作业挤进一个画布。每个视角保留自己的消费者、数据范围和方向。首屏展示聚合对象，点对象直接打开统一权限弹窗。

| 主图视角 | 主线 | 收进对象权限列表的内容 |
|---|---|---|
| 服务部署 | 正式／待验证入口 → 部署槽及副本 → 生产数据、API；事件 → 实际订阅的服务 | 服务规格、发布镜像与引用、共享存储配额、API 权限、事件订阅、对应申请 |
| 开发工作区 | 开发预览 → 工作区 → 关联 Agent；工作区／执行 → 真实挂载卷、开发库、平台工具 | 工作区规格和镜像、Agent 独立档位及镜像、共享并发、开发访问权限 |
| 业务任务 | 工作区 → 所属执行；两者 → 本任务专属卷 | 任务规格、Agent 档位、镜像、数据绑定和并发额度 |
| 构建与迁移 | 发布 → 构建／迁移作业；迁移 → 目标数据库 | 固定版本、镜像产物与仓库、作业资源规格、实际可管理动作 |

项目 API **已授权**与部署 **已声明调用**分开。仅可申请或已授权未使用的规格／能力不生成部署节点和使用连线，在对象的权限列表或全项目资源目录中查看；申请中作为目标资源的附加状态，不替换原来已经生效的权限或额度。

## 3. 命名空间与配额

- 顶部为项目命名空间及 CPU requests、内存 requests、Pod 数量、PVC 数量的共用额度。它是隔离和资源约束边界。
- 图中的命名空间边框只包住已知位于其中的运行对象及 PVC。外部数据库、对象空间、平台 API、仓库不因属于项目而进入此物理边界；逻辑访问入口也不冒充物理 Ingress 对象。
- 项目执行并发是另一种额度，工作区、Agent、归档等执行共享，服务槽不占用；放在项目公共能力入口，并在消费者的资源详情中引用同一 scope。
- 生产双槽连接同一个生产库、对象空间。界面复用相同资源 ID 与配额 scope；不会双算容量或生成两份授权。
- 当前生效值、已用／预留、申请目标、生效条件分别显示。CPU requests 不写成实时 CPU 使用率，PVC 容量不写成文件使用量，未知保持未知。

## 4. 展开与管理

点击部署对象打开统一 Dialog，默认显示资源与权限列表，另有运行对象和关系页签；副本／技术子对象仅在列表内展开。列表支持搜索与状态筛选，已有来源明确标为自动供给、平台默认或项目分配。项目公共入口包含仓库、环境配置、日志／指标及执行并发，不为每项增加主图节点。

负责人在列表中申请能力或调额，开发者仅查看，管理员在同一页直接分配／调整及批准／驳回。弹窗显示具体目标和作用范围、当前值、目标值、理由、影响和生效条件。已有待处理目标优先处理原申请，避免制造重复变更。关闭后保持筛选、滚动、焦点和草稿；嵌套 Esc 只关闭上层。

项目侧仅展示平台明确开放申请的目录项，管理员可查看完整管理目录。既有撤回、撤销授权、应用失败重试及修订冲突处理继续复用原资源中心动作，不因拓扑展示调整改变权限边界。

管理员决定 → 等待应用回执 → 生效。新增使用权生效后首先进入「已授权未使用」；选择发布规格、新建工作区或启动新执行时才采用。申请和审批不会自动重新部署、替换镜像或终止实例。

## 5. 实现和扩展约束（本次实施）

1. 抽取两页共用的部署事实组装及数据读取，保留资源中心授权／申请／计量快照作为叠加信息。不同来源的快照时间和完整性分别展示；来源失败不能变成「没有资源」。
2. 以台账 ID、物理 UID、serviceId、releaseId、taskId、spaceId 等建立桥接。权限目录以原 resourceId 和动作描述执行。不得靠名称、同 namespace 或同类资源猜消费者；无法定位的授权进入项目目录，运行对象进入待核对清单。
3. 聚合身份由部署槽、用途、环境及真实归属决定。同部署副本可折叠；跨任务、跨环境的存储和数据访问保留分项。实例增加时增加列表成员；部署对象过多时增加对象选择／分页，不回到全量平铺。
4. 同组内部边进入对象关系清单；组间边保留方向、关系类型、证据及原始成员关系。图中的授权数量是关联条目数，跨节点不相加。审批中拟新增权限不生成运行连线。
5. 空视角显示当前无运行对象及资源目录入口；孤立资源、保留存储、失败／未知对象需要可发现的清单入口。停用目录、历史申请、配额冲突、异常回执继续沿用既有资源中心处理。
6. 两端路由共用 feature 和事实模型，后端动作描述继续控制权限。保留单项稳定链接和原有配额范围；正式新增文案补齐中英文。
