# RFC-007｜开发环境 OAuth 2.0 一键换角色

> **In Progress · 2026-09-20**。作者直接要求“把 agent-workflow 的 dev 启动 OAuth 2.0 认证能力搬过来并适配到环境上，实现一键换角色登录”，该指令同时批准本 RFC 进入实施。

## 1. 背景

RFC-005 已提供生产可用的 OIDC／OAuth 2.0 登录，但本机逐角色验收仍要手工配置 IdP、建立账户、修改管理员标记和项目成员关系。`agent-workflow` 的 dev-auth 已证明一种更稳妥的做法：开发进程在产品外提供固定身份，通过产品原有授权码流程完成登录，不在产品内加入冒充接口。

## 2. 目标

- 本机安装后提供 `http://dev-auth.cs.localhost/`，一页切换平台管理员、项目开发者、preview 测试者和无项目成员。
- 开发者／测试者可选择一个未归档的数字人项目，页面记住上次选择；登录前只调整固定开发账号的成员关系。
- 身份提供方、用户、管理员标记和成员关系全部经 CrewStation 的公开 HTTP API 写入。
- 点击角色后走真实 discovery、授权码、PKCE、token、JWKS、userinfo、回调和 Cookie 会话链。
- 每次重启使用新的 issuer 路径、RSA 密钥和随机 client secret，避免复用旧端点与 JWKS 缓存。

## 3. 非目标

- 不在生产工作台加入换角色入口，不增加“以某用户身份登录”的产品 API。
- 不提供项目负责人一键切换；负责人转移会改变项目所有权，不适合作为无确认的开发快捷操作。
- 不把真实用户资料、运行时 client secret 或管理员口令写进仓库；仓库内的固定 subject／邮箱只属于 `.localhost` 开发身份。

## 4. 角色

| 入口 | 平台管理员 | 项目成员关系 | 默认落点 |
|---|---:|---|---|
| 平台管理员 | 是 | 不依赖项目 | `/admin` |
| 项目开发者 | 否 | 所选项目 `developer` | 所选项目开发页 |
| preview 测试者 | 否 | 所选项目 `tester` | 所选项目概览 |
| 普通成员 | 否 | 清除该固定账号的非负责人关系 | `/`（能力市场） |

## 5. 验收标准

1. 本机安装脚本幂等部署 dev-auth，CI 可显式跳过。
2. 页面明确标出“仅开发环境”，播种未完成或失败时禁用登录并显示原始原因。
3. 四个身份首次启动即可登录；连续换角色会替换浏览器里的 CrewStation 会话。
4. 开发者只能开发所选项目，测试者只能访问 preview 范围，普通成员看不到未授权项目，管理员可进入管理空间。
5. 重启 dev-auth 后旧 Provider 行被原位更新，既有固定账户不重复创建，新密钥可立即验签。
6. `apps/`、`modules/`、`packages/` 与 `runtimes/` 不出现 dev-auth Provider 或固定账号标记。
7. 所有角色切换 POST 都带进程级随机表单令牌；跨站或过期页面的无令牌请求返回 403，并给出带新令牌的完整可重试页面。
