# RFC-041｜实施计划

> 状态：Draft · 2026-10-15 · CLI/Bot 独立边界已确认，设计批准后才改生产代码。

| 任务 | 依赖 | 产物与验收 | 状态 |
|---|---|---|---|
| RFC-041-T1 | 无 | 核对真实三段 Agent/session；确认 CLI/Bot 独立；三件套及可交互原型 | 原型及 Chrome 交互检查完成，待设计批准 |
| RFC-041-T2 | T1 批准 | dev-session 稳定对话/epoch/消息受理模型与迁移，真实 PostgreSQL 并发回归 | 未开始 |
| RFC-041-T3 | T2 | 原生上下文私有卷、固定身份/UID、台账和父生命周期回收，迁移锁与资源回归 | 未开始 |
| RFC-041-T4 | T2,T3 | Runner 能力与幂等消息回执，持久 HOME/XDG，停止证明后同 session 恢复 | 未开始 |
| RFC-041-T5 | T2,T4 | 默认持续聊天、停止本轮、历史统一弹窗、显式 fresh 与旧会话兼容 | 未开始 |
| RFC-041-T6 | T3,T4,T5 | 相应分层测试、结构/lint/类型、准确 SHA GitHub gate/e2e | 未开始 |
| RFC-041-T7 | T6 | 本机部署、隔离真实模型多轮/停止续接/换 Pod 续接；Chrome 桌面与 390px | 未开始 |
| RFC-041-T8 | T7 | 验收事实、已知限制、资源保留/清理证据和 RFC 收口 | 未开始 |

不得把 T1 原型或普通三轮成功写成 T4 冷续接完成。每个 CB-01–CB-10 条目要记录相应证据层级；旧数据无法恢复的边界保持，不以新 Agent 的相似回答代替原 session 恢复。

用户批准项集中为：默认 Bot 持续对话；主按钮停止本轮且上下文保留；独立原生上下文卷首次使用分配 1 GiB；明确的新上下文入口；旧历史不合并、缺失原生数据不冒充恢复。CLI 维持独立。
