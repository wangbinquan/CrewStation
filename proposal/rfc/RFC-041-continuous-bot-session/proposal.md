# RFC-041｜Bot 持续对话

> 状态：Draft · 2026-10-15 · 作者已明确 CLI 与 Bot 先保持独立；本 RFC 的执行恢复设计待批准。

## 1. 问题与已确认范围

作者反馈“一个 session 会切分成好几个对话……上下文丢失”，并在澄清后明确“cli 和 bot 先保持独立”。本次解决 Bot 内的连续开发体验；CLI 仍有独立模型会话，两者继续共享项目文件。

当前普通追问实际上沿用同一原生 session。贪吃蛇成功开发 Agent 的三次输入使用同一个 OpenCode session；界面中的另外两项来自此前内存不足失败和另开的只读验收。问题是产品直接将每个执行 Agent 当成一条独立对话，并把“新对话”作为结束后的唯一继续入口。“停止”终止整个 Agent，清理原生 HOME，真实上下文可能随执行环境一同消失。详见 design.md 的源码核对。

## 2. 目标行为

1. 一个开发会话默认有一条持续的 Bot 对话。再次打开、刷新、模式切换、正常答复结束均回到原处；发送追问不产生新的对话。
2. Bot 回复保持浅绿色气泡。工具调用、实际命令、参数与结果仍是对话内部的执行记录，可以打开统一详情弹窗。
3. “停止本轮”停止当前执行，保留已经产生的内容和可用的原生上下文；下一条消息继续本对话。等待输入时不再显示一个会结束整个 Agent 的“停止”按钮。
4. 网络重连只恢复显示与投递状态。进程或 Pod 结束时，在原生上下文完整且旧执行已停止的前提下恢复同一对话；没有原上下文时明确说明，绝不静默换新上下文。
5. 主工具栏只显示当前 Bot、状态以及“历史与设置”。旧的独立对话在统一弹窗中查看；用户主动“开始新的上下文”需要明确确认，保留旧历史，界面显示上下文切换边界。
6. 无发送动作不启动模型，不因刷新、进入页面或自动重连创建 Agent；同一对话不允许两个执行者同时改写原生会话目录。

## 3. 非目标与能力影响

不合并 CLI 与 Bot 的模型上下文，不解析终端屏幕来伪造 Bot 历史；不把业务任务的 session 自动转成开发会话；不承诺找回已被旧版本删除的原生会话文件。模型自己的上下文压缩仍由原生运行时负责，平台不把“保持同一 session”宣传成无限上下文。

| 现有能力 | 本次变化 |
|---|---|
| CLI 独立会话、原生终端及并行 CLI | 保持 |
| 高级工作区显式启动多个独立 Agent | 保持；不自动归入默认 Bot 对话 |
| Bot 顶栏直接选择/新建多个独立对话 | 收入“历史与设置”；主路径默认持续同一条，显式新上下文入口仍保留 |
| 停止按钮结束整个 Agent | 主输入区改成“停止本轮”；结束/释放执行环境仍可从已有管理入口操作，并保留明确后果 |
| 查看旧执行、工具详情和原始事件 | 保留，不删除或串改旧记录 |

## 4. 用户旅程

打开开发页 → Bot → 在当前对话继续提出需求 → 查看执行过程与预览 → 停止本轮 → 修改要求继续发送 → 在同一对话收到答复。刷新或来回切换 CLI 后，Bot 消息、当前上下文和草稿保持；CLI 内容仍独立。

发生环境中断：对话中显示“执行已中断，上下文已保留”，用户继续发送时先恢复原生 session，再投递这一条消息。已有操作结果未知时先对账，不能自动重复执行命令。原生上下文缺失则显示“历史仍在，但原上下文不可恢复”；用户可以查看记录，或明确选择“以新上下文继续”，后者不冒充无损恢复。

## 5. 验收标准

| 编号 | 必须证明的行为 |
|---|---|
| CB-01 | 同一开发会话连续至少三轮，conversationId 与 native sessionId 均不变，消息不重复 |
| CB-02 | 刷新、离开再进入、CLI/Bot 切换保留 Bot 选择、已接受消息及草稿；CLI session 不被绑定或改写 |
| CB-03 | 执行中停止，确认旧进程已停止；继续发送仍命中原生 session，能回忆只出现在前轮上下文中的随机标记 |
| CB-04 | 独立执行 Pod 更换后从原生持久目录冷续接；执行身份改变但对话/原生 session 不变，无双写 |
| CB-05 | 丢回执、双击、两页并发发送/恢复只受理一条同键消息；未知结果先对账，不创建第二个不明执行 |
| CB-06 | 原生文件缺失、损坏或档位不兼容阻止冒名恢复；显式新上下文保留旧记录并标出边界 |
| CB-07 | 当前活跃旧 Agent 可继续；不同旧 session 不被自动合并，已取消且 HOME 被清理的旧 Agent 不宣称可恢复 |
| CB-08 | 历史/工具/设置复用统一 Dialog；长列表末项、嵌套 Esc、返回焦点与滚动、桌面和 390px 无溢出 |
| CB-09 | 原生目录不进入 Git、工作区文件 API、构建或发布；资源台账与父开发会话的保留/删除流程一致 |
| CB-10 | 精确候选测试、准确 SHA 的 GitHub gate/e2e、实际镜像/Pod 和真实模型验收分别留证 |

交互原型在 `prototype/`，复用正式 Bot 气泡、工具详情、输入框和统一弹窗，所有模型/恢复操作为明确标注的本地模拟。原型验收不代替 CB-03/04 的真实原生会话证明。
