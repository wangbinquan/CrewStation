## 2. 验收清单

| 编号 | 要求与可观测证据 |
|---|---|
| RO-01 | Node 总数、Ready、可调度、版本和压力与独立 kubectl 一致 |
| RO-02 | CPU／内存／临时存储 capacity、allocatable、申请、限制和实际值分列，单位／分母正确 |
| RO-03 | 普通、init、常驻 sidecar、overhead、Pod-level 与 resize 测试向量符合 Kubernetes 算法 |
| RO-04 | Pending 未调度、终态、未设置申请／限制、申请超额各有正确状态 |
| RO-05 | 全集群包括基础组件消耗，受管项目／平台分项可核对，非受管对象不出现写操作 |
| RO-06 | Pod 普通／init／sidecar／临时调试容器、镜像、资源、QoS、节点与原生对象一致 |
| RO-07 | Pod／容器 CPU、内存与临时存储可见；未运行容器不填假 0，hostNetwork 不复制节点流量 |
| RO-08 | PVC 请求、绑定容量、挂载、StorageClass、access mode 与独立查询一致 |
| RO-09 | CSI／原生卷统计按 live Pod／PVC／PV UID 对齐，RWX／多 Pod 同卷只算一次 |
| RO-10 | 本机 local-path 专用 PVC 写入前后实际用量可对账；未挂载保留卷仍可采集 |
| RO-11 | 稀疏／硬链／软链／路径越界／替换／取消／不可访问卷均有断言，扫描不读文件内容或改变卷 |
| RO-12 | 多 PVC 共用底层磁盘、node／image／container fs 不重复计容量；非硬配额说明和超过 100% 可见 |
| RO-13 | 网络接收／发送和错误使用两次计数差分；默认接口与 interfaces 不重复，范围明确 |
| RO-14 | 磁盘读写 B/s 与操作速率按设备可核对；根设备／分区／映射无法去重时不虚报合计 |
| RO-15 | 首次样本、节点重启、计数重置、0 时间差、迟到／乱序／过旧值不产生假速率 |
| RO-16 | Node／Pod／PVC 同名新 UID 不继承旧观测；旧库存快照不会连到新实例 |
| RO-17 | 来源 403／404／超时／畸形数据、部分节点失败显示具体原因、覆盖率与源时间；真实 0 可区分 |
| RO-18 | 多浏览器共用采集；慢卷扫描／长运维操作不阻塞指标或目录刷新；租约接管阻止迟到回写 |
| RO-19 | Node／usage 分页固定 observation；过期 410 可恢复；项目筛选不会悄悄缩小全局容量 |
| RO-20 | 管理员可读全部新接口，普通用户被拒；内部 probe 认证、无外部入口和固定路径约束有回归 |
| RO-21 | probe 本身纳入平台内置资源和实际消耗，停止 probe 会显示采集失败而不是卷空闲 |
| RO-22 | 1280／390／320px、明暗、中文／英文、键盘、表格局部滚动与操作草稿保持通过 |
| RO-23 | RFC-010 管理动作、库存完整性、项目归属和用途回归通过 |
| RO-24 | 本地完整 gate、production build、新迁移锁、必要契约锁、改动行防护及最终 SHA 六项 CI 有实证 |
| RO-25 | 1h／6h／24h／7d 和自定义区间、单位／时区／step、均值／峰值及覆盖率正确；超范围／点数被拒 |
| RO-26 | 采集失败与停机在历史中留缺口；过期缓存不会被 scrape 成连续新数据；新装明确起点 |
| RO-27 | 资源删除／改名／归属变更／同名重建后，历史按稳定 UID 和当时归属查询，无历史写操作 |

## 3. 交付门禁

按共享 main 纪律只提交本任务路径；保留已有下拉框和其他会话改动。开始全量前检查是否有等效门禁运行；同一候选内容不因无关 HEAD 变化重复全量。

新增迁移使用 `bun run migrations:lock <本任务文件>`。管理 API 和内部采集协议不是业务金样范围；若实施中确实改变业务契约面，按 testing §6 入锁，不替并行任务的业务形状入锁。

本机完整 check 要区分真实环境通过与环境缺席 skip；浏览器／存储实机证据须记录版本、对象 UID、源时间、样本窗口、HTTP 状态／耗时及错误原因。发布后按精确 SHA 盯完 static／unit／module／console／gate／e2e，再标记 Done。本文所有“未执行”不可仅凭设计完成或测试夹具通过改为完成。

新增真实时序存储测试使用隔离 Prometheus 实例和专用数据目录。若以新 `prometheus` 能力闸门落模块层，必须同步 capability 清单、testing 文档和对应 CI 提供环境／`CS_TEST_REQUIRE`，不能让 hosted 验收长期跳过；CPU／卷当前值与历史查询的主要判断仍由最低可断言层覆盖。七天保留用真实 TSDB 和可控历史样本验证，本机新增部署只声明其真实数据起点，不需要伪造过去样本或等七天才交付。
