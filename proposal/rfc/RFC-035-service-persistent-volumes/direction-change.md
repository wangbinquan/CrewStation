# 服务存储方向调整｜服务无 PVC，任务卷结束后回收

> 2026-09-28。作者明确裁定：「服务容器不要PVC，任务肯定是要的，但是任务结束后要自动清理掉」。本记录取代 RFC-035 原服务挂卷方向。作者随后要求沿用 RFC-035 重写目标设计；当前三件套已替换原草案。
> 本文件记录方向变化；当前以重写的 proposal/design/plan 为准，状态 Draft，待作者审视，不代表功能已实现。

## 1. 当前确定的边界

- AW Web／控制面服务不挂 PVC，可用有容量限制的临时目录作缓存，缓存丢失必须能恢复。
- Git、worktree／iso、脚本、原生 Agent 会话继续放 CS 业务任务工作卷，父容器与 Agent Pod 的共享布局保留。
- 工作流终结后自动回收任务 Pod／PVC；等待人工、暂停、可重试节点失败不视为最终终结。
- 不为了 AW 引入 RWX 服务卷；不把服务 PVC 设计扩大成部署前置条件。不修改 AW 只读仓库。

## 2. 建议存储分配

| 数据 | 建议持久来源 | 本地使用方式 |
|---|---|---|
| 业务任务／DAG／节点状态、权限、配置、版本指针 | AW PostgreSQL | 按版本读取；并发修改使用数据库事务与修订 |
| skills 的小型文本文件及不可变版本 | 有单文件／版本总量边界的 PostgreSQL 文本记录 | 执行前按固定版本生成文件；服务读写经 repository |
| skills 大附件、插件完整包、上传和导出文件、结果产物 | S3 兼容对象存储；PG 存 objectKey、摘要、长度、状态与权限 | 按需下载、校验、解包到任务工作卷或可丢弃缓存 |
| 密钥、数据库／对象存储连接配置 | 平台 Secret／配置注入 | 不在服务启动时临时生成新的加密主密钥 |
| Git 镜像缓存、worktree／iso、依赖、原生 CLI 会话库 | 任务 PVC | 沿用真正的文件系统；任务终结前选取所需产物归档 |
| 业务和执行事件 | 所属 AW／CS 数据库 | 通过持久事件接口补读；大日志分块归档对象存储 |

数据库连接地址由可信启动配置确定；数据库内保存该实例的 schema／generation 验证信息，不靠服务本地文件选库。插件数据库记录从绝对 cachedPath 改为 artifactId／digest／运行环境兼容信息，解包路径只是当次执行位置。容器间不传另一个容器的本地绝对路径。

建议保持不可变对象版本：先上传并校验对象，再通过 PG 事务切换版本引用；失败的未引用对象延迟 GC。删除必须考虑历史版本与活动任务引用，不对业务端暴露整个 bucket 的管理凭据。不使用一个反复覆盖的 S3 key 充当多文件事务。

对象存储通过 API 使用，不把 S3 FUSE 挂成 Git／SQLite 的透明共享目录。文件锁、随机修改、目录重命名等语义必须保留在任务文件系统；对象存储承担交付包和归档。

## 3. 任务结束与清理

建议将数据寿命和 Pod 寿命分开：`pause` 留卷、最终 `close` 回收。不能简单改成 follow-container，否则等待人工时删 Pod 就可能丢工作区。

最终状态分业务结果与资源回收结果，按持久操作推进：

1. AW 判断工作流 succeeded／最终 failed／cancelled，不再受理新节点；CS 冻结本父任务的新执行。
2. 确认所有 Agent、命令子任务及未知执行已经停止；需要归档的工作区不再并发写。
3. 使用平台控制的归档操作读取任务卷，上传需要保留的产物，保存校验摘要与持久归档收据。执行事件完成数据库持久确认。
4. 原父 Runner／归档进程停止，确认所有引用 PVC 的 Pod 消失，公共资源中心按原 PVC UID 回收。
5. 观测确认 Pod／PVC 清理完成，资源状态 closed；业务历史、对象引用和审计记录保留。

默认归档明确的结果文件、必要的 diff／commit 引用与日志，不把 node_modules、仓库镜像、每个 iso 和可再生成缓存全部长期打包。若产品需要“任务关闭后原生会话继续”，须显式增加一致性会话归档／恢复合同；事件历史不等于原生会话可续跑。

归档失败自动重试并标明归档未完成，不先销毁唯一数据；删除失败显示清理中／失败并重试；同键重放不能重复归档或删同名新 UID。失败任务若仍有恢复／重试意图则未最终关闭，保留任务卷。长期无法归档的处置需要独立的数据丢弃策略，不在本记录默许自动丢数据。

## 4. 当前代码与缺口

- AW 的 skills 内容读取已有版本化端口，可作为 PG／对象实现切入点，但当前 repository 仍调用文件系统兼容实现：`packages/backend/src/modules/resource-catalog/application/skills/contentReader.ts:3–19`、`infrastructure/skillRepository.ts:27–38`（AW 仓库）。不等于已经完成云存储适配。
- AW 插件安装当前产生不可变本地 generation，并将 cachedPath 发布进数据库：`packages/backend/src/services/pluginInstaller.ts:1–17`（AW 仓库）。需要改造资源身份与物化机制，而不只是运行时 spawn。
- AW `config/index.ts` 已变为入口转发；实际本地 config.json 机制在 `packages/backend/src/platform/configuration/fileConfiguration.ts:1–3`；generation 文件适配仍在 `platform/persistence/generationStore.ts`（AW 仓库）。后续实施须按最新层次接入，不能沿用早期路径直接改旧入口。
- CS 目前 data 的数据资源投影只供给 PostgreSQL，不供给 s3：`modules/data/domain/dataRecords.ts:50–54`。对象存储的供给、权限和生命周期要补；也可以先由平台登记外部 bucket 并注入受限访问配置，不能假称已有自动供给。
- CS 任务卷投影当前将 persistent 配为 retain，释放投影只自动删除符合条件的 follow-container 卷：`modules/task-runtime/domain/ledgerProjection.ts:176–184`。因此“持久任务最终关闭后自动删卷”仍是待实现的产品变更。
- RFC027 的业务存储当前包含工作区、原生会话和 Runner 私有日志：`packages/k8s/objects/businessStorage.ts:4–19`。继续保留其可靠执行机制；新增终结回收必须等日志持久确认，不删除仍在执行的子任务数据。

上述 AW 路径只读核对，本轮没有写入 AW、没有改服务或任务卷。

## 5. 后续设计范围

CS：对象存储登记／项目隔离访问、任务产物归档合同、persistent 任务的最终回收策略与幂等清理、资源与拓扑状态。不得擅自批量删除现有 retained 任务卷；存量清理另行列清单和归档条件。

AW：PG 冷启动和配置／版本指针、skills 与插件文件适配、产物引用与读写、任务终结／归档握手；同时保留原鉴权、单主调度和平台执行适配工作。AW 修改须在允许写入该仓库的独立任务实施。

新方向不要求服务卷或 RWX 存储。作者随后明确要求沿用尚未实施的 RFC-035 改写目标设计，并在实施前重新提交审视；该最新指令取代此前另起编号的建议。三件套现已改写，实施未开始。
