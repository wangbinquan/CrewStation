实施范围是 CS，不写 AW。真实资源验收使用专用服务和任务；不得用历史 retained 卷做删除测试。Garage 后端 endpoint、bucket、凭据、镜像 digest、测试存储类和独立备份演练目的地必须在验收前准备齐全，敏感信息不进入 RFC。不能以模拟 S3 或仅删除 PVC API 成功代替端到端持久化／回收证明。

## 3. 实施门禁与完成条件

两次补充自审累计 21 组缺口见 [design-audit.md](./design-audit.md)，D1–D8 已整体批准；新增可观测要求纳入 OS-52…54。实现过程发现新的产品取舍，按开发规则记录待裁定事项，不默默扩张能力或降低数据安全门槛。每条失败／拒绝分支和资源完整性都需用例。

生产代码候选完成后跑针对性验证、迁移锁／契约锁及 `bun run check`；不因无关共享 HEAD 变化重复跑完整门禁。发布精确暂存自己范围，共享文件保留并行贡献；必须另有有效发布授权。交付记录区分本地测试、真实后端／集群、最终 SHA CI 和部署版本。

仅当 CS 对象能力、任务归档／自动回收、资源展示和必需故障证据齐全，才可标 Done。AW 改造始终另列为外部接入工作，不能在本 RFC 中勾完成。

## 4. 本轮设计验证

已核对原任务关闭／卷保留源码、模块分层、RFC-027 生命周期合同；第二轮进一步追查实际 Manifest／HTTP、日志过期、父 Pod 绑定、冻结、额度和安装入口，补写 design-audit.md 与 OS-30…OS-44。仅做文档一致性、链接和 diff 检查；未执行任何生产实现、自动删除、迁移、部署或功能测试。具体文档检查结果记录于 review.md。

第三轮沿清单修改和收据并发、提前删产物、未启动 Pod、多个冻结原因、日志导出、损失完成及旧版本回退逐一构造反例；更新 design-audit §15–22 与主稿，新增 OS-45…OS-51。所有功能验收仍未执行，已有 namespace 退休保护经代码核对保留，未把现有保护误报为缺陷。
