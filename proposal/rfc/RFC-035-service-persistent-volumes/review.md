## 2. 已在稿内补齐的设计风险

| 风险 | 处理位置 |
|---|---|
| 用 follow-container 代替 persistent 导致暂停丢数据 | design §4–5 分离暂停和最终寿命 |
| 应用／平台猜测失败就是工作流结束 | proposal §3；显式 finalize outcome |
| 对象上传成功但数据库事务失败，或者 pin 与删除竞态 | design §3 staging／ready／引用与行锁 |
| 删除父任务 cascade 绕过归档门槛 | design §6 独立卷释放许可，覆盖运维入口 |
| 节点失联仅删 API 对象就当作已停止 | design §5 要求实际停止／fencing 证据，未知时阻塞 |
| 归档无法读取 paused 任务，偷偷恢复业务命令 | design §5 固定只读助手与独立额度准入 |
| PVC 删除成功被误认为后端空间已释放 | design §5 存储类验证与 PV／后端观测 |
| 公共 infra 已创建资源而图遗漏 | design §7 声明／观测／拓扑集合与边对账 |
| 服务不挂卷但 AW 仍只改 spawn | design §8 列明配置、插件、skills、PG 和终结握手 |
| 自动回收改变旧任务语义 | design §4、9 旧记录 legacy 沿用原 volumeMode，新策略显式协商 |

## 4. 对象存储选型补充

已对照官方资料选择 Garage v2.4.1，并写入 storage-selection.md 及三件套；纠正原稿仅选 S3 协议、要求外部后端但没有本机落地方案的缺口。官方兼容缺口落实为 CS 自管不可变版本和权限，不依赖 bucket versioning／policy／Object Lock。明确系统 Garage 自己的 PVC 和业务服务零 PVC 之间的区别。

只读本机核对为单 ARM64 节点、10 allocatable CPU、约 31.3 GiB allocatable 内存、local-path Delete；未测空闲磁盘和实际性能。单节点被限定开发／验收，生产需要独立故障域与恢复演练；不把 Garage 官方“轻量”替代本项目性能实测。没有拉镜像、安装组件或创建卷。所有新参数与安装范围仍待作者审视。

## 6. 第三轮自审结论（2026-09-28）

**上一轮补充后仍有七组组合缺口，不能直接判完备。** 本轮用并发和故障时序核对，而非仅增加功能清单：

| 发现 | 本稿修正 |
|---|---|
| R2 清单与 R1 收据可能分别成功 | data 的同一 finalization binding 裁决修订／收据／损失许可，跨模块用 outbox 接续，旧回执不能套新 revision |
| 删卷前可以先删除归档产物 | 终结 guard 持有产物，回收完成前拒绝产物集销毁；许可前复核已知健康情况 |
| 未调度／启动失败 Pod 没有完整 terminated 列表 | 区分 never-provisioned／never-scheduled／正常停止／unknown，证明先存 resources 再移 finalizer；封存启动准入，处理迟到 create |
| 切流／备份／项目归档共用“冻结”可能互锁或漏删 | 明确各原因的权限矩阵与优先级；后台归档不依赖失效应用身份，备份则暂停收据和新删除许可并排空已发操作 |
| 日志导出与代终结预览有未说明的能力 | 使用现有事件游标提前导出，不虚构新平台导出作业；过期／断档显式不完整，预览不假称列全暂停卷 |
| 损失分支、从未有卷却套正常完成条件 | 分别使用 lossReceipt／never-provisioned 证明；不伪造产物 ready、停止证据或释放字节 |
| 旧二进制被假设会读取新版本标记 | 保护落实于更新后的官方部署工具、新版本启动检查及启用前排空；绕过工具直接启动旧版本不在首期保证内 |

具体合同为 [design-audit §15–22](./design-audit.md#15-清单修订与收据提交的唯一裁决)，三件套与 OS-45…OS-51 同步。核对 `resources/application/namespaceRetirement.ts` 后确认原有退休路径已经阻塞保留卷，本轮要求新资源接入其保护，没有把它误报成现存删除漏洞。Kubernetes 官方文档用于校验 Pod 终止及 finalizer 边界；未做集群写入。

修订后的稿件可提交作者审视，但不标实施门禁通过：D1–D8 尚未批准，51 项功能验收均未执行；停止证明／迟到创建、后端回收、Garage 兼容及生产耐久仍是实施时必须取得的证据。没有新增产品决定、没有改生产代码、没有联系其他 session／Agent，也未提交或部署。
