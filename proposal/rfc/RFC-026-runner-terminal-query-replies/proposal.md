## 1. 背景

OpenCode 这类全屏 TUI 启动时会向终端发查询：设备属性（DA）、光标位置（DSR）、模式支持（DECRQM）、前景／背景色（OSC 10/11）等，
**拿到应答才继续画界面**。现在只有浏览器里**持有输入控制**的那个 xterm 会应答；没持有控制的视图 `disableStdin`，不应答
（`apps/console/src/features/dev-session/model/native/nativeTerminalSurface.ts:20,41-45`）；Runner 自己的无头终端也从不应答
（`runtimes/task/src/terminal/terminalScreen.ts` 没有接 `onData`）。

后果（STATE.md 已记录、RFC-024 的非目标 N2）：

- 新开的 CLI 在**有人取得输入控制之前一直是空白**。RFC-022 让创建者的窗口提前取得控制、RFC-024 让创建者在初始化期间保持控制，才绕开了这个问题；
  创建者关掉页面、别的成员打开、或者用命令行 / 接口起的 CLI，都会一直空白，RFC-024 只能等 90 秒超时放行。
- 应答走 `terminalInput`，每一条都给控制租约续期：人已经离开，TUI 的查询还在替他续租（`nativeTerminalAttachment.ts:26-28`、dev-gotchas「终端程序的查询也会产生输入」）。
  现在靠页面按焦点主动释放兜住。
- 多个查看者的应答各不相同（浏览器主题、字体），CLI 拿到的答案取决于「这一刻谁持有控制」。

## 2. 目标与非目标

**目标**

- G1 CLI 的终端查询由 Runner 的无头终端统一应答，与有没有人打开页面、谁持有控制无关；新开的 CLI 无人查看也能画出界面。
- G2 浏览器里的 xterm 不再应答终端查询，`terminalInput` 只剩人真正的键盘、鼠标、粘贴输入；控制租约只因人的操作续期。
- G3 旧 Runner 的 CLI 行为不变（浏览器照旧应答），不出现「谁都不答」的窗口。

**非目标**

- N1 不改输入控制的规则（取得、续约、释放、换人）。
- N2 不改 RFC-024 的界面判定；本 RFC 之后超时放行应当很少触发，但仍保留。
- N3 不做按查看者区分的应答（多人看同一个 CLI，CLI 只有一份答案）。

## 3. 用户故事

- U1 开发者用接口起一个 OpenCode，没有打开页面；十几秒后打开，看到的已是画好的界面。
- U2 开发者 A 新开 CLI 后马上切到别的页面，30 秒后控制被释放；CLI 照常画出界面，A 回来时一切正常。
- U3 成员 B 打开 A 的 CLI 只看不操作：B 的浏览器不向 CLI 发任何东西，也不会因为 TUI 的查询被判为「在输入」。

## 4. 行为

- Runner 的无头终端应答全部终端查询：xterm 自带的 DA／DSR／DECRQM／DECRQSS 照其应答；它不回答的配色查询（OSC 10/11/4，实测无应答）由 Runner 按固定配色补答。
- 浏览器 xterm 拦下这些查询、不产生应答；只在 Runner 声明「由我应答」时这样做，旧 Runner 照旧由浏览器应答。
- CLI 看到的背景色是固定的一种（见 Q2），不再随「这一刻谁持有控制、他用浅色还是深色主题」变化。

## 5. 能力影响清单

| 编号 | 被改变的既有能力 | 影响 | 请作者确认 |
|---|---|---|---|
| C1 | CLI 通过 OSC 11 读到查看者的真实背景色，据此选深色／浅色配色 | 改为 Runner 的固定配色（Q2）：用浅色主题的查看者看到的 OpenCode 配色可能与工作台底色不一致 | 是否接受 |
| C2 | 浏览器应答的 DA／字体相关能力（如 xterm.js 渲染器支持的特性） | 改为无头 xterm 的应答；两者同为 xterm.js 6，DA／DECRQM 结果一致（实测见设计 §2） | 是否接受 |

## 6. 待裁定

| 编号 | 问题 | 选项 | 推荐 |
|---|---|---|---|
| Q1 | 谁应答 | A：Runner 始终唯一应答，浏览器一律拦下（新 Runner）；B：无人持有控制时 Runner 应答，有人持有时浏览器应答 | A。B 在换人瞬间会出现重复应答或无人应答，重复的应答会作为乱码进 TUI 的输入框；A 只有一个应答方，还顺带解决「应答续租」 |
| Q2 | Runner 答的配色 | a：工作台深色主题的固定值；b：创建者起 CLI 时页面的主题（启动命令带上两种颜色） | a。多人查看时本来就只能有一份答案；深色是终端区的默认观感 |
| Q3 | RFC-024 的「创建者在初始化期间保持在用」是否撤掉 | 撤掉 / 保留 | 保留。它只影响控制归属，不再是画界面的前提，留着让创建者进页即可输入 |

## 7. 验收标准

| 编号 | 标准 |
|---|---|
| RQ-01 | 实机抓取 OpenCode 1.18.29 启动时发出的全部查询，逐条列出 Runner 的应答；OpenCode 画出界面 |
| RQ-02 | 用接口起 OpenCode、不打开页面：名册「CLI 初始化」按 `screen` 完成（不是超时）；之后打开页面即是完整界面 |
| RQ-03 | 创建者起 CLI 后立刻离开页面：控制 30 秒释放，CLI 照常画出界面 |
| RQ-04 | 只读查看者的浏览器在 CLI 启动全程不发 `terminalInput`（抓 WS 帧） |
| RQ-05 | 旧 Runner 的 CLI：浏览器照旧应答，行为与之前一致 |
