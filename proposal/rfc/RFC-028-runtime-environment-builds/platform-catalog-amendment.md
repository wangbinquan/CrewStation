# RFC-028 平台镜像目录与业务授权修订

2026-09-27，作者明确裁定「运行镜像不归属于项目，但是和算力档位一样可以开放给某个业务」。本修订已经获得这一产品行为指令，覆盖原 P6 与项目私有／共享目录模型；平台归属迁移和工作台已形成在制候选，尚未发布部署，验收状态见 acceptance.md。

## 产品合同

- 运行镜像定义、不可变版本、配方和构建历史属于平台；新增镜像不要求选择所属项目。停用、版本退休及原引用保留的语义不变。
- 平台管理员管理目录及业务授权。业务开发者／负责人只能查看已授权的目录与兼容版本、选择绑定并查询本业务的执行记录；不能借项目 develop 权限创建或修改平台镜像。
- 授权与算力档位保持一致的可理解方式：平台默认开放范围与特定业务授权分离，业务可使用范围由服务端计算。受限业务的空允许集合明确等于禁止新选，不能解释为全部开放；业务不能给自己增加授权。
- 镜像用途／Agent 档位组合验证是使用条件，不是授权。获得目录授权不获得模型凭据、其他业务源码／构建 Secret 或其他业务执行历史。
- 平台镜像详情显示授权业务和各业务的实际使用记录；业务入口只显示自身历史。定义、版本、构建、使用任务分开，不用引用计数代替使用记录。
- 源码构建选择仓库／提交，仅表示构建来源；构建所需仓库授权和包 Secret 仍按来源边界校验。已有镜像登记无需来源业务。初始化凭据在消费业务上下文固定，不把来源业务 Secret 自动开放给其他业务。
- 管理、查看、新增和授权操作均使用已有统一弹窗或独立页面，禁止页尾 append。

## 与算力档位统一的工作台交互

作者随后要求两者界面风格基本一致，因为都由平台配置后赋予业务。本节为验收要求：

- 平台入口沿算力档位的 PageHeader／Card／列表工具栏／DataTable 结构，右上角统一“新增”，名称、用途、可用状态、默认开放状态和操作位置一致；不再出现“所属项目”选择或徽标。搜索、空状态、状态徽标、按钮尺寸和窄屏适配复用公共组件与样式，不另造一套镜像管理视觉体系。
- 编辑入口与算力档位使用同级独立编辑页面或统一弹窗，基本配置、执行配置与验证结果按相同方式分组。镜像独有的配方、构建记录、不可变版本、使用历史属于详情内容，不堆到目录底部；不复制旧页面中可能残留的行后管理区。
- 业务授权放在既有管理员“业务资源配置”中，与算力授权并列，采用“继承平台默认／仅允许指定”的相同模式、具名多选、空集合禁止使用、修订冲突保留草稿。平台详情可以打开授权入口，不能以构建来源项目代替授权业务。
- 业务侧显示已获授权镜像与本业务实际使用，描述授权来源和不可用原因；业务负责人不能修改平台目录或给自己扩权。开发／任务／服务中的版本选择沿用同一有效授权集合。
- 实机并排核对算力档位与运行镜像页面，以及业务资源中的两种授权配置；验证中英文、明暗主题、320／390／1440 宽度和键盘路径。

## 技术落位与边界

沿用 runtime-environment L4，拥有平台目录和业务镜像授权记录；不在 agent-runtime 内复制镜像生命周期。授权管理复用算力授权的管理员限定、预期修订号、空集合语义和当前有效集合表达，独立存储镜像 ID。platform 只负责接线；源仓库、凭据、执行历史仍通过所属模块端口读取。

定义与版本移除项目所有权字段；构建来源、验证消费业务、执行引用的 projectId 分别保存，不能拿这些操作上下文推断镜像拥有者。旧 registry 路径可以作为不可变产物来源保留，不再决定目录访问权限。新构建的资源归属与额度明确属于平台镜像构建，不能隐式计入某个获授权消费业务，也不能让来源业务归档自动删掉平台镜像。

平台管理端提供定义／setup／配方／构建／日志／版本／授权／全局历史接口。现有 /v1/admin/runtime-images 推送信息合同保留，目录沿 /v1/admin/runtime-image-catalog 扩展。业务路径保留授权目录、兼容选择和本业务历史；旧项目写入口不再提供所有权绕过，明确拒绝或返回迁移说明。所有执行入口和发布允许集合必须重新检查有效业务授权，不能只过滤下拉框。

撤销授权阻止新绑定和新执行；已受理运行按固定快照继续，不热换镜像、不删产物。已有执行的重试／恢复按原引用、原业务权限与恢复合同处理，不能借恢复扩大允许集合；这一边界必须与停用语义逐项测试。全局历史仅管理员可读，业务历史查询在后端强制限制业务。

## 数据迁移

采用新增迁移，禁止修改已锁旧迁移；保留现有镜像／版本／构建／验证／引用 ID 与 digest。原项目私有镜像转为平台镜像，并为原消费业务建立显式可用授权，避免突然不可用；原 shared 范围按原实际可见范围保留，不能将所有私有镜像默认公开。来源项目仅保留为可审计 provenance，不再是所有者。当前配置、release 快照、暂停任务与可恢复工作卷引用不重建、不删除。

迁移同时转换幂等创建记录的授权主体与请求键命名空间，防止项目路径兼容请求与管理员全局新请求发生串单；旧键重放须校验原主体，不能因提升目录归属而扩大读取范围。授权变更、版本选择与退休保留现有并发锁及 OCC 约束。

## 验证要求

1. 管理员未选择业务也能登记已有镜像；源码构建只需指定来源仓库，镜像不会出现在“所属项目”模型中。
2. 向业务 A 开放后 A 可选、B 不可见且直接传 ID 被拒；管理员给 B 开放后才可选；非管理员不能自行授权。
3. 默认开放／受限集合／空集合／停用／撤销及并发更新的 HTTP、真实PG和执行准入用例。
4. 迁移后原 ID、digest、引用、任务恢复保持；私有镜像不泄露，历史业务上下文不混淆，来源业务归档不误删平台产物。
5. 平台管理员查看跨业务执行记录；A 无法通过版本ID、分页游标或历史链接读取 B 的执行、源码和日志。
6. 中英文、深浅主题、长列表、320／390／1440宽度、键盘关闭与返回上下文；管理表单不要求填写内部业务ID，不在页尾追加详情。
