# RFC-028 运行镜像可理解性整改

2026-09-28，依据用户“重新看下所有描述和所有界面，以好理解的方式进行重新设计”的要求落实。延续已批准的全局目录、业务授权、三种构建来源、独立任务与 Agent 容器，不增加后端契约。

## 实际问题

实机查看发现，“编辑”打开的却是构建、版本、授权、使用记录、配置混合弹窗。构建按钮和开放范围按钮常驻所有页签；初始化和工具检查只能写整份 JSON；停用镜像、停用版本、取消构建/验证直接提交。开发配置的版本选择仍在表单中直接展开，违反统一弹窗约定。

## 调整

- 保持与算力档位相同的全局目录布局。入口明确为“管理镜像”，平台管理进入独立路由；返回保留搜索、分页与滚动上下文。业务只读查看继续用统一弹窗。
- 管理页按“基本信息、构建配置、镜像版本、构建与日志、业务授权、使用记录”组织。构建只出现在构建配置；开放范围只出现在业务授权；停用只出现在基本信息。
- 创建和新增构建配置使用共享大表单弹窗，清楚区分镜像名称、用途、来源、依赖安装、每次启动初始化、验证检查。构建配置不可变，修改会保存新配置，不修改已有版本或容器。
- Dockerfile/仓库/已有地址各给填写提示。任务、Agent、服务解释独立容器与工具安装边界。初始化步骤和文本工具检查提供字段编辑；完整 JSON 作为可选高级入口，已有复杂配置不丢失。
- 危险操作统一 ConfirmationDialog/ConfirmDialog：列明目标、范围、后果和恢复方式。开启默认开放也须确认；取消不发送请求；失败留在原弹窗；确认使用打开时的目标及修订，避免自动刷新改变确认含义。
- 开发镜像选择用嵌套共享 Dialog，保存配置和丢弃冲突草稿均先确认；草稿变动在保存前不落库。
- 重写目录、新增、配置、构建、验证、授权、使用记录、开发选择的说明，去除镜像归属项目的过时文案。

## 验收

先用回归用例复现即时危险写入。覆盖取消/确认/失败/过期修订、路由返回上下文、长列表末行、嵌套 Esc、三种来源草稿、构建幂等、初始化与检查表单、业务读权限。实机检查宽窄视口与中英文；本地完整门禁通过后提交，CI 与部署结果单独记录。

## 实现与验收记录

- 目录仍复用算力目录的 CatalogPage / CatalogSearch / DataTable / CatalogPagination；平台“管理镜像”进入 `/admin/runtime-images/$imageId`。从目录进入时，返回使用原历史项恢复滚动、搜索和分页；直接打开链接时返回目录。
- 基本信息只负责名称、说明与可用状态。构建配置可选历史配置、生成版本、保存新配置；“清空”恢复本次打开时的内容。授权范围操作归入“业务授权”。
- 配置表单分为“镜像内容 / 启动与检查（可选） / 高级 JSON”。步骤和工具检查用 FormDialog 编辑；支持原有文本、SHA-256、JSON 输出比较，修改不会丢弃其他配置。安装指南也改用 Dialog。
- 镜像停用/启用、版本停用、取消构建、取消验证、默认范围变更、新增时默认开放、开发配置保存、丢弃冲突草稿均有确认；不可逆删除继续使用输入确认词的 ConfirmDialog。
- `runtimeImageSafety` 先红（3 个即时写入），修复后绿。与 `runtimeImageUsability`、既有 console/workflow 组合共 **32 pass / 0 fail**。覆盖过期修订冲突、取消错误保留与同键重试、嵌套 Esc/焦点、30 行末行独立路由/返回、无效高级草稿不崩溃、命令字段及幂等提交。
- 真实 IAB 读取本机 API 的 Vite 预览：1280 宽屏中文和英文编辑布局、390 窄屏管理页与编辑弹窗（页面宽度 390，弹窗 358）、停用确认及 Esc 返回触发按钮均已检查。仅打开/取消操作，未停用真实镜像、变更授权或发起构建。开发配置写入、错误与重试用 HTTP 夹具验证。
- 结构门禁发现组件目录达到 21 个源文件，按仓库规则归组到 `components/recipe/`；React 检查发现恢复基线不应在渲染中读取 ref，已改 state。两次静态阶段失败记录保留，完整检查仍以最终自然结束结果为准。

- 最终复查把残留的技术标识、Dockerfile 查看、高级版本选择和高级验证配置全部改为共享 Dialog/FormDialog，运行镜像功能不再含 `<details>` 展开区。补充长版本列表末行打开/关闭后保留焦点和滚动、无效验证 JSON 关闭后保留草稿的回归。
- 最终定向组合包括 inline 上传和中英文键一致性，共 **55 pass / 0 fail、235 断言**；生产改动行 **478/482 = 99.17%**，无防护违规。第一次完整测试发现两处旧按钮文案定位（3718 pass / 11 skip / 2 fail），更新定位且保留上传断言。后续完整检查继续自然运行，最终补充修改另跑全套静态检查；完整结果待自然结束后记录。

## 另行确认的限流问题

用户在本轮验收中追问正常浏览频繁出现 429。实机读取 `rate-limit-platform-api` 与 `in-flight-platform-api`，当前每用户 average=20/s、burst=40、in-flight=16。`ImageCatalogRow` 每行分别读取 versions、builds、validations，目录每页 30 项、自动刷新 30 秒；满页有约 90 个额外查询。25 分钟网关日志窗口中运行镜像相关请求峰值达 66 次/秒，版本/构建/验证均出现 429。该窗口也包含同一 dev-admin 的自动验收流量，不能把全部 429 归因于单个正常页面。确认是页面请求放大与共享账号额度叠加；本轮未改全局限流，聚合目录摘要与刷新调度仍应单独修复。
