# RFC-028｜运行镜像构建与独立绑定

> In Progress · 2026-09-27。作者已要求「开始落地」，选择「保留独立容器，统一预置工具环境」，随后明确补充「每种 agent 或者任务或者服务执行的时候，可以指定自己的运行镜像」。本稿以最后这项要求修正绑定模型：各执行对象独立选择，公共工具定义可复用，不强制同一镜像或整组绑定。作者已批准完整实现 RFC、提交上库和本地部署，批准包含本稿 P1～P6／E1～E10 与 ADR-0010。现开始实施，部署及实机验收尚未完成。

## 1. 背景与当前能力

执行需要的不只是 pip／npm 包，还可能是系统库、脚本、二进制、模板与配置。平台需要构建和管理运行镜像，并允许服务、业务任务、各类 Agent 独立选择。

源码核对基线 `01ecfc1f20b1588341b351216ad7cc029042b05d`，fetch 后本地与 origin/main 为 0／0。RFC-027 在同一 main 并行实施，其在制文件不属于本任务；设计承诺不视为已有能力。

## 2. 已确认要求与建议

### 2.1 已确认要求（本会话）

- U1：平台代为构建镜像，预置 pip／npm／系统包、脚本、二进制和环境配置。
- U2：保留父任务与 Agent 的独立容器；共享工作文件，不共享进程和容器根文件系统。
- U3：服务、业务任务和每种 Agent 均可指定自己的运行镜像。
- U4：公共工具环境可复用到多种镜像；不能把统一工具环境解释为所有执行必须使用同一镜像。

### 2.2 建议方案（已获批）

- P1：以 Git 中的 Dockerfile＋构建上下文为主输入；提供 Python／Node／工具安装模板，也支持登记已有平台仓库镜像。
- P2：每个镜像版本对应一个不可变 digest。镜像构建、用途验证、绑定三者分开；一个镜像可以被多处引用，组合验证按用途及 Agent 档位修订记录。
- P3：服务声明自己的镜像；业务任务声明默认镜像及可选镜像；每个 Agent 档案独立声明默认镜像及可选镜像。执行请求的覆盖只能来自该 release 授权的可选集合。
- P4：未指定时保持现有行为：服务走仓库构建，父任务用平台任务镜像，Agent 用所选算力档位镜像。Agent 不自动继承父任务镜像。
- P5：发布与每次执行受理时解析为 digest 并固定；已有任务、重试和恢复不随标签或默认值变化。
- P6：项目管理自己的业务工具镜像；平台管理员继续管理模型、协议、算力档位和公共镜像。显式 Agent 镜像必须通过与档位的组合测试。

开发会话同样覆盖：开发工作区镜像和开发 Agent／CLI 镜像在项目配置中独立设置，创建时可以从相应允许集合中选择；不要求先发布一个业务 release。

## 3. 用户流程

1. 在项目设置「运行镜像」选择仓库提交、Dockerfile、上下文和用途，或登记已推入平台仓库的镜像。
2. 提交依赖锁文件、安装脚本、二进制／下载校验、配置模板；点击「构建并验证」，查看真实进度和逐步骤日志。
3. 获得镜像版本，查看已通过的服务／任务／Agent 用途验证；Agent 验证明确关联档位修订。
4. 分别配置服务运行镜像、业务任务默认镜像、Agent A 镜像和 Agent B 镜像。可以四处不同，也可以显式引用同一兼容版本。
5. 发布预检通过后固定配置。创建任务或启动 Agent 时，可从发布声明的可选集合选择镜像；详情展示实际版本与摘要。
6. 更新依赖产生新版本，显式修改需要更新的绑定；不会连带替换其他 Agent 或服务。

例：Web 服务用轻量服务镜像；父任务用 Python 数据处理镜像；浏览器 Agent 用带浏览器的镜像；报表 Agent 用带自研二进制的镜像。它们仍可读取同一任务的工作文件，各自拥有所需工具。

## 4. 范围与边界

| 对象／阶段 | 本期行为 |
|---|---|
| 服务 | 支持从仓库构建，或选择完整的现有应用镜像；不是把一个仅装 Python 的工具底座直接当成已包含业务代码的服务 |
| 业务任务 | 创建时选择父任务镜像，command 子任务在该容器中执行；活动父任务不热换镜像 |
| Agent | 每个业务 Agent 档案独立选择；显式镜像必须保留平台 Runner 和所选档位启动能力，模型／凭据／资源仍由档位管理 |
| 构建脚本 | 支持系统包／语言包安装、下载校验、编译、COPY、普通环境配置，结果进入镜像 |
| 每容器初始化 | 可选，以工作用户执行配置生成和检查；成功后接收任务。服务初始化使用镜像入口／启动命令，不强加 TaskRunner |
| 复用 | 同一个镜像可多处引用；公共 Dockerfile／安装脚本可以复用，镜像之间没有隐式全局继承 |

第一版单架构构建，架构明确记录；任务／Agent 最终镜像需兼容平台 Runner，服务镜像不要求 Runner。业务工具建议安装到 /opt/business 等非挂载位置，不能用 /work 的镜像文件冒充挂载后的可用文件。

开发工作区和开发 Agent／CLI 也可各自选镜像，原档位默认作为缺省回退保留。公共每容器初始化不提供跨容器「任意脚本只执行一次」承诺；共享数据准备通过显式父 command 顺序完成。已有档位 beforeStart 保留。

不包含宿主机环境安装、hostPath、Docker socket、特权容器授权或通用 CI 编排。选择镜像不赋予额外平台权限。

## 5. 能力影响清单

| 编号 | 原有能力 | 新行为与兼容方式 |
|---|---|---|
| E1 | RFC-006 C1/C2：管理员档位拥有完整运行配置 | 增加业务 Agent 镜像的显式选择；平台档位仍拥有协议、模型、二进制路径、参数、凭据和资源，项目选择不能覆盖这些字段 |
| E2 | RFC-006 C3/C18：管理员自行构建镜像 | 增加平台构建和项目镜像目录；原外部构建／推送入口保留 |
| E3 | 每 Agent 独立 Pod、独立额度 | 保留；新构建与验证另有容量，不占用业务 Agent 额度冒充资源管理 |
| E4 | 父任务统一镜像 | 显式选择则使用所选版本，否则沿原默认；旧任务不原地迁移 |
| E5 | Agent 镜像仅来自档位 | 显式业务镜像优先，经组合测试后使用；缺省仍用档位镜像，不继承父镜像。兼容失败阻断，不能静默退回默认 |
| E6 | RFC-006 C17：default 每次启动解析 | 保留解析时机。每次 Agent 受理固定档位修订及镜像；显式镜像若与新的默认档位不兼容，明确报错，已有执行不变 |
| E7 | 服务每次发布均构建 | 新增引用镜像模式，明确跳过构建，仍执行原迁移／健康检查／切流。服务镜像必须包含其业务程序，迁移默认用该发布镜像 |
| E8 | RFC-027 禁止动态材料覆盖 image | 增加受控镜像选择字段，从 release 的允许集合解析；普通 env／material 仍不能注入 image。快照、幂等和恢复包含镜像摘要 |
| E9 | 镜像停用／删除 | 停用禁止新采用；已有任务与可恢复引用保留原产物，原权限仍校验。被引用 digest 不得物理删除 |
| E10 | Manifest v2 解析器对部分未知字段可能宽松剥除 | 使用新增镜像字段的 Manifest 必须声明 crewstation/v3；新平台兼容原 v2，旧平台按 apiVersion 明确拒绝 v3，不让选择失效。Manifest 版本和业务 HTTP API v3 是两个独立版本维度 |

以上均需随完整方案评审。旧 Manifest 和不使用新字段的任务保留原行为；新增显式选择不能被旧平台静默忽略。

## 6. 验收标准

详细 RI-01～RI-28 见 [plan.md](./plan.md#3-验收清单)。必须实机证明：

- 服务、父任务和两种 Agent 分别运行不同的指定镜像；实际 imageID 对应各自固定摘要。
- 同一兼容镜像也可显式复用到父任务与 Agent，公共工具清单在这些目标上验证通过。
- pip／npm、本地模块导入、脚本、动态链接二进制和模板文件在实际执行用户下可用。
- 明确覆盖优先级和缺省回退；指定了错误镜像时报错，不丢弃选择。
- 发布回退、任务暂停恢复和子任务重试保持各自镜像；构建／初始化失败、取消和跨项目隔离可验证。
