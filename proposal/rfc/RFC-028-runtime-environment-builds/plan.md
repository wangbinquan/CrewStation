## 2. 并行工作与验证边界

开工已有 RFC-027 同主干在制实现及 tests/e2e/referenceResources.test.ts 改动，均不属于本任务。

- 设计阶段拥有本 RFC、ADR-0010、RFC 索引一行和 STATE 本段；共享文档只增补，不改他人段落。
- 实施热点包括 manifest/serviceSpec.ts、manifest/tasks.ts、业务 API、Runner、business-task 创建／启动／恢复、release pipeline、platform 和资源 Job。先核对最新接口与并行状态，冲突先协调，保留现有输出。
- 只在现有 main 开发；不建分支／worktree／临时克隆，不 stash，不写只读的 agent-workflow。
- 新模块用标准脚手架；迁移只追加并锁定；契约变更用能力影响表作为 contracts lock 的依据。
- 精确 staging，完整核对 index 与任务清单；不捎带其他任务文件。
- 定向测试先验证失败，再修改；完整候选门禁只跑一次并记内容指纹，无关 SHA 变化不触发重跑。
- 覆盖率预检只跑 unit/module/console 三层，不用连接共享集群的 test:cover；实机使用本任务专用项目、构建与工作卷。
- 不删除其他项目镜像／缓存／PVC 腾空间；记录并恢复本轮改变的验证配置。
