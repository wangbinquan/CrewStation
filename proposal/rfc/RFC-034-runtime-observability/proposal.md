# RFC-034：项目与系统两级运行观测与统计

- 状态：Draft，2026-09-28；本次仅交付全景设计与交互 Demo。
- 用户要求：CrewStation 同时具备项目层级和系统管理层级的运行观测与统计能力；2026-09-28 追加每种运行时的 Token 单价配置入口，所有费用显示人民币。
- 配套：[技术设计](./design.md) · [实施计划](./plan.md) · [Demo](./demo/README.md)。
- 取证基线：`d9d929df97f4d25ec4c7a25a3137c20335054d78`。以下引用是此基线的源码事实，不把设计目标当作已上线能力。

## 1. 产品目标与边界

项目负责人需要回答“本应用是否稳定、哪次任务慢、哪些 Agent 消耗最多、发布后有无退化”；系统管理员需要回答“哪些项目影响平台、资源是否够、哪类执行或驱动不可靠、平台成本与采集是否可信”。

两个层级共用执行身份、用量口径和查询合同，但有不同入口、默认指标与权限范围。项目页不是缩小版管理员大盘；管理员页也不是把项目卡片无限堆起来。

CrewStation 提供业务运行底座，不接管业务应用的 Agent 编排。对于托管在 CrewStation 上的 agent-workflow：AW 负责工作流节点、回合和业务依赖；CS 负责平台 task/subtask/attempt、执行环境、用量、资源与服务健康。通过相关 ID 联接，同一次模型消耗只记一次。没有应用声明的依赖时，不展示虚构关键路径。

## 3. 两级能力全景

| 能力 | 项目层级 | 系统管理层级 |
| --- | --- | --- |
| 总览 | 本项目业务运行、Agent Token、完成耗时、服务与资源异常 | 全平台请求/执行健康、项目影响、容量、成本与采集水位 |
| 运行任务 | 业务任务、开发会话、子任务/尝试；命令与 Agent 分开 | 跨项目定位，平台档位测试/构建单列，不混进业务成功率 |
| Agent | 当前任务贡献、跨任务累计、档位修订、重试/失败消耗 | 跨项目/档位/驱动/镜像版本比较，内部模型映射与费用 |
| 时间 | 业务完成时间、启动阶段、执行段、人工等待、容器保留时间 | 排队、调度、拉镜像、Runner 就绪、平台处理延迟和长连接质量 |
| 线上服务 | 请求/错误/延迟、正式/待验证版本、发布注记、维护窗口 | 平台 API、cs-session、controller、events、网关及依赖健康 |
| 资源 | 项目 CPU/内存/存储、申请与实际、额度占用及被拒原因 | 全集群容量、CS 项目/内置/其他占用；容量风险与共享开销 |
| 费用 | 默认展示 Token 和资源量；未开放费用时明确说明 | 模型费用估算、资源量、直接归属/共享未分摊分别列账 |
| 异常 | 失败、重试、人工等待、服务错误、数据缺失，关联诊断入口 | 跨项目影响、系统瓶颈、价格缺失、积压与采集故障 |
| 输出 | 权限内 CSV；单个任务与筛选结果口径一致 | 跨项目报表与审计留痕；不默认导出业务正文 |

## 4. 信息架构与用户路径

### 4.1 项目空间

在项目左栏“运行与诊断”相邻位置新增独立 **运行观测与统计**：数字人项目 `/projects/:id/observability`，管理员项目空间沿用既有 project-space 路径规则。接入项目同样支持服务与事件观测，没有 Agent 时显示“不适用”。

五个页签：

1. **总览**：业务成功率与样本数、已知 Token、完成耗时、服务健康摘要；趋势与异常支持下钻。
2. **任务执行**：按业务/开发、状态、Agent 档位、版本筛选；任务详情为独立 URL，含泳道、Agent 汇总、逐次执行。
3. **Agent 与 Token**：任务内及跨任务贡献、四桶消耗、重试、未归因用量；Agent 明细统一弹窗。
4. **服务与资源**：正式/待验证/开发明确分区；服务 RED、资源实际/申请/限制、配额与保留卷，关联发布版本。
5. **异常与数据质量**：异常记录、覆盖率、数据开始时间、过期/缺失/不支持及下一步定位入口。

既有运行与诊断继续承载形态、日志、告警、事件投递与调用链回放；通过 taskId/traceId/releaseId/resourceId 和时间窗口定位，共用 trace 查询与明细。统计首页不重复复制日志查看器，也不移除现有 URL 和权限。

### 4.2 系统管理空间

在“运行与观测”分组增加 **运行观测与统计** `/admin/observability`，与集群管理、业务运行和网关管理并列。

五个页签：

1. **平台总览**：项目影响清单、平台组件健康、任务吞吐/失败、已知 Token 和积压。业务和平台测试分母分开。
2. **项目对比**：项目种类、业务/开发消耗、耗时分位数与样本量、错误、额度占用、采集覆盖。按问题或消耗排序，点击进入同条件项目页，返回保留列表。
3. **容量与平台**：CPU/内存/存储、申请和实际、调度队列、Runner 连接、调和滞后、数据库与事件服务。全集群容量只读；受管对象操作仍去集群管理。
4. **Token 与成本**：项目/档位修订/驱动/内部模型/镜像维度；人民币价格版本、估算和实报，直接/共享/未定价分开；提供到算力档位 Token 成本的配置入口。
5. **异常与采集**：影响项目、开始/恢复、证据链接、采集积压/时钟偏差/事件缺口/价格缺失；异常记录不等同于通知。

上层管理员进入项目页后只看该项目视角的字段；跨项目统计与敏感费用留在系统页，避免复用 DTO 导致字段泄漏。

## 5. 任务执行与泳道

固定层级：项目 → 业务任务或开发会话 → 应用声明的阶段（可选）→ Agent/命令 → attempt → 模型/工具调用（按能力）。父任务容器和每个 Agent 独立 Pod 分行，并关联资源 UUID、Pod UID、镜像摘要与档位修订。

- 平台时间轴：受理、排队、调度、拉镜像、初始化、Runner 就绪、执行、暂停/恢复、清理、保留。
- 执行时间轴：Agent 活动、模型等待、工具、人工交互、失败/重试；没有调用级证据时只画执行段。
- 任务整体耗时、各 Agent 累计执行、父容器存活分别展示。业务结果完成后容器仍保留时，业务耗时不继续增长。
- 原生会话恢复保留 sessionKey；新执行尝试必须有独立 attempt/execution ID。回合、续聊、恢复和技术重试不能全算成 retry。
- 同一个 Agent 并行实例排子行。父轮廓条只表达包含关系，不能和子条求和。
- 点击短片段使用现有 Dialog；复杂任务用独立页；禁止在长列表底部追加详情。Esc/返回保持筛选、分页、滚动和焦点。
- 有因果边且时间覆盖完整才给关键路径；仅相同 traceId 不是依赖证明。应用上报语义标明来源。

## 6. 口径、权限与可信度

1. **计量实体**：模型 usage 只计一次。CS 执行、AW 节点、父任务汇总为多种视图，不是三笔费用。
2. **Token**：标准化为非缓存输入/缓存读/缓存写/输出四互斥桶；原始 input 包含缓存时由版本化 adapter 转换；reasoning 是输出子集。旧事实没有包含关系证据时保留 reported/legacy 状态，不硬相加。
3. **完整性**：complete/partial/pending/unsupported/unattributed/conflict 分开，已知下限用“≥”，未知“—”，采样范围旁显示覆盖率；零仅表示明确采集到零。
4. **窗口**：运行表按开始时间选生命周期样本；消耗趋势按 occurredAt 归桶，跨窗口累计修订没有调用时间时进“时间未分配”池，不按到达时间伪造历史。
5. **成功率**：同类终态成功/(成功+失败)，取消/中断/执行中单列；开发会话释放不等于业务成功；HTTP 2xx 不等于异步任务成功。
6. **延迟**：任务、请求、模型延迟各自分位数；不平均项目或每日 P95。低样本量明确提示。服务维护窗口标注，统计是否排除需显式切换，不能抹掉原始失败。
7. **资源**：CPU 实际核时积分、内存 GiB·h、PVC 申请与实际用量是不同指标。共享 PVC 按 UID 一次归属，不能被父子 Pod 重复累加；采集缺口不插值成零。
8. **成本**：模型直接成本和基础设施估算独立。共享成本默认不摊派；启用分摊须记录规则与版本。所有用户可见金额统一人民币（CNY），单价单位为元 / 百万 Token；未知价格不当免费；本功能不收费或自动停止任务。
9. **项目权限**：沿用项目 view；非成员遵循现有隐藏语义。平台普通 user 的市场使用权、preview tester 身份不能自动升级为开发工作台权限；以实际 owner 授权合同为准。
10. **系统权限**：系统聚合仅管理员可读。DTO 默认没有业务 Prompt、源码、工具参数、日志正文、凭据；项目看公开档位，采购模型和单价保持管理级。
11. **跨项目链路**：项目视图只含本项目片段；跨项目相同 traceId 不扩大查询权限。系统可展示有权限的关联摘要，不能把共享父链总额复制进每个项目。

## 6.1 Token 单价在哪里配置（本轮补充）

**主入口：系统管理 → 算力档位 → 选择档位 → Token 成本。** 观测统计的“Token 与成本”页增加“配置 Token 单价”，进入同一套配置；没有项目级重复价目表。由系统管理员维护，项目页面保持现有公开档位和用量边界。

现有 `ComputeProfileListItemSchema` 已包含 protocol/revision/model，但没有单价字段（`packages/contracts/api/compute/computeProfile.ts:152–169`）；编辑器已有运行协议与模型配置（`apps/console/src/features/admin/components/compute/ProfileBasicsSection.tsx:33`、`ProfileLaunchSection.tsx:54`）。因此此处是新增设计，不能告诉用户生产系统已经能配置。

价格记录关联 **档位ID/修订 + 运行协议 + 模型服务标识 + 模型ID + 价格版本**。运行镜像是执行环境，不是 Token 计价实体。同一 OpenCode / Claude Code 运行时可以访问不同模型、采购渠道或合同，所以不能只按运行时名称套一个全局价格。运行中切换模型必须上报真实模型标识，未匹配部分显示“未定价”。

配置字段：

| 字段 | 规则 |
| --- | --- |
| 算力档位、运行时、模型服务与模型 | 从档位修订固定读取，管理员可核对；凭据不进入价格表 |
| 币种 / 单位 | 固定人民币 CNY，元 / 百万 Token |
| 非缓存输入、缓存读取、缓存写入、输出单价 | 四项独立，最多6位小数；空值是未配置，0须明确代表免费；不使用输出子集reasoning重复收费 |
| 生效时间 | 明确显示时区；发布新版本只影响之后新受理的执行 |
| 版本与来源 | 版本号、采购依据、维护人、变更时间；可读历史、禁止覆盖历史价格 |

费用 =（非缓存输入 × 输入价 + 缓存读 × 读价 + 缓存写 × 写价 + 输出 × 输出价）/ 1,000,000，界面以“¥”和“人民币”标明，按实际需要保留到6位小数；极小非零值显示下限提示，不能四舍五入成免费。

管理员直接维护人民币采购单价。若采购依据采用外币，应记录折算依据与日期后形成CNY价格版本，不能把外币数值仅替换货币符号；缺少人民币定价时统计显示“未定价”，不擅用实时汇率补算。固定订阅费用另列，不把套餐费推成每Token精确单价。

新价使用独立版本，不触发运行参数修订、镜像重建、模型测试或任务重启。执行受理时绑定价格快照，历史与正在执行的尝试保留原价；修正历史应走有影响范围和审计记录的独立重算流程。本次原型展示新价“待生效”和旧价历史，不实际推进时钟。

Demo 增加[人民币单价配置页](http://127.0.0.1:48372/?scope=admin&page=pricing)，OpenCode / Claude Code 两行对应不同档位与模型，Terminal 示例明确“不支持计量”。四桶费率均为新填写的人民币虚构值，不代表真实供应商价格，也不是汇率换算结果。

## 7. 业界参考

查阅于 2026-09-28，借鉴产品组织与可信度设计，不要求接入外部 SaaS。

- [Datadog Agent Observability](https://docs.datadoghq.com/llm_observability/)：将执行追踪、用量、延迟和错误串联；CS 扩展为项目 → 执行 → 资源的定位路径。
- [Datadog Cost](https://docs.datadoghq.com/llm_observability/investigate/cost/)：调用与应用聚合、费用估算及部分费用提示；CS 明确项目公开用量与管理员采购价格的边界。
- [Grafana Kubernetes Monitoring](https://grafana.com/products/cloud/kubernetes/)：实际使用与 requests/limits 对照、资源归因、指标/日志关联；CS 复用 RFC-015，不再建第二套集群采集。
- [OpenTelemetry Signals](https://opentelemetry.io/docs/concepts/signals/)：指标、链路、日志使用关联上下文；CS 的平台 traceId 与 OTel trace ID 分字段记录，绝不互相冒充。
- 前序 AW RFC-371 的分层用量与泳道模式仅作参考；CS 的双层权限、平台资源、服务运行与契约边界独立设计。

## 8. 分阶段与验收

| 阶段 | 内容 | 退出条件 |
| --- | --- | --- |
| P0 | 采集能力矩阵、身份关联、用量账本、授权投影、水位与历史 legacy 标记 | 固定驱动/Runner 协议样本；重复、乱序、恢复、跨项目不串账 |
| P1 | 两级入口、任务/Agent/项目聚合、基本泳道、现有资源指标关联 | 项目单任务 → 项目汇总 → 系统汇总逐层一致；不扩大项目权限 |
| P2 | 网关 RED、平台健康、价格版本、启动阶段/调用片段、异常记录 | 各指标有来源、窗口、覆盖率与归因证据；保留 D61 |
| P3 | 应用自定义业务结果/因果边、长期趋势与 SLO、受控 OTel 接入 | 独立合同、采样/保留/容量预算和完整准入证据 |

告警通知、自动停任务、自动扩缩、跨项目数据共享、账单结算均不在当前实施范围；新增需单独提出行为变更。

验收 PO-01 两级路由与权限；PO-02 任务/Agent/attempt 与四桶对账；PO-03 同 trace 多项目隔离；PO-04 重放/恢复/父子无重复；PO-05 容器时长与业务完成分开；PO-06 旧驱动/CLI/无模型任务明确降级；PO-07 发布角色切换不重标历史；PO-08 系统分位数与错误率原始分母；PO-09 CPU/PVC/共享成本不重复；PO-10 缺失/未定价/维护/采集延迟明确；PO-11 长列表末行详情与返回上下文；PO-12 桌面/窄屏/键盘/双语/主题；PO-13 分阶段实机和精确 SHA CI。

本次 Demo 是设计证据，不作为上述生产能力已经实现或权限已经生效的证明。
