# RFC-034｜旧报告链接失效时恢复当前统计

本片是已批准运行观测页面的错误恢复修复，两个 RFC 仍 In Progress。2026-10-09 实际管理员项目页打开旧 `reportId=01a118ca-f91f-7001-8a36-165ffff356aa` 返回404；通过原时间范围重新查询，原 A 的63921四桶与验收人民币 ¥0.066516仍在。报告链接失效与原始用量丢失必须区分。

## 现状与修复范围

`apps/console/src/features/observability/pages/RuntimeStatisticsPage.tsx:34` 与 `:46` 用原 `reportId` 读取封存报告；错误使内容隐藏。`hooks/useRuntimeReport.ts:12` 的 pinned 分支只读状态，不会自行创建另一份报告。总览当前需调整时间才能清除编号；任务详情没有同等恢复入口。

只在明确带原报告编号、实际 `ApiClientError` 的404／`not_found`旁显示公共小按钮“重新统计”。使用原页面的 `go` 去掉唯一 `reportId`；保留原项目／系统／接入管理空间、原任务、from/to完整精度、页签与全部筛选。当前范围使用原完整报告链，保留原30秒自动查询及 asOf；若已有该范围的有效缓存，继续使用其真实快照，不宣称重新生成相同的历史封存报告。

401／403、网络／5xx、未带原报告编号的任务不存在继续显示原错误，不提供这个恢复动作，不自动重复 POST，不扩大可见范围。旧报告和查询缓存不被删除或改写。此入口不是普遍刷新按钮，也不新增筛选、CSV或关注任务卡片。
