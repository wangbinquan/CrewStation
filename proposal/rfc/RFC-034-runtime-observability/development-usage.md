# RFC-034 开发执行用量接入

状态：首批身份/账本兼容设计及实现经独立只读功能门 PASS，完整候选门禁通过（4191 pass／142 skip／0 fail，静态全绿）；沿用已批准的 RFC-034 开发来源范围。本文不代表开发 Token 已采集。取消 CSV、异步 CSV 和额外筛选折叠入口的用户决定继续生效。

## 1. 现状与目标

正式项目与系统统计由 `platform/wiring.ts` 注入业务任务事实与业务数值 outbox，`runtimeStatistics.sourceScope` 因而明确为 `business-tasks`。开发 Agent 受理记录已固定父工作区、Agent、执行环境与算力修订；CLI 同样有持久受理记录，但普通 Agent 事件和 CLI 活动不是完整、可确认的数值来源。不能给开发行补零，也不能把工作区存活时间当成模型执行时间。

用户应能从项目总量看到业务任务、开发 Agent、开发 CLI 的各自贡献，再按算力名称与受理修订查看具体执行、四个 Token 桶和人民币费用；系统总览按相同账本跨项目汇总。平台档位测试单列，仍属后续接入范围，不塞进任意项目。

## 2. 身份与账本边界

保留托管 AW 的公开 `ExecutionObservationIdentity`、`ExecutionObservationPage` v1 和既有业务记录字节形状。新增内部 `UsageExecutionIdentity`：

- 业务分支原样接受 `{ projectId, taskId, subtaskId, executionId, executionGeneration }`，不补默认字段，既有哈希与计价键保持不变。
- 开发分支为 `{ sourceKind: development-agent | development-cli, projectId, taskId, agentId, executionId, executionGeneration }`。`taskId` 是真实父工作区，`executionId` 是真实独立执行环境 UUID，`agentId` 是原受理 ID。没有 `subtaskId`；严格 schema 拒绝混合身份。
- 内部用量、估值、原生采集证明共用此身份 union；只替换身份 schema，继承全部四桶、范围、修订和完整性约束。对外业务 v1 仍只接受原业务身份，不能因为内部扩展静默扩大 HTTP 合同。
- 原生沿革按真实工作区及原生持久来源固定。工作区账本容纳多个开发执行，恢复基线与迟到修订仍回到原执行，而不算给当前新执行。发生身份、沿革或顺序缺口时显示部分/未知。
- 执行价格仍由 `(executionId, executionGeneration)` 唯一绑定，并核对完整身份。受理档位、修订、价格目录水位只接受一次；新价格、重放、重启均不重新定价。

首批只扩展内部账本与计价身份，不启用新生产来源、不改变统计的 `business-tasks` 能力声明。这是后续持久采集接线的前置条件，不作为开发用量完成验收。

## 3. 开发受理、数值持久化与恢复

`dev-session` 持有开发归属。受理记录固定项目、父工作区、执行环境、Agent/terminal、档位修订与受理时间；首次模型调用前通过 platform 注入的价格受理端口冻结 CNY 目录。历史缺少受理快照的执行保留未定价，不套当前目录。

headless 的数值开关与 `businessEvents` 分离，保留现有交互和流式行为。Runner 为开发数值提供独立版本协商、私有持久日志和连续水位；普通会话 WebSocket 的内存 replay buffer 不作为数值完成证明。意图和初始基线先落盘再启动模型，末次采集先落盘再发布结束证明。数值事件不因大量文本/PTY 输出被驱逐。

Session 在接收事务中保存独立数值副本与连续持久水位，之后才确认 Runner。消费者公平轮询，各次已提供页固定结束水位，丢 ACK 重放同一页；账本摄取及该页估值提交后再 ACK outbox。重复、乱序、同版冲突、代次变更和磁盘失败有明确结果。开发环境清理必须先排空最终已证明水位；不能通过读到普通 terminal/completed 事件就提前回收。

在没有能力的新旧混合部署中继续原开发工作，观测显示不支持/未知。不能仅发送未知字段后就把采集能力标成完整。部署顺序为 Session/控制面，具备私有持久路径的 Runner，再启用受理能力；已固定旧镜像的执行不被自动重建。

## 4. CLI 与原生基线

OpenCode CLI 通过驱动的原生数值适配器读取实际环境对应的持久来源；必须在原生轮次执行前完成基线边界，结束后分页读取根/子会话并提交最终证明。原生会话切换生成独立沿革，resume 的 100→130 仅归入新增 30；旧步骤 10→15 的修订按已证明的原归属和原价处理。无法证明前置基线时标明缺口，不倒推历史。

Claude 只接受其实际原生数值证据；配置模型与心跳都不能替代实际 provider/model。provider 缺失可显示已知 Token、人民币仍未定价。通用 terminal 协议明确不支持模型计量。CLI 采集必须独立验证，不能用 headless 夹具代替。

## 5. 查询与界面

观测模块不得联查其他模块私表。task-runtime 提供有界环境事实，dev-session 提供受理与执行事实，经 platform 在同一 repeatable-read 快照装配。每条开发运行记录以独立执行环境为详情 ID，另带真实工作区 ID；读取账本时使用父工作区范围，再按完整执行身份选择贡献，避免同工作区其他执行被重复计算。

时间窗口中业务任务沿用创建 cohort；开发记录按执行受理时间进入 cohort，即使父工作区很早创建也能被查到。页面明确区分来源并提供直接可见的用途选择；开发运行与业务成功率分开，默认总 Token 只加互斥贡献。算力弹窗列出来源、项目/工作区、具体执行和各自消耗。新事实接通前继续显示当前能力范围。

时间轴分别保留受理、排队/准备、进程生命期、真实轮次执行和等待；只在真实成对时间证据存在时汇总活跃时间。1 小时驻留、两次 10 秒轮次应显示 20 秒累计执行，未知片段不插补为连续运行。工作区与容器资源生命周期是独立信息。

## 6. 落位、分批与验证

不新增模块或架构例外。合同落在 `packages/contracts`；账本、冻结价格和投影沿用 `modules/observability` 现有文件；受理归属在 `modules/dev-session`，环境查询在 `modules/task-runtime`，数值 outbox 在 `modules/session`，跨 owner 装配只在 `modules/platform`。Runner 和驱动分别负责本地持久传输及真实原生适配。

1. 内部身份/账本/冻结计价兼容增量：验证业务 v1 不变、开发身份不伪造 subtask、两个开发执行独立估值、历史修订归属、重放不增量、不支持身份拒绝。保持生产来源关闭。
2. headless 受理、Runner 数值日志、Session outbox、owner 查询与正式两级下钻同时接通；覆盖重复/乱序/重启/丢 ACK/最终多页/清理屏障/旧 Runner，实际驱动回归不能只测 DTO。
3. CLI 前置基线及轮次、原生会话切换、历史修订、真实活跃时间；同算力多 Agent、跨算力修订及开发/业务合计对账。
4. 平台档位测试单列、真实模型与两级实机验收、精确 SHA CI 和本机升级回执，之后才能关闭开发来源项目。

后续 Runner/CLI 设计须单独经过功能门，本文概述不作为已通过证明。每批独立功能复核、适当定向检查，再对冻结候选仅运行一次完整本地门禁，精确路径提交/推送并核对 hosted CI。正式页面验收继续采用公共 Card/Stack/ActionRow/DataTable/Dialog，检验宽窄屏、名称、金额可见性、焦点与返回上下文，不恢复 CSV。
