## 已写入候选的接线

1. 新 OpenCode headless 受理默认启用 native v2 数值接线，保持原档位、原价、原受理身份。仅自动选择、且独立证明旧 Runner 不支持时保留 legacy 运行和用量未知；已观察到数字布局／journal 能力后不降级。旧执行不补写新选择。
2. 平台算力测试使用独立 `profile-test` 身份，受理冻结人民币价簿，初始模型轮次与后续业务能力探测均接可靠 journal。数值来源以实际 runtimeTaskId、executionId、attempt、incarnation、payloadDigest 固定归属；数值、游标和重放证明提交后才 ACK。既有 Session 数值来源公平轮询复用，不把平台用途塞进业务项目。
3. 各正式 Hono 进程采集实际请求 counter、可合并延迟桶和 SSE 生命周期。Prometheus 按实际 Pod 抓取；网关保留物理 Service 标签。项目入口先鉴权再读项目 namespace，系统入口限管理员。采样边界、无样本、来源停止、精度和高延迟尾部仍标为缺口；这些样本不冒充完整 Token 账本。
4. 原提交事务写入按任务合并的 dirty queue。后台一次历史人口 bootstrap 后，只对受影响任务读取真实原来源到 EOF，取得规范分配结果。资格文件在原读连接释放后才上传，避免单连接数据库内自等待；内容计数与摘要在真实文件 EOF 核对。源码接线覆盖重放、失败、较新 dirty 覆盖旧资格、旧数字保留及项目删除清理。
5. 同一份任务分配结果进入项目／系统共享 UTC 日期桶。修订在同一事务扣除旧成员、再加入新成员；任务出生日期更正、四类 Token、原价小计和缺口引用计数一起修正。7 天／30 天完整中间日期复用这些桶；自定义窗口两侧残段读既有任务 fold，含搜索／状态／质量的筛选退到规范 fold，不重开原生文件或重做 Token 分配。
6. 正式页接小型汇总读取与真实投影版本 SSE。普通新数据只刷新汇总；整份明细保留原页面快照，由明确的“更新任务明细”更新。默认／预设周期滚动更新截止时刻；自定义周期保持原范围。来源刷新不重置用户正在编辑的时间字段，进入任务并返回仍使用该明细实际范围、分页、滚动和焦点。

## 精度与资格

输入、缓存读取、缓存写入、输出是四个不相交桶；数值和人民币 picos 均用精确十进制／BigInt，不将大整数压成 JS 浮点。人民币费率沿用算力档位入口的 CNY／百万 Token；受理价簿为空保持未定价，不能借后续新费率追改原快照。

投影待更新与原模型用量缺口分别保留。已有分类数字和已记录人民币金额不因 pending 清空；未取得真正来源 EOF、完整采集证明或定价资格时不声明完整数字。传输 page size、调度 packet 和图表分辨率不限制人口。
