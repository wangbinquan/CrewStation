# RFC-034 v2：运行观测精简重设计（2026-10-14）

> 状态：In Progress。作者 2026-10-14 要求「看 agent-workflow 怎么实现，审视 CS 的实现逻辑，重新设计并重构，目标高效、能力统一、能力完备」，并在同日逐项确认：断代、不迁移 v1 已采集数据；原 RFC-034 会话已停，v2 直接替换其代码（含未提交的可空 CLI 受理改动）；按 §10 能力影响清单收缩。本文取代 [design.md](./design.md) 与其后全部补充文档里的**实现**设计；[proposal.md](./proposal.md) 的产品定位、统计口径（§6）与人民币规则（§6.1）继续有效。对等的 agent-workflow 设计见该仓 `design/RFC-371-run-observability/redesign-v2-20261014.md`，本文与其保持同一数据模型与口径。

## 1. 为什么重做

v1 的口径是对的，实现代价与 agent-workflow RFC-371 v1 同源（2026-10-14 实测）：

- observability 模块 287 个文件 / 1.69 万行，44 个迁移建 87 张表（账本、修订、投影、完整报告、报告缓存、小时/日汇总、异常、存储维护、估值修订、价簿修订、平台用量折叠……），另有 session 的数值外发箱、Runner 里的原生分页采集与回执、platform 组合根里直接读他模块表的报告读取器。自 9/27 起观测相关提交约 9.6 万行，文档 87 篇。
- 仍未闭环：默认开发采集 producer 关闭，CLI、档位测试、托管 AW 联动、性能与界面矩阵均开放；本机 30 天正式页只有 51 次执行。
- Runner 协议为观测增加了 `usageObservationsV1`、`nativeUsageTreeV1`、`nativeUsageLineageKey`、`developmentUsage` 受理与一整套 `DevelopmentUsage*` 命令，业务执行也要协商这些能力。
- 页面 7 个页签、16 种运行状态、reportId 固定报告与「重建」按钮，文案偏实现术语。

v2 原则与 agent-workflow 一致：**一次 Agent 执行一行，原地更新；按实际模型拆分的可替换快照；统计按需聚合，不建派生表；跨模块只走端口。**

## 3. 数据模型（observability schema，四张表）

### 3.1 `observability.agent_calls` — 每次 Agent 执行一行

| 列 | 说明 |
| --- | --- |
| `id` uuid | 受理时生成（UUIDv7） |
| `project_id` uuid null | 档位测试等平台执行可以不属于项目 |
| `source` | `business`（业务子任务）/ `development`（开发 Agent 与「＋ CLI」）/ `platform`（档位测试等平台自身执行） |
| `kind` | `subtask` / `agent` / `cli` / `profile-test` |
| `task_id` / `task_label` | 业务任务、开发会话或档位测试的 ID 与受理时的展示名 |
| `subtask_id` / `attempt` | 业务子任务与尝试序号 |
| `runtime_task_id` / `agent_id` | Runner 寻址：执行环境任务 ID 与 Agent ID；同一组合同时最多一行 `running`（部分唯一索引） |
| `agent_key` / `agent_label` | 稳定逻辑 Agent（业务 agentProfile、开发 Agent 名）与展示名快照 |
| `profile_id` / `profile_revision` / `profile_name` / `protocol` | 受理时固定的算力档位与协议 |
| `status` | `running` / `done` / `failed` / `canceled` / `interrupted` |
| `started_at` / `ended_at` / `updated_at` | timestamptz |
| `usage_state` | `pending` / `partial` / `complete` / `none`（与 AW 同义：未知不是 0） |
| 五个 Token 列 | 非缓存输入、缓存读、缓存写、输出（含推理）、推理（输出子集） |
| `cost_nano` / `cost_state` | 人民币纳元整数；`none` / `priced` / `partial` / `unpriced` |

索引：`(started_at)`、`(project_id, started_at)`、`(task_id, started_at)`、`(runtime_task_id, agent_id) WHERE status='running'` 唯一。

### 3.2 `observability.agent_call_models`

主键 `(call_id, model)`，级联删除；`model` 为运行时报告的实际模型（OpenCode `provider/model`，Claude 模型名，空串为未归属）；五个 Token 列、`price_id`、`cost_nano`（null 为未定价）、`cost_state`。每次快照整组替换（同事务先删后插）。

### 3.3 `observability.price_versions` — 只追加

`(profile_id, model)` 一条价格线；四项费率为人民币微元 / 百万 Token 的整数，null 为未知（不是免费）；`effective_from`、`created_at`、`created_by`、`note`。选择规则与 AW 相同：调用采用 `effective_from ≤ started_at` 且 `created_at ≤ started_at` 中 `(effective_from, created_at)` 最大的版本，新价只影响之后受理的执行；保存以 `expectedLatestId` 做 CAS，冲突 409 保留草稿。没有档位的平台执行以 `builtin:<protocol>` 为键（与 AW 相同）。

### 3.4 `observability.project_cost_visibility`

`project_id` 主键、`visible` 布尔、`updated_at`、`updated_by`。默认（无行）为不可见：项目页与项目成员看不到人民币，系统页始终可见。管理员在价格配置页按项目开关。

计价：`cost_nano = round(tokens × rate_micro / 1000)`，按桶 BigInt 求和；展示最多 6 位小数，非零但小于 ¥0.000001 显示「< ¥0.000001」，未定价显示「未定价」。

## 4. 写入链路

```text
派发前   owner 受理端口 accept()              owner（business-task / dev-session / task-runtime）插入 running 行；失败则不派发，下一轮调和重试
运行中   Runner 计量器 observe()             驱动内存合并；变化后 ≤3 秒发一次 usage 事件（快照整份替换）
每轮末   OpenCode 原生会话树汇总              有界只读一次，替换为含子 Agent 的按模型结果
结束前   最终快照                            Agent 终态事件之前发出
session  AgentCallSink                       usage → 原地更新（按 runtime_task_id + agent_id 定位 running 行）；终态事件 → 写终态
结束     owner fail() / 环境释放兜底          开发派发被定性拒绝时 owner 补写失败；执行环境释放事件把其中仍在运行的执行记为中断（幂等）
```

- **计量器与 agent-workflow 同算法**：OpenCode stdout 只有根会话的 `step_finish`，按 part id 去重累加，见到 `task` 工具（子 Agent）即为 partial；每轮结束后在 Agent 的私有数据目录只读汇总根会话沿 `parent_id` 递归（深度 ≤8、≤500 个会话）、`time_created ≥ 执行开始` 的 `step-finish`，按 assistant message 的 `providerID/modelID` 分组，输出加回推理（依据：opencode `packages/opencode/src/session/session.ts` 的 `getUsage` 把推理从输出中扣除，`processor.ts` 在 `step-finish` 落 tokens）。Claude 按 assistant message id 去重累加，`result.modelUsage`（含子 Agent）替换为 complete；恢复会话保留 assistant 合计为 partial，`error_during_execution` 的全零不覆盖已知值。
- **「＋ CLI」终端**：TUI 不产生结构化输出。终端 Agent 使用每次执行私有的 HOME / 数据目录，Runner 每 10 秒及退出时读该目录下的原生存储：OpenCode 汇总 `time_created ≥ 执行开始` 的全部 `step-finish`；Claude 累加已接入的 OTel 日志 `api_request`（每次模型请求一条、含子 Agent，按（会话, 事件序号）去重以吸收导出重试；遥测有缺口时为 partial）。读不到即保持上一份快照（无快照时为 `none`）。通用终端协议没有计量来源，用量未知。
- **外部取消 / 中断**：终态为 `canceled` / `interrupted` 时把 complete 快照记为 partial（进程可能停在一次请求中途，运行时只在请求完成后记账）。
- **业务事件**：Runner 发给业务应用的 `usage` 业务事件改为每份执行快照一条：`scope` = 执行 ID、`mode=cumulative`、四个总量字段为各模型合计，`complete` = 快照完整，新增可选 `snapshot` 携带按模型明细与推理。托管 agent-workflow 直接据此记它自己的调用（RFC-370 v2 执行端口的 usage 事件），不再需要 `/v3/business-tasks/:id/observations` 同步接口。
- 写入失败不影响执行（受理失败除外）。同一执行的写入在 observability 内按调用串行，晚到的中间快照不会覆盖终态。

## 5. 读取：按需聚合

所有统计在请求时对 `agent_calls` / `agent_call_models` 做窗口过滤 + `GROUP BY`，走 `(started_at)`、`(project_id, started_at)` 索引；没有缓存、投影、水位或报告。页面打开即为当前数据，运行中每 30 秒自动刷新。

| 接口（项目 `/v1/projects/:projectId/observability/…`，系统 `/v1/admin/observability/…`） | 口径 |
| --- | --- |
| `overview` | 执行按开始时间落在 `[from,to)`：Token 四桶与人民币、业务 / 开发 / 平台拆分、连续日桶、执行状态计数、执行时长 P50/P95、Token 最多的任务与 Agent（系统页另含项目） |
| `tasks`、`tasks/:taskId` | 按任务汇总（来源、展示名、首末时间、执行数、Token、人民币），关键词 / 来源 / 状态筛选、键集分页；任务详情为执行泳道 + 执行表 |
| `agents`、`models` | 窗口内按 Agent 汇总；按档位 × 实际模型汇总并标出未定价 |
| `projects`（仅系统） | 按项目比较消耗，点进同窗口的项目页 |
| `platform`（仅系统） | 不属于项目的平台执行（档位测试等），按类别与最近执行 |
| `pricing`、`pricing/:profileId/history?model=`、`POST pricing/:profileId` | 价格目录（档位 × 配置模型与实际出现过的模型）、单条历史、新增版本（CAS） |
| `projects/:projectId/cost-visibility`（GET / PUT） | 项目费用可见性 |

**权限**：项目接口先按项目 view 授权（`ProjectAuthorizer`）再聚合，只看 `project_id = :projectId` 的行；项目页的人民币字段由项目费用可见性决定（管理员进入项目页同样遵守）。系统接口仅管理员，金额始终可见。价格与可见性写入仅管理员。上限：任务页每页 25、任务详情执行 ≤2000（超出标截断）、Agent 200、模型 500、项目 500。

## 6. 界面

项目「运行观测与统计」与系统「运行观测与统计」共用组件。顶部：时间范围（近 24 小时 / 7 天 / 30 天，`Segmented`，写入地址的 `period`，默认近 7 天）；页面每 30 秒在原位自动刷新，按工作台 2026-09-23 裁定不设刷新按钮。页签：

1. **总览**：Token 消耗（四桶）、人民币估值、执行情况（完成 / 失败 / 取消 / 中断 / 进行中）、执行时长 P50/P95 四张卡；按天堆叠柱图；来源拆分；Token 最多的任务、Agent（系统页加项目）。
2. **任务**：任务表 → 任务详情独立路由（执行泳道复用既有时间轴组件，按 Agent / 尝试分行，执行表四类 Token 分列）。
3. **Agent 与模型**：Agent 表、档位 × 模型表；未定价行在系统页提供「配置价格」入口。
4. **项目**（仅系统）/ **平台执行**（仅系统）。
5. **资源**、**健康**：保留现有实现（集群指标与 Prometheus 运行遥测、告警），不属于本次 Token 统计改造。

价格：系统管理 → 算力档位 → Token 成本，每个档位列出配置模型与实际出现过的模型，各自配置价格、查看历史；项目费用可见性在同页按项目开关。全部复用 `Card`、`Tabs`、`Segmented`、`DataTable`、`FormDialog`、`Dialog`、`EmptyState`、`QueryStatus`、`PageHeader`。

## 7. 迁移（断代）

- observability：新迁移退役 v1 的全部 RFC-034 表（账本、投影、报告、估值、价格、可见性、平台用量、开发原生表、异常、维护、存储、汇总……，以及它们的触发器 / 函数），建 §3 四张表；alerts、traces 等 RFC-034 之前的表保留。v1 数据与价格不迁移（作者确认断代）。
- session：退役业务数值外发箱与开发用量接收表；dev-session：退役开发用量 owner 表；其他模块的 RFC-034 附加表一并退役。
- 已应用的迁移文件一字不改，新迁移追加并登记迁移锁。

## 8. 测试策略

- 领域：快照合并（去重、推理子集、未知 ≠ 0）、计价（整数纳元、部分定价、未归属、内置价格线）、价格选择（生效 / 创建时间、回填不改历史）、取消 / 中断下界、分位数与连续日桶。
- 驱动：OpenCode 流合并与 `task` → partial；原生存储夹具（根 + 多层子会话、时间下界、读失败回退、私有目录缺失）；Claude assistant 分片去重、`modelUsage` 替换、恢复调用 partial、`error_during_execution`；终端周期读取。
- 模块（真实 PostgreSQL）：受理 / 原地更新 / 结束 / owner 补写终态、同 Agent 只一行 running、模型行整组替换、价格 CAS、项目与系统聚合、窗口 / 分页 / 上限、项目授权与费用可见性。
- 接线：业务子任务、开发 Agent、「＋ CLI」、档位测试各自受理先于派发；session 收到快照与终态后转交；业务 `usage` 事件携带快照且旧字段仍为合计。
- 工作台：两级四个页签、任务详情、未定价 / partial 展示、价格编辑 CAS 冲突、项目费用可见性开关、长列表末行详情为独立路由、窄屏与双语。
- 实机：本机集群跑业务子任务、开发 Agent、「＋ CLI」与档位测试，逐条与原生存储对账。

## 9. 与 agent-workflow 的统一

| 方面 | 两边一致的做法 |
| --- | --- |
| 计量单位 | 一次 Agent 进程（CS 为一次 Agent 执行）一行，按实际模型拆分的可替换快照 |
| 口径 | 四桶互斥、推理是输出子集；`pending` / `partial` / `complete` / `none`；未知不是 0；取消 / 中断为下界 |
| 计量算法 | 同一份 OpenCode / Claude 计量规则（流 + 原生树汇总、assistant/result） |
| 价格 | 只追加的人民币价格线（AW：运行时注册 × 模型；CS：算力档位 × 模型；无注册 / 无档位为 `builtin:<protocol>`），按开始时间冻结 |
| 读取 | 窗口过滤 + GROUP BY，无派生表 |
| 托管 | CS 业务 `usage` 事件携带同形快照，托管 AW 直接记入自己的调用 |

## 10. 能力影响清单（作者 2026-10-14 逐项确认收缩）

| v1 能力 | v2 处理 |
| --- | --- |
| 完整报告、reportId 固定报告、报告重建 / 恢复 | 删除；按需聚合 + 30 秒刷新 |
| 增量投影、小时 / 日汇总、发生时间表、固定视图 | 删除 |
| 异常与采集质量页签、异常生命周期 | 删除（服务告警仍在健康页签） |
| 存储保留与维护操作 | 删除 |
| 数值账本修订、证明、原生基线、开发原生分页回执 | 删除；每次执行一份可替换快照 + `partial/complete` |
| 估值修订、价簿修订、执行价格快照与更正 | 删除；价格按开始时间从只追加的价格线选择，计价写在调用行 |
| AW 执行观测同步接口（`/v3/business-tasks/:id/observations` V1/V2） | 删除；改由业务 `usage` 事件携带快照 |
| 16 种运行状态、阶段时间轴、应用信号 | 收为 5 种执行状态；泳道粒度为执行 |
| v1 已采集的执行、用量、估值与价格 | 不迁移（断代） |
| Runner 协议的用量能力协商与 `DevelopmentUsage*` 命令 | 删除；统一为 `usage` 事件快照 |

保留：项目 / 系统两级入口、业务 / 开发 Agent / 开发 CLI / 档位测试四类来源、任务 / Agent / 模型 / 档位分解、执行泳道、价格版本与历史、项目费用可见性、资源与健康页签。
