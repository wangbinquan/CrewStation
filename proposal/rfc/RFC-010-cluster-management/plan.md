## 1. 分工与依赖

调研开始时 RFC-008 的正常／拒绝连接状态与保卷恢复、RFC-009 的管理项目导航与共享 UI 正在同一 main 工作树修改。
本轮方案收口时索引已记录 RFC-008 Done，RFC-009 的生产实现已发布但仍有验收欠证；用例防护体系另有并行在制品。
本 RFC 设计阶段只新增本目录和 ADR，给索引／STATE 追加自己的记录；不碰上述生产在制品。
获批实现后先重读它们的最终内容，协同共享路由、平台装配与 task-runtime 生命周期的文件改动。
依赖为 T1 → T2 → T3／T4 → T5 → T6／T7／T8 → T9 → T10 → T11；这是技术依赖，不是子 Agent 派工授权。

## 3. 验收清单

下表定义验收标准；各项实际结果和证据由 [acceptance.md](./acceptance.md) 单独维护，模块测试与真实集群验收不混记。

| 编号 | 检查与通过标准 |
|---|---|
| CM-01 | 平台管理员进入集群页；普通成员直达 UI／HTTP 均被正确拒绝，保留返回路径 |
| CM-02 | 三种项目资源、平台全部实际内置组件可见，kube-system／外部未受管对象不在清单和数量中 |
| CM-03 | 没有 managed-by 的旧系统 Service／PVC 等通过目录或有效引用仍可见；同 namespace 外部对象不被误认领 |
| CM-04 | 每项显示具体项目或系统；归档残留、缺失项目、标签冲突显示真实说明与动作限制 |
| CM-05 | 父工作区、CLI、开发 Agent、业务工作区、子任务、档位测试分别分类；同名新 Pod 不沿用旧任务归属 |
| CM-06 | 构建／迁移、数字人／两种接入项目用途正确，物理槽与正式／试用角色随切流更新 |
| CM-07 | 控制器去重、CronJob／Job、独立 Pod、终态 Job／Pod 的数量与源对象 UID 集合一致 |
| CM-08 | Running 与 Ready 区分；Pending、OOMKilled、CrashLoopBackOff、ImagePullBackOff、退出码与调度消息真实显示 |
| CM-09 | Service／PVC／配置／命名空间完整覆盖；数据正文与日志容量按设计边界展示 |
| CM-10 | 跨页数量不等于当前页条数；continue／410／部分失败／不支持 API／0 各自正确；过滤和游标绑定同一快照 |
| CM-11 | 多浏览器共用采集结果，手动刷新合并；采集取消和超时有界；没有逐 Pod／逐项目查询风暴 |
| CM-12 | 项目、类型、用途、状态筛选、URL 定位与浏览器返回；旧响应不覆盖新筛选 |
| CM-13 | 拥有者链、关联 Pod／卷、容器、事件、当前与 previous 日志可查；无日志或对象已删除时原因可见 |
| CM-14 | 专用项目 Deployment 重启后同一发布／配置、旧新 Pod UID 与 Ready 证据齐；不误重启同名新 workload |
| CM-15 | 扩缩副本实际收敛、遵守套餐，覆盖在后续发布保留，恢复发布配置生效；切流／发布冲突重新检查 |
| CM-16 | 正常开发工作区保卷重启：taskId、PVC UID、工作树保持，子执行与配额正确，Runner 重新连接 |
| CM-17 | 单 CLI／Agent 重启／结束只影响选定执行，父卷及其他窗口保持，新旧 ID 可追踪 |
| CM-18 | 业务任务／子任务与档位测试经所属流程停止或恢复，调用方与测试记录收到真实终态；不重放已成功业务 |

## 4. 验收环境与完成条件

实现阶段建立专用验收项目与受管演示资源；使用已确认的管理员视角，记录 context、namespace、UID、operationId、
HTTP 状态、traceId、耗时及操作前后证据。生命周期测试要核对数据库状态、实际 Pod／PVC 与配额，而非只看 DOM。
系统核心组件的真实中断会影响其他会话，执行前完成具体目标与窗口协调；不把 UI 操作许可视为可随意中断正在工作的共享平台。
不修改已有 demo 或 RFC-008／009 的验收资源来制造测试条件。

门禁按冻结的本任务候选内容执行，先检查共享树是否已有同等全量 gate；不启动重复任务争抢资源。
只读方案阶段做文档引用和预览行为验证，不启动生产全量测试，也不声称 CI 已通过。
Git 发布使用精确路径与共享索引临界区，保留并发文件，提交署名真实，发布后记录远端 SHA 与终态 CI。
RFC 只有代码、CM 清单、实机证据及发布收口完成才标 Done；无法实机完成的项目说明范围并请作者裁定。
