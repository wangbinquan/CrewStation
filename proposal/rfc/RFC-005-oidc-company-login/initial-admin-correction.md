# RFC-005｜首次管理员交接修正

> 2026-09-20 · 作者直接要求「搬迁 agent-workflow 的模式，首次直接要求创建管理员账号」。本批修正已确认的 A1／G4 初始化流程，保留一次性引导令牌、事务完成态与后续正常登录。

## 原因与来源

- `deploy/local/install-platform.sh:74` 默认调用 `bootstrap-admin`，随机生成口令并写入 `.local/admin.env`，导致首次打开已经进入普通登录页。
- `modules/identity/application/loginPages.ts:75` 在未初始化时只显示一个入口，未直接展示创建表单；令牌说明还指向不存在的 `cs-bootstrap` Secret。
- 只读参照 agent-workflow 的 `packages/frontend/src/routes/auth.tsx:134`、`routes/setup.admin.tsx:88` 与 `lib/bootstrap-token.ts:1`：安装入口携带引导凭据，进入首位管理员表单，完成后清除引导凭据并回正常登录；字段约束与逐字段反馈始终可见。

## 本批落位与行为

1. `deploy/local` 默认保留待初始化状态，输出创建管理员链接；不生成用户或初始密码。CI／无人值守安装显式设置 `CS_BOOTSTRAP_ADMIN=1` 才播种，真实失败终止安装，不能被解释成「管理员已存在」。
2. `modules/identity` L1 的 application 页面直接显示首位管理员表单。复用现有登录页外壳、HTTP 路由与事务用例，不新增模块或改变依赖方向。
3. 初始化链接携带一次性令牌；使用 URL fragment 传递，页面读入后立即清除地址中的令牌。普通访问可手工填写令牌，页面明确说明真实 Secret 与读取命令。完成后旧链接只进入正常登录并清除遗留令牌。
4. 字段约束与 CrewStation 现有契约保持一致：用户名 3–48 位、小写字母开头，显示名 1–80 位，邮箱必填且至多 254 位，密码 12–200 位，确认一致。每个字段有说明、错误与焦点；失败保留非口令资料，服务端不回显密码和令牌。
5. 保留原访问目标，创建后用新账号登录，再回目标页面。已有管理员与公司身份配置不重置。
6. 未创建管理员时不运行需要登录的目录播种。创建后可在管理空间配置套餐，或显式提供自选账号密码运行 `seed-catalog.sh`；已有凭据或显式自动初始化时保留自动播种。

## 验收

- 默认安装不创建账号、不落随机口令文件；显式 CI 播种与既有安装可重跑，非交互失败准确上报。
- 空库首次打开即有创建表单；所有字段规则可见，非法提交逐字段提示；错误后资料保留。
- 安装链接自动接入令牌并清理 URL；完成后令牌永久退役，重复／并发提交至多一位管理员。
- 创建 → 正常登录 → 原访问目标的真实数据库与浏览器链路；已有实例继续登录。
- 定向测试、`bun run check`、console 构建与浏览器宽／窄屏验证。

## 已验证结果

- 先红后绿：真实 PostgreSQL 的首次访问用例复现了「只有二次入口，没有创建表单」；安装脚本进程回归复现了默认随机建号、重复建号、失败被当作已存在、口令文件权限不正确。
- 安装回归覆盖默认交接、显式播种、已有管理员、已有脚本凭据、真实失败、遗留凭据与非法状态；HTTP 回归覆盖资料保留、错误可见、原访问目标、并发建号和重启后令牌退役。
- 真实 Chrome 153 ＋独立临时 PostgreSQL 数据库走通：首次访问 → 初始化链接自动带入令牌并清除 URL → 所有字段校验 → 创建 → 正常密码登录 → 原访问目标 → 旧初始化链接退役；无浏览器控制台异常。
- 1280×900 与 390×844 浅／深色页面检查通过，无横向溢出。实机发现 HTML `pattern` 在 Unicode `v` 模式下不接受未转义短横线，已修复，并新增按浏览器模式编译的回归断言。
- 页面测试使用独立 DOM 与脚本上下文，不替换进程的 `fetch`／`Request`／`Response`；初版全局注册产生的跨文件干扰已修正，受影响的会话与 HTTP 出站用例定向复验通过。
- 浏览器证据在 `/tmp/crewstation-first-admin-20260920/`；临时服务、数据库和浏览器已清理，没有重置现有平台用户。console 构建通过；最终完整门禁与发布记录见 `STATE.md` 本批接力。
