# RFC-031：工作台目录的统一显示与交互

状态：In Progress（作者于 2026-09-27 批准） · 2026-09-27 · 作者已批准；产品实现与定向验证已完成，完整门禁和发布状态见 acceptance。

## 背景与源码证据

作者要求统一优化项目开发里的项目列表、系统管理里的项目目录、能力接入、运行镜像、算力档位等表格，允许重写界面。本 RFC 延续 RFC-030 的紧凑目录方向；RFC-030 的既有批准不自动批准本 RFC。

- 项目列表有六列，负责人混在 slug 与角色之间，技术信息在行内 details，开发／发布／健康信息多行重复：`apps/console/src/features/projects/components/summary/ProjectSummaryTable.tsx:17`、`SummaryFacts.tsx:21`。
- 管理目录行内展开 UUID／namespace，每行并列资源、成员、生命周期多个按钮：`apps/console/src/features/admin/components/projects/ProjectDirectoryTable.tsx:14`。
- 两处负责人下拉候选来自当前页，无法作为完整负责人目录：`apps/console/src/features/projects/components/summary/ProjectListFilters.tsx:14`、`apps/console/src/features/admin/components/projects/ProjectDirectoryFilters.tsx:14`。
- 镜像表逐行查询版本、构建与验证，项目视角构建列重复“平台管理”：`apps/console/src/features/runtime-images/components/ImageCatalogRow.tsx:11`。该文件有并行 RFC-028 工作，以实施时最新内容为准。
- 算力的更多操作在表格中追加 actionRow，配置详情使用 details：`apps/console/src/features/admin/components/compute/ProfileRowActions.tsx:62`、`ProfileListRow.tsx:16`。并行工作必须原样保留再增量融合。
- 两种资源套餐目录常驻 UUID，名称、描述分列，规格不易比较：`apps/console/src/features/admin/components/plans/ResourceCatalogSection.tsx:23`。

## 范围与用户目标

本次覆盖七种目录：开发项目列表、管理项目目录、能力接入、运行镜像（平台管理与项目可用目录两种视角）、算力档位、服务套餐、任务容器套餐。项目授权编辑、镜像构建／验证、算力编辑中的列表入口沿用统一交互，业务规则不重做。其余日志、事件、调用链等时序列表不强行套用目录布局。

| 页面 | 默认主列与字段顺序 | 行主动作 | 次级动作／详情 |
| --- | --- | --- | --- |
| 开发项目 | 项目名＋slug＋本人角色；负责人；开发状态；正式／Beta 各自版本与健康 | 继续开发／进入开发，遵守现有角色与新鲜度判定 | 项目概览；开通失败时突出查看进度；原有正式／Beta 打开入口保留 |
| 项目目录 | 项目名＋slug；负责人；开通状态；创建时间 | 资源配置；失败／开通中优先查看进度 | 成员、生命周期、技术详情，跳既有路由或共享弹窗 |
| 能力接入 | 名称＋slug；API 代理／事件生产者类型；负责人；开通状态 | 进入接入项目 | 资源、成员、生命周期、技术详情；不把 active 冒充上游健康 |
| 运行镜像 | 名称＋用途；最新版本短摘要＋架构；版本状态／用途验证；最新构建状态（平台） | 查看版本 | 平台可管理，项目保持授权可见与只读边界；项目视角不留重复“平台管理”列 |
| 算力档位 | 名称＋用途；协议＋模型；任务容器套餐；可用性＋最新测试 | 编辑 | 复制、默认、启停、可见性、删除进统一管理弹窗；限制与确认保留 |
| 服务套餐 | 名称＋用途；CPU；内存；最大副本数 | 编辑 | ID 在详情／编辑中保留，非当前使用量 |
| 任务容器套餐 | 名称＋用途；CPU；内存；存储 | 编辑 | ID 在详情／编辑中保留，非实际已分配资源 |

## 统一规则

1. 一个页面标题、一个主创建动作、一个搜索筛选区、一个结果目录。移除重复卡片标题、大段常驻操作说明与“暂无说明”等占位噪音；权限、风险、错误不删。
2. 名称突出，第二行呈现 slug 或用途；负责人独立显示。普通行目标 60–76px，复杂状态可增高；不以小于现有正文的字体或截断异常原因达标。
3. 4–6 个语义列；表头弱底色、细横线、可见焦点与轻量 hover，无竖线和重复包裹卡片。名称列弹性、状态列稳定、操作列不挤占半张表。
4. 技术资料与完整说明进入共享 Dialog 或既有路由。禁止行内 details／追加操作区。主动作外保留一个具名“更多”入口，打开统一管理弹窗；菜单不是详情容器。
5. 每个状态必须写明对象：开通、开发会话、正式、Beta、构建、验证、可用性不得混成一个绿色“正常”。未知、受限、过期、读取失败分别表达；不可用原因有可访问的完整阅读路径。
6. 搜索保持既有覆盖范围：项目与接入按服务端名称／slug 搜索和 state/owner/kind 过滤；镜像用既有服务端 search；算力和套餐用完整已加载目录搜索名称／用途及现有字段。不得把当前页过滤标为全目录搜索。
7. 去掉来自当前页的“全部负责人”假目录。保留“全部／我负责”快捷筛选与行内负责人点击筛选、显示已选人名；不另建全企业人员目录，不开放人名自由搜索的虚假承诺。
8. 搜索与筛选在 URL 中，输入 Enter 提交；改变条件重置游标。保留各接口已有页大小（项目 20、镜像 30），增加会话内上一页历史，刷新无历史时可回首屏；不显示没有服务端依据的总数／总页数。完整目录才可显示筛选结果总量。
9. 关闭详情／编辑或路由返回后保持筛选、页码、滚动；草稿恢复、切换对象确认、在途锁定、嵌套 Esc 与危险动作确认词全保留。
10. 窄屏按字段标签重排；不靠固定 min-width 推出横向滚动。正常列表无横向溢出，名称、状态和主动作始终可见。

## 能力影响与边界

没有移除业务操作。原平铺次级按钮多一次打开管理弹窗，技术字段多一次查看详情；换取主信息可扫描。正式／Beta、项目角色、模板与项目额度、镜像平台归属及项目授权均保留。预览使用明确标注的演示数据，不代表真实系统状态。

不新增评分、热度、成本、使用量、分类体系、批量删除或可疑的“异常项目总数”；不扩展后端状态聚合或做逐行新请求。逐行镜像读的性能债保留，后续如需聚合另行定契约。

## 验收

- CU-01 七种目录＋镜像项目视角都遵循同一布局与动作规则，关键字段直接可见，全部原操作可到达。
- CU-02 1440×900、至少 30 条夹具：普通目录首屏至少 8 条完整行；项目多状态目录至少 7 条。记录新旧截图和真实行高；复杂错误不强制限高。
- CU-03 320／390／1024／1440、中英文、明暗主题、键盘无溢出；1440 为密度门槛，窄屏保证可读性。
- CU-04 搜索和过滤、翻页、刷新、返回上下文；查询范围标注正确，跨页目标仍可找到，游标不跨筛选／身份复用。
- CU-05 长列表末行打开在共享弹窗或路由，关闭焦点回原入口且上下文保留；嵌套确认 Esc 只关最上层；草稿／危险动作原约束不退化。
- CU-06 载入／空／失败／成功、无匹配与无数据区别、自动重读无布局跳动；撤权后不保留旧管理入口。
- CU-07 状态未知／过期／受限、正式与 Beta 独立健康、构建失败但旧版本仍可用、默认档位禁止删除等得到交互测试保护。
- CU-08 类型、lint、相关组件与浏览器回归、构建通过；发布前按仓库要求完成一轮有效 check；外部阻断与部署验收单列。
