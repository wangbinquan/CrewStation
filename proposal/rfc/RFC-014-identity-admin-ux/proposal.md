# RFC-014：用户与权限、认证管理 UX 重设计

状态：In Progress · 2026-09-20 作者已授权完整实现、验证与提交上库。

## 背景

作者反馈「用户与权限、认证两个页面的样式太丑」，要求重新设计 UX 与元素表达。
本轮已读现行 RFC-003、RFC-005、RFC-011 的相关实现，并在本机管理会话中只读查看 `/admin/users`、`/admin/authentication`。

当前用户页每行常驻「角色标签＋带姓名的角色下拉框＋禁用的保存按钮」，一个用户占约 110px；1280×720 首屏只能完整看到 4 行。来源：`apps/console/src/features/admin/components/UsersSection.tsx:28`、`components/roles/UserRoleEditor.tsx:12`。姓名、角色说明与页面文案反复出现，阅读目录需要绕过大量表单。

认证页将登录策略、身份提供方、身份转发三张大卡纵向排列；六列表格里的长 Issuer URL 挤压操作，新建后所有配置连续展开。诊断结果以一长串文本显示；项目覆盖要求手输项目 ID 和逗号分隔字段。来源：`apps/console/src/features/admin/pages/AdminAuthenticationPage.tsx:11`、`components/auth/ProvidersCard.tsx:19`、`components/auth/ProviderForm.tsx:163`、`components/auth/ForwardingCard.tsx:90`。这些都是已核实的现状，而非从旧验收记录推断。

## 目标

1. 用户页首先服务于查找和理解用户；进入单个用户后再修改角色。
2. 认证页先回答「现在怎么登录」，随后可进入接入配置和身份字段设置。
3. 展示内容采用名称、短句、语义化状态；技术字段在需要复制、配置、排障的位置完整可见。
4. 对齐现有工作台的蓝色主动作、明暗主题与公共组件，改善密度、留白、对齐和窄屏重排。

## 设计附件

`admin-identity-ux.html` 为可点击的设计附件，使用示例账号、项目和接入方，所有演示操作仅改变附件内存状态。它不是正式页面，也不构成真实权限、登录、接口或端到端验收证据。

## 用户与权限

- 标题「用户与权限」，一句副标题「管理成员的平台访问权限」，总数附在目录标题旁。
- 姓名与邮箱组成一列；同色系首字头像辅助扫描，当前账号标「你」。角色保留文字标签，每行只放「管理角色」。不增加无数据支持的最后登录、所属部门、项目数或账号状态。
- 按姓名、邮箱搜索，按三类平台角色筛选；全部在现有完整用户结果上计算。读取失败与筛选无结果分别显示，空搜索可以清除。
- 点击「管理角色」进入局部编辑面板，显示具名对象、当前角色和三个角色的简短能力说明。选择仅改变草稿；「检查变更」后显示旧角色 → 新角色，再确认保存。
- 冲突保留选择并提供「重新读取当前角色」；重新确认后才能再提交。不用新回执静默覆盖草稿。
- 「角色说明」按需展开，明确平台角色与项目成员关系。管理员包含开发者能力；开发者只开发获授权项目。

## 认证

- 保留导航名「认证」；页面内两个标签「登录方式」「身份字段」，原有路径直接进入登录方式。
- 登录方式：上部「公司登录」呈现接入方名称、启用状态、Issuer 摘要与账号创建规则；头部放「添加接入方」。每项有「配置」「测试连接」，删除降级到配置末尾的独立区域。下部用紧凑设置行呈现密码登录与当前状态。
- 当前登录方式、启用接入方数量与初始化状态降为辅助信息；安装配置强制开启时提升为可见说明，同时区分生效状态与数据库保存状态。
- 接入方使用全宽专注编辑视图，按「基本信息 → 连接设置 → 账号规则 → 字段映射」分组导航；每组都有约束，草稿跨组保留。新建可以逐组前进，编辑可直接跳组；保存校验全部字段，有错时定位第一项并标出其他组的错误数量。
- 布尔配置用带标签的原生开关或勾选行，不使用「是／否」下拉。账号规则显示「首次登录自动创建账号」「仅指定邮箱域」，提交值仍为 `auto`／`allowlist`。
- 测试连接显示独立的诊断明细：配置是否就绪、自动发现结果、端点来源与完整 URL、JWKS 可达性、支持的 scopes、错误原因。未检查不写成功；HTTP 200 不等于配置可用，更不等于已完成真实登录。
- 身份字段：中文字段名优先，协议键名其次；全局与按项目设置分块。项目按名称选择并可核对完整 ID，字段按候选集合多选，取消手工逗号输入。

## 能力影响清单

本方案没有关闭任何既有能力。角色变更、创建／编辑／启停／删除接入方、连接测试、密码登录控制、全局字段转发、项目覆盖与删除覆盖全部保留。

业务规则保持现行契约：角色 CAS、最后管理员与最后登录入口约束、关联身份限制、空密钥保持原值、空字段覆盖、固定身份字段恒定传递、停用不结束已有会话、转发最长 5 分钟生效。不会因视觉简化静默改变默认值、权限或开通方式。

本轮不调整全局导航信息架构，不改登录页、后端授权模型、认证协议、数据库、UUID 迁移或其他会话页面。

## 验收

设计稿需能切换两页、筛选用户、选择角色并查看确认、进入接入方的四组配置、查看模拟诊断、选择项目与字段；标明示例数据。正式实现的功能与视觉验收见 `plan.md`，不能把本轮设计稿核对记作实现通过。
