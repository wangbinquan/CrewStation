# RFC-011｜交互附件与核对记录

> 2026-09-20；全部为模拟数据。原型不访问真实 API，不迁移账号、不创建实际项目；不计作 RH 生产验收通过。

## 打开方式

在仓库根运行：

```sh
bun run proposal/rfc/RFC-011-role-based-home/prototype/preview.ts --serve
```

- [默认使用者首页](http://127.0.0.1:5201/)
- [评审模式：切换三类角色、试用资格和服务响应](http://127.0.0.1:5201/?review=1)
- [320px 同源窗口](http://127.0.0.1:5201/responsive.html)

服务只监听环回地址，构建产物位于 `/private/tmp/crewstation-role-home-rfc011/`。默认页不显示评审工具；`?review=1` 的工具在页尾，不是产品功能。
使用既有 Brand、GlyphIcon、Card、Button、Badge、FormField、PageHeader、ActionRow、ActionNote、EmptyState、ConfirmationPanel 和主题变量。

## 本轮操作核对

| 场景 | 已观察到的结果 |
|---|---|
| user 默认首页 | 顶栏只有应用与账号；没有技术侧栏、项目入口、管理入口或 Agent 动态 |
| 三类角色切换 | user：应用；developer：应用／项目开发；admin：应用／项目开发／平台管理；切角色后均回市场 |
| 应用卡片 | 正式卡片“打开应用／了解应用”；未发布的“客户回访助手”显示 Beta 和“试用应用”；维护卡片禁用主入口 |
| Beta 直接试用 | 首页按钮进入对应应用落点，显示 Beta 与试用资格提示；后续补齐真实业务数据提示 |
| 无试用资格 | 六张卡片变为五张，Beta 应用不再显示 |
| user 直达 `#/projects` | 显示角色限制与返回市场，没有挂载开发列表 |
| developer 项目页 | 只展示可开发项目与新建入口；无平台管理入口 |
| 创建字段 | 初始展示名称和标识约束；空提交同时显示两处错误，焦点回名称字段 |
| 创建草稿 | 填写“团队会议助手／meeting-helper”后切应用触发离开确认；继续编辑保留值 |
| 确认创建 | 显示名称、标识、负责人“我”、模板及默认资源 |
| 模拟创建503 | 保留确认资料；改为正常后成功进入“项目已创建，你是项目负责人”及准备状态，不出现多余离开确认 |
| admin 管理入口 | 可以到用户与角色，看到三类角色的职责描述 |
| 模拟角色保存 | 陈晨 user→developer，具名旧新角色确认后列表更新；不改变真实账号 |
| 1280px | 首页三列六卡片；DOM `innerWidth=scrollWidth=1280`，人工检视布局 |
| 390px | 市场／项目列表／创建表单／用户角色四视图 `innerWidth=scrollWidth=390`；人工检视单列布局 |
| 320px | 同源 iframe 内上述四视图 `innerWidth=scrollWidth=320`；管理员三个入口均有文字；人工检视窄屏卡片 |

直接设置浏览器320px时实际仍为390px，没有将这次设置当作320px证据；改用真实320px同源 iframe 后重新读取四视图尺寸。
主预览页的 error/warn 日志为空。320px窗口完成四视图尺寸核对后，自动化点击首页品牌遇到 `No node found at given location`，
外层页记录一次 `MutationObserver.observe` 参数异常，来源未确认；AX 与截图仍显示市场。未把该项记录为“全流程无错误”。
