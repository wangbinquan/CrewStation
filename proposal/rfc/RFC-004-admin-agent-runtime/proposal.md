# RFC-004｜管理员定义 Agent 启动前 Hook，租户按档位使用

> In Progress · 2026-09-14 作者批准三件套与 ADR-0004（原定 RFC-003 完结后启动）。2026-09-16 作者以会话目标“完整落地RFC-004并提交上库”要求立即实施，本 RFC 的生产代码、测试与文档已按 design.md 落地并提交 main；实机（本机 kind 集群）AR 验收尚未执行，进度与证据见 [plan.md](plan.md) 的实施说明。

## 背景与依据

RFC-001 已确立算力归平台，但现有管理员表单只包含名称、驱动、模型和说明：[ComputeProfileForm.tsx:17](../../../apps/console/src/features/admin/components/ComputeProfileForm.tsx#L17)。运行凭据仍靠安装配置 `CS_AGENT_ENV_SECRET`，Runner 创建时读一次环境文件：[platformSettings.ts:63](../../../packages/settings/platformSettings.ts#L63)、[runner.ts:85](../../../runtimes/task/src/runner.ts#L85)。

2026-09-14 的 RFC-003 实机验收中，新的任务镜像已正确运行；`rfc003-verify-workbench` 中原生 Claude Code 启动后进入登录选择页。只读核对该 Pod 未设置 `CS_AGENT_ENV_FILE`，也没有 `agent-env` 挂载。作者要求改用 OpenCode，并明确：“运行配置肯定是要由管理员来做的，并且租户使用”。

因此，完成驱动／模型登记不等于完成运行环境配置。租户点击启动以后应直接得到可用 Agent；配置不完整时应提示平台配置未就绪和管理员处理入口。

作者进一步指定：管理员定制原生配置文件及其容器内存放路径，平台在启动 Agent 前预置；管理员还可提供 Shell／Python／JS 等脚本，在同一启动前生命周期内执行环境初始化。本 RFC 采用这两个通用动作，Claude Code 与 OpenCode 作为首批预设。

## 产品方案

平台管理的“算力与 Agent”保留两个页签，租户开发页仍只选择算力档位。

| 页签 | 管理员维护 | 租户得到的行为 |
|---|---|---|
| 运行环境 | CLI 类型、按顺序执行的启动前 Hook、变量、版本、验证结果 | 每次新增 Agent 自动完成文件预置和环境初始化 |
| 算力档位 | 名称、用途、运行环境、使用的模型、启用状态 | 选择“日常开发”“复杂分析”等业务档位后逐个启动 CLI |

同一种 CLI 可以有多份运行配置，例如“OpenCode 公司网关”“Claude Code 公司网关”；多个档位可以引用同一份配置，但选择不同模型。配置粒度以 Agent 进程为准，同一开发容器可同时运行来自不同配置的 CLI。

### 两种启动前动作

| 动作 | 管理员配置 | 平台执行 |
|---|---|---|
| 预置文件 | 步骤名称、目标路径、文件内容模板、格式、文件已存在时的处理 | 展开当前 Agent 的路径与变量，创建所需目录，写入配置文件 |
| 执行脚本 | 步骤名称、Shell／Python／JavaScript 或自定义解释器、脚本内容、工作目录、超时 | 在目标容器中执行，收集退出码与结果，将约定的环境变量输出传给后续步骤和 CLI |

每份运行环境可添加任意一种动作，也可组合多步；列表顺序就是执行顺序，支持按钮／键盘调整。通常先写配置文件，再运行补充初始化脚本；需要脚本生成变量再写文件时可调换顺序。平台创建 CLI 进程前，必须等整条 Hook 执行成功。

这里的 Hook 是 **CrewStation 的 Agent 进程启动前生命周期**。每个新 Agent 都执行，包括同一旧容器中新开的 CLI；浏览器切页、断线重连、取得输入控制不执行。Claude 自己的 SessionStart／工具 Hook 和 OpenCode 插件仍用于 CLI 内部行为，不能替代平台的启动前步骤。

脚本可以准备目录、证书、依赖、动态配置和认证材料。环境变量采用统一输出约定，Shell 的 `export`、Python 或 JS 子进程内的环境修改本身不会改变后续 CLI 的环境。界面随语言提供最小可运行示例和实际解释器版本。

### 运行环境编辑

使用紧凑表格与编辑面板。列表展示名称、CLI、启用版本、检查结果、引用档位数和修改人／时间；草稿、检查通过、检查失败、已启用和已停用分别显示。

编辑围绕步骤表和代码编辑器展开，避免把所有厂商配置再拆成一套重复的模型连接表单：

1. 基本信息：名称、说明、CLI 类型；提供“Claude settings.json”“OpenCode opencode.json”和空白环境预设。
2. 启动前步骤：紧凑列表展示顺序、类型、名称、路径／解释器和超时；选中后编辑文件模板或脚本，新增、复制、删除与排序均保留草稿。
3. 变量与模型：普通变量、凭据引用、默认模型与可绑定模型名；连接、认证方式与供应方细节以原生文件为准。密钥使用保留／替换／清除操作，不在模板和脚本中重复保存明文。路径预览显示展开后的实际位置与作用范围。
4. 检查与启用：保存草稿 → 在目标环境预演完整 Hook → 校验最终 CLI 配置 → 一次最小模型调用 → 启用此版本。逐步显示等待／执行中／成功／失败／已取消、耗时、文件路径或退出码、镜像及解释器／CLI 版本。检查失败可直接定位步骤继续编辑；读取模型目录不代表推理成功。

检查使用可识别的临时任务和固定测试内容，不带租户项目源码或业务数据；确实执行脚本，不只检查语法。需要项目运行上下文的脚本可以在检查任务的样例工作目录中验证，结果注明使用的上下文，不冒充所有项目检查通过。

路径由管理员定义，支持容器内绝对路径和 Agent 私有目录变量；预设使用每 Agent 独立目录，平台显式告诉 CLI 从哪里读取。共享固定路径可能被多个 Agent 同时使用，保存和检查时显示作用范围，启动时不能静默覆盖另一个活跃 Agent 的不同配置。

### 生效规则

- 保存草稿不改变已启用版本。编辑采用版本比较，冲突保留草稿并显示当前版本。
- 启用后，下一次新启动的 CLI／Agent 使用新版本，包括已存在开发容器中新增的 CLI。
- 已运行的 Agent 固定原版本，继续执行；页面分别显示“配置已启用”和“此 Agent 使用版本”。
- Hook 版本固定文件内容、路径、脚本、解释器、变量引用与步骤顺序。普通输入不会重新执行；确实需要新建 CLI 进程时按本次执行记录运行，传输重试不重复脚本。
- 任何文件步骤失败、脚本非零退出／超时／取消，都停止本次启动，显示失败步骤和原因；修复后显式重试。不能将“环境准备中”显示成“Agent 正在执行任务”。
- 对已有 Agent 使用新配置，须通过现有结束／新建流程显式操作，不把后台更新伪装为已经加载，也不批量结束租户会话。
- 停用只阻止新的托管启动，已接受的执行继续按固定快照运行；回退是启用之前仍可用的配置版本。
- 业务子任务与原生 CLI、历史对话的 headless Agent 使用同一个配置解析规则。发布记录冻结的 Manifest 仍引用算力档位，实际执行另记运行配置版本。

## 管理与租户边界

管理员拥有文件模板、目标路径、脚本、变量、认证、启用／停用、检查和档位绑定权限。租户只获得档位名称、说明、是否可用以及自身 Agent 的配置版本／准备进度；开发页没有运行环境编辑入口。失败显示“环境准备失败：步骤名称”与可供管理员定位的执行 ID，管理脚本和密钥不进入租户表单、动态事件或导出日志。

项目中的业务说明、代码规则和既有工具权限继续保留。平台负责驱动、模型连接、认证与运行版本；会话负责当前任务、工作目录和已授权的工具范围。原生配置冲突必须按字段显示来源与结果，不能静默覆盖平台用于 MCP 身份和轮次观测的配置。

原生文件预设先覆盖企业 API／网关和无需认证的供应方。Claude API 配置可由 settings.json 中的环境设置提供，但 settings.json 不是所有网页登录状态的完整副本；需要动态认证的环境可以通过管理员脚本准备相应材料。平台不把复制一份 settings.json 声称为已经实现 OAuth 登录或自动续期，也不删除 CLI 的原生登录能力。

## 兼容与能力影响

| 既有能力 | 本方案处理 |
|---|---|
| 租户以 `compute` 名称启动 | 保持；不要求租户填写厂商、模型或运行 JSON |
| 已有仅 driver／model 的档位 | 保持兼容路径，并在管理页标识“部署配置模式”；管理员显式绑定运行配置后切到托管模式 |
| 已有 `CS_AGENT_ENV_SECRET` | 仅供未迁移档位继续使用；不自动读取并写回界面，也不把全部旧凭据混入已托管 Agent |
| 原生 CLI／headless／业务子任务 | 全部接入同一解析入口，不只修原生 CLI |
| 正在执行的会话与进程 | 保持当前配置，新增 Agent 可使用新版本 |
| 失效的托管配置 | 启动前报可恢复错误，不悄悄改用其他模型或转入租户登录流程 |

托管模式中的启动前拒绝、停用后的新启动拒绝，以及平台字段优先级，是本次新增的行为约束，需随本 RFC 一并确认与测试。旧模式保持原行为，不以本次迁移擅自删除能力。

## 验收

管理员在 UI 为 Claude Code 和 OpenCode 配置启动前文件与脚本，各完成一次真实运行环境检查并启用；普通租户只选档位即可使用。Shell／Python／JS 的真实执行、环境输出传递、动作排序、共享路径、超时／取消、双 CLI、业务子任务、已有容器中新建 Agent、配置失败恢复、修改冲突、停用、回退、旧 Runner／旧档位兼容均需实际证据。细项见 [plan.md](plan.md)。

RFC-003 继续保留完整 UX 验收范围；本 RFC 负责其中暴露的运行配置缺口，不将 RFC-003 提前标记 Done。
