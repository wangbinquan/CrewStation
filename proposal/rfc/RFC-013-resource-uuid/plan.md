## 5. 验证与发布纪律

先跑每批定向用例；最终候选稳定后运行 `bun run check` 和 console 构建。已有等价共享候选门禁在运行时复用，不制造重复全量运行；候选内容变化或结果无效才重跑。文档草案阶段无需启动完整门禁。

迁移使用 `bun run migrations:lock <精确路径>`；契约金样在批准后使用 `bun run contracts:lock --breaking "RFC-013 已批准的能力影响清单"`。禁止修改已入锁的历史迁移或替其他会话锁定在制契约。

发布时使用精确文件 allowlist、检查整个暂存区及贡献署名；fetch 后核对本地与远端。最终分别记录：本地候选门禁、已提交／已发布 SHA、精确 SHA static／unit／module／console／gate／e2e 结果、真实升级和运行验收。没有实际执行的项保持未验证。
