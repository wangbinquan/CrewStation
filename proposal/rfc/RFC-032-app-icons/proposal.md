# RFC-032：业务自定义应用图标

状态：In Progress（作者于 2026-09-27 批准） · 2026-09-27 · 作者要求保留图标，并明确“上传图片＋填写图片 URL”，补充应用可通过约定图标 URL 自行提供。具体设计已批准并实现。

## 改动前状态

市场图标目前是六个固定符号，`packages/contracts/api/market/appListing.ts:12` 仅允许 station/assistant/workflow/book/chart/spark；展示设置弹窗仅有枚举下拉：`apps/console/src/features/projects/components/visibility/AppPresentationDialog.tsx:36`。设置写入经 owner/admin 的 manage-members 权限与 revision 冲突检查：`modules/project/application/appVisibility.ts:20`。没有业务自定义图片能力。

## 决定与建议

- **作者已决定**：不删除图标；改进显示；业务可上传图片、填写 URL，也可在约定 URL 开放图标由市场自动读取。
- **已批准约定**：应用入口 origin 下的 `/favicon.ico`。有已部署且当前用户可访问的正式入口时优先正式；仅 Beta 可用时用 Beta；没有可用入口则内置图标。保留网关身份与授权规则，不为取图标绕过应用访问控制。
- 展示设置中明确选择一种来源：应用约定地址（默认）／上传图片／自定义 URL。手动配置优先；手动来源失败可回退应用约定，再回退已选内置符号。可随时恢复自动来源，内置六种选择继续作为兜底。
- 图标只占 32×32px，8px 圆角，内部 24–26px 可用区，object-fit: contain，不拉伸、不裁掉品牌主体，不统一套鲜艳底色。名称和用途整体对齐，图标居中，不侵占信息密度。缩略图装饰性 alt 为空；设置中展示 32px 实际尺寸和较大预览。
- URL 支持站内根相对路径（基于选定应用 origin）或完整 HTTP(S) 图片 URL。HTTPS 工作台不接受会被浏览器拦截的 HTTP 图片；本地 HTTP 开发环境可用 HTTP。不支持 HTML 页面、脚本协议或凭据 URL。明确保存的是地址，不是将外部图片上传平台。
- 上传支持 PNG/JPEG/WebP，建议原始文件 ≤2 MiB、宽高各 ≤4096px；服务端实际解码、移除元数据、等比例规范化到最大128px、限制规范化结果 ≤64KiB。首版上传不接受 SVG/GIF/ICO；约定 favicon 可由浏览器作为 image 解码 ICO，不将其作为 HTML 执行。
- 图标修改权限仍是项目负责人／平台管理员。普通使用者只读取允许其看到的应用图标。保存沿用展示设置、草稿保护与 revision；更换图片不改变应用可见范围，也不触发发布。

## 能力与范围

保留全部旧枚举图标作为 fallback，不移除其他市场功能。业务选择手动自定义或自动约定，不强制每个项目上传。正式与 Beta 共用一个条目图标，不根据轮询在两种图标间跳动。业务入口不可读、401/403/404、HTML、坏图片、超时都降级，不影响应用按钮可用性。

本 RFC 与 RFC-031 分开：前者是上传／读图契约和业务品牌入口，后者是目录显示。共用市场缩略图预览，实施可同批验收。本次实现不修改真实业务图标、业务发布或平台部署。

## 验收

- AI-01 旧六种图标继续显示；市场、详情与设置预览一致；320/390/1440、中英明暗不溢出。
- AI-02 应用 `/favicon.ico` 自动选择正确 origin；正式优先、Beta-only、无入口、无权、加载错误／超时全部回退；失效 URL 不请求循环。
- AI-03 自定义绝对／相对 URL 校验、保存、刷新恢复；不发送服务端代理抓取；手动来源覆盖自动。
- AI-04 上传真解码与边界校验，原始／规范化大小限制，替换／恢复、冲突时保留草稿；不以 MIME/扩展名代替实际解码。
- AI-05 上传写接口 401/403/400/409、图标读接口按市场可见性裁定；身份／授权变化后禁止复用前一用户敏感图标缓存。
- AI-06 URL 地址或 revision 变更重置加载状态；本次渲染只做有限回退；错误没有布局抖动或破图。
