## 本轮修复

1. 算力表从 10 列收为档位、执行配置、状态、操作四列；镜像／二进制／修改资料按需展开，低频操作收入菜单，增加搜索与清除。
2. 镜像仓库地址改为逐行展示，避免长地址被压成一字一行；管理表单的字段顶部对齐并保留合理最小宽度。
3. 身份提供方表单新增取消、草稿导航提醒、完整字段校验与可见约束；提交时定位首个错误，输入时不抢焦点；密钥按密码输入显示，编辑切换提供方不串草稿；新增时收起重复空态。
4. 事件生产方的 slug 不再被当成项目 ID，避免点击进入 `400 validation` 页面。
5. 开发页“会话／数据访问”改为有高度上限的互斥浮层，展开时不再把工作区推到屏幕外。
6. 文件区断线时解释不可读取的原因并保留草稿，暂停文件打开、保存、重新读取与快捷键保存；恢复连接后重新读树。
7. 通用终端不再显示没有意义的“轮次状态未确认”，仍保留真实进程在线／结束状态；Agent 的未确认状态继续如实保留。
8. 资源说明失败可原地重试，返回结构不完整时显示可操作错误，避免访问 `service.identity` 使整个设置页崩溃。
9. 更新管理概览、开发入口与配额的中英文描述，使其符合当前每个 Agent 独立执行的模型。
10. 最终实机复验在 API 页发现 `Cannot read properties of undefined (reading 'some')`；对照部署包的实际异常栈，源头是全局 Agent 动态栏直接读取缺失的 `memberships`。修复该空值访问，并同步处理 API、发布、告警、应用可见性页面的同类路径；API 页提供用户资料异常提示和重新读取入口。重新部署后实测 API 页正常显示 22 条操作。
