# 0011. 项目资源申请与同页资源管理

- 状态：已接受（作者批准 RFC-036 实施）
- 日期：2026-09-30

## 背景

项目资源由不同领域拥有，现有授权、配额和实例台账不能承担跨领域申请的持久状态。RFC-036 要求负责人申请、管理员审批，管理员也在项目资源页直接调整；批准与实际生效必须分别可追踪。

## 决策

增加 `resource-access`（L3），仅依赖 `project`（L2）与技术包。模块拥有可申请目录政策、申请、审批、应用回执和审计，持久数据写入自己的 `resource_access` schema。领域授权与配额仍由其所属模块保存；通过组合根注入的适配端口读取、校验和幂等应用，不跨 schema 访问。

`capabilities`（L6）只读聚合资源全景；`platform`（L7）组合适配器。现有 `resources`（L1）继续拥有已声明资源的期望和实况；可申请目录项不作为物理实例写入台账。

项目命名空间配额归 `project` 所有，经 `provisioning` 写期望、`cluster-control` 对账。服务和算力的新增授权使用正向例外，保留继承规则。新旧资源申请入口统一校验负责人，审批校验平台管理员。

## 后果

增加工作区单元、迁移集和申请恢复工作器。申请与领域应用之间采用持久状态和幂等回执，不声称跨模块事务。部分来源失败保留可读取资源并标记完整性；失败、修订冲突和实际同步都在同一页面呈现。

不调整依赖规则、尺寸上限或测试门禁，不增加架构例外。
