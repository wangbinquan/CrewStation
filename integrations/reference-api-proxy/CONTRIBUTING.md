# 参与开发

本项目是 CrewStation 上的一个接入容器（`kind: APIProxy`），同时是其他接入容器的参考实现。平台能力——网关的服务域识别与放行表、内部 API 目录与开放策略、配置与密钥、权限化 Swagger——的权威说明不在本仓库里，而由平台实时提供，内容随本服务当前的授权、绑定、配额与套餐变化。请以下面两个入口为准，本文不复述其内容：

- **能力说明 MCP**：开发会话内的 Agent 可直接读取它的只读 resource（平台能力目录、本服务现状、约定说明与接口示例）。给 Agent 的第一条指令可以是“先阅读能力说明 MCP，再……”。
- **工作台 → 本项目 → 能力页**：同一份内容的网页版，附本服务已登记的操作、开放策略、定向开放申请与环境地址。

本仓库自身的约定：

- `crewstation.yaml` 是与平台的唯一契约：改端口、配置项、`proxy` 名、`upstream.connection`、`apis.exposes` 都在这里改，发布时由平台校验。
- **`openapi.yaml` 与 `src/proxy/catalog.ts` 的操作清单必须一致**：目录只认发布时从 `openapi.yaml` 读出的操作。`src/proxy/catalog.test.ts` 会比对两者，加操作时两处一起改。
- **不要在这里写鉴权**。放行由网关按放行表在请求到达之前判完，资源级范围由上游把关。在代理里再判一遍只会造出两份会不一致的规则。
- 不在代码、配置默认值、日志或响应里留任何凭据；上游令牌只从平台注入的密钥来。
- 转发要忠实：方法、路径、查询串、请求体、上游状态码与响应体都不改写。要改写，先问清楚为什么不能让上游或调用方来改。
- `bun test` 必须通过；请求头处理与响应头处理这类纯函数逐分支覆盖。
- 发布只经平台（工作台发布按钮／`crewstation` CLI／操作 MCP）；手工打的标签不会发布。
